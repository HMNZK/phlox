会話画面（Session Chat）の下端。上から 送信失敗の通知 → 承認カード → 質問カード → 入力欄 → キーの案内 の順に積む。承認と質問は入力欄の直上に出し、会話の中には流さない。
論点: 承認を素早く、安全に捌く
1
何を許可するかを先頭に大きく出す。見出しの 1 行目は種類（コマンドの実行 / ファイルの変更 / 権限の変更）、2 行目が対象そのもの。コマンドは全文を等幅で、ファイルはパスと増減行数、権限はルール文字列と追加先を出す（R6）。
2
キーは 2 段にする。入力欄にいるときは ⌥⌘↩ 許可 / ⌥⌘⌫ 拒否 の 2 つだけ（修飾キー 2 つで、文字入力中の誤打を防ぐ）。Tab か ⌘J でカードにフォーカスを移すと、Y 許可 / S このセッション中は許可 / N 拒否 / Esc キャンセル の 1 キーで返せる（R6b）。
3
フォーカスを勝手に移さない。承認カードが出ても入力中のフォーカスは入力欄に残す。入力欄の ↩ は常に「送信」で、承認には使わない。
4
出た直後の 0.5 秒は押せない。カードが出た瞬間のクリックやキーは無視し、許可ボタンの下端に進み具合を出す（R6c）。別の操作の続きで押してしまう誤承認を防ぐ。
5
「このセッション中は許可」は範囲を言葉で示す。フォーカス時に説明を 1 行出す。範囲がエージェントごとにどう違うかは未確認（分岐候補）。
6
複数の要求は 1 枚ずつ。「1 / 3」と前後の送りを出し、1 件返すと次が出る（R6d）。一括許可は置かない。
ボタンの文言は「許可 / このセッション中は許可 / 拒否 / キャンセル」に揃える（骨格・会話画面の「承認 / 却下」もこの回で置き換える）。ApprovalDecision は accept / acceptForSession / decline / cancel に対応する。

現行から大きく変えた点
承認カードの先頭に対象そのものを出す。現行はボタンが主で、何を許可するのかを読み取りにくい。
承認のキーを 2 段にする（論点 2〜4）。1 キーで返せる速さと、入力中の誤承認の防止を両立する。
送信失敗を通知する。下書きが黙って戻るだけだと、送れたと思い込むため。
Codex の権限をキーごとの選択にする。承認方式とサンドボックスは別々の設定なので、1 つのリストにまとめない。
分岐候補（推測・未確認）
「このセッション中は許可」の範囲（同じコマンドか、同じ種類か）はエージェントごとのクライアント実装に依存し未確認。
「キャンセル」が要求の取り下げだけか、ターンも止めるのか未確認。
画像添付の可否（案 A〜C）。
権限モードの正式な文言（UIWording+Permissions）は詳細を読んでいないため、選択肢の数だけを機能一覧に合わせた。
↑ キーでの入力履歴の呼び出しは実装が見つかっていない。
承認待ちの間に入力欄から送信できるかは未確認。本案では入力は可能で、送信は承認のあとにした。
