# ADR 0026: iOS のツールコールは1件でも「ツール実行 ×N」の集約行に畳む（macOS とは意図的に異なる契約）

> **このファイルの役割**: iOS チャットのツールコール（`ChatMessage.command`）を、連続2件以上ではなく**1件でも**集約行へ畳むと決めた理由、macOS（2件以上で集約）との差異を意図的に残す理由、そして「唯一の行には空出力フィルタを適用しない」という例外の理由を記録する。
> **書かないもの**: 現行の実装仕様（→ `Features/SessionDetail/SessionDetailToolCallGrouping.swift`・`SessionDetailToolCallGroupRow.swift`、および `architecture/overview.md`）／per-message 折りたたみの一般則（wave-5・`architecture/overview.md`）／末尾ウィンドウ描画（→ [ADR 0022](0022-ios-transcript-tail-window.md)）。

## 文脈

`SessionDetailToolCallGrouping` は当初、macOS の `ChatTranscriptGrouping` と**同一契約**として実装された:
連続する `.command` が**2件以上**なら「ツール実行 ×N」の1行集約ヘッダ（`SessionDetailToolCallGroupRow`）に畳み、
**1件だけなら `.single`** としてモノスペースカード（`$ <コマンド>` を見出しにした折りたたみカード）で描画する。

この分岐により、単独のツールコールだけが不釣り合いに大きくなる。見出し `$ <コマンド>` に `lineLimit` が無いため、
長いコマンド（例: `Read /Users/…/ClaudeStatusLinePane.swift`）では折り返しが起きる。ユーザー報告のスクリーンショットでは
**1件のツールコールが縦6行**を占め、その直後の「ツール実行 ×15」が1行で収まっているという逆転が起きていた。
モバイルの狭い画面では、この不均衡が履歴の見通しを直接損なう。

## 決定

1. **連続する `.command` は1件以上で必ず `commandGroup` に畳む**。`makeBlocks` の「1件なら `.single`」分岐を削除し、
   単独/複数で描画経路を1本化した。見出しは複数件と同一書式のまま `"ツール実行 ×\(items.count)"` で、
   単独では `"ツール実行 ×1"` になる。**単独専用の別表記・別レイアウトは作らない**（書式を分けると
   「単独だけ例外」という分岐が表示側にも増え、今回直した不均衡が形を変えて戻る）。
2. **macOS との差異は意図的に残す**。要求はモバイル固有（狭い画面での占有行数）であり、macOS 側
   （`macos/Packages/SessionFeature/.../ChatTranscriptGrouping.swift`）は 2 件以上で集約のまま変更しない。
   iOS/macOS は Swift Package を共有しないため実装の乖離コストは無く、旧コメントの「Mac と同一契約」という記述は
   本 ADR の決定に置き換える。
3. **唯一の行には「空出力フィルタ」を適用しない**。集約行の展開部は `rows` を描画し、`rows` は
   「出力が空かつ実行中でない行」を除外する。この除外は**複数件が並ぶときのノイズ抑制**が目的であって、
   唯一の行を消す意図ではない。単独に適用すると、出力が空のツールコール
   （wire 側 `output` が nil のとき空文字になる = `PhloxNetworking/DTOs.swift`）が
   「ヘッダを押しても何も出ない＝どのコマンドが走ったのか画面から知る手段がない」状態になり、
   変更前（`$ <コマンド>` が常に見えていた）に対する**情報の後退**になる。
   したがって `items.count == 1` のときはフィルタを通さず、唯一の行を必ず残す。
4. **2件以上の既存ルールは変更しない**。全件が空出力かつ実行中でないグループは従来どおり描画しない
   （`shouldRender == false`）。退行ガードとして受け入れテストで凍結した。

## 棄却案

- **`$ <コマンド>` の見出しに `lineLimit(1)` を足すだけ**: 折り返しは止まるが、単独と複数で見た目・操作感が別物のまま残る。
  ユーザー要求は「集約行と同じ1行の見せ方」であり、対症療法になるため採らない。
- **単独時の見出しを「ツール実行」（`×1` を出さない）にする**: 「×1 が不自然」という論点はあるが、書式を分けると
  表示側に単独専用の分岐が生まれる。ユーザー判断で「複数件と完全に同じ形式」を採用した。
- **見出しにコマンド名を残して1行省略**（`$ Read /Users/…` を truncate）: 何が走ったか一目で分かる利点があるが、
  複数件の集約行と見た目が揃わない。同上のユーザー判断で不採用。
- **`shouldRender` に `itemCount == 1` の特例を足す**（ヘッダだけ出して展開は空）: 行の消失は防げるが
  「押しても何も出ない開閉コントロール」が残り、どのコマンドかは分からないまま。発生源（フィルタ側）で直す決定3に置き換えた。
- **`.fileChange`（「ファイル変更」行）も同じ集約に含める**: 既に1行に収まっており折り返し問題が無い。
  スコープを広げないため今回は対象外（ユーザー判断）。

## 結果

- 受け入れテスト `AcceptanceIOSToolCallGroupingTests`（12件・PM 凍結）と白箱 `IOSToolCallGroupingWhiteboxTests`（9件）が green。
  `swift test --package-path ios/Packages/PhloxKit` 全数 **491件 green**（変更前 484件から +7）。`make build` / `make run-ui-test` も成功。
- `ImageRenderer` で集約行を実レンダリングし、単独ツールコールが「ツール実行 ×1」の**1行**（「ツール実行 ×15」と同一の見た目）
  に収まることを目視確認した。
- 副作用として `SessionDetailView.chatRow(for:)` の `.command` 分岐が **transcript 経路からは到達不能**になった
  （`switch` の網羅性に必要で、`SubAgentDetailView` では今も `.command` を描画するため削除しない）。
- **既知の残課題（本 ADR では直さない）**: グループの開閉キーがグループ先頭 message の id と同一のため、
  単独グループではヘッダと唯一の行の開閉状態が共有される（ヘッダを1タップするとコマンドと出力が同時に開き、
  行の chevron でカード全体が畳まれる）。2件以上のグループの先頭行でも変更前から存在する既存挙動で、
  単独では実害が無いと判断した。恒久対策の方向はグループの開閉キーを別名前空間（例 `"group:<id>"`）にすること。

## 後日談（2026-07-27）

本 ADR は「macOS の `ChatTranscriptGrouping`（2件以上で集約）とは**意図的に異なる**契約にする」と書いたが、
その後 macOS 側が [macOS ADR 0127](../../../macos/docs/adr/0127-transcript-window-counts-blocks.md) で
**1件以上の集約へ揃えた**ため、この差異は解消した。本 ADR の決定（1件でも集約する・唯一の行には
空出力フィルタを適用しない）自体は有効なままである。

**本文中の「macOS 側は 2 件以上で集約のまま変更しない」という記述は、この時点で STALE である**
（ADR は追記専用のため本文は書き換えず、この後日談で打ち消す）。
