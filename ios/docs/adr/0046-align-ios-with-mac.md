# ADR 0046: 色・ロゴ・状態・一覧・新規チャット・入力欄・承認を Mac に揃える

> **このファイルの役割**: iOS 再設計で、iPhone 独自だった見せ方をやめて Mac アプリの作りに揃えた決定の一覧と理由。
> **書かないもの**: 画面ごとの要件（→ [specs/redesign-2026-10.md](../specs/redesign-2026-10.md)）。Mac 側の変更は承認の操作の種類だけ（→ macOS ADR 0216 追記 7）。

## 文脈

iPhone アプリは Mac アプリとは別に育ち、紫とピンクのアクセント・エージェント別の色と略号・状態の記号・3 択でエージェントを選ぶ新規作成・1 段の入力欄・Codex だけの 4 択シートなど、同じ操作が Mac と違う見た目と手順になっていた。両方を使う利用者は 2 つの作法を覚える必要があった。見本は 1〜3 回目の改訂でこれを Mac に寄せた。

## 決定

1. **色**: アクセントを白黒（#1D1D1F / #F2F2F4）にし、塗りの上は `accentOnFill`。色は対応待ち（承認待ち・質問あり）・エラー・無応答（Mac と同じ紫 `status.stalled`）と、使用量の残りわずかだけに使う。エージェント別の色・略号・紫ピンクのグラデーションは消す。
2. **ロゴ**: 実物のロゴにする。Claude・Codex は副文字色の単色、Cursor は元の色（Mac と同じ規則）。
3. **状態**: アプリ内は文字だけ（Mac と同じ）。記号はロック画面・ウィジェット・Live Activity・Dynamic Island だけに残す。語は 9 つに揃え、画面ごとに言い換えない。
4. **一覧**: Mac のサイドバーと同じ構成（対応待ち → プロジェクトごと → その他、見出しの「＋」、子セッションの字下げ）。行は名前と状態の語だけ。
5. **新規チャット**: Mac の新規チャットと同じく、DotGothic16 の見出し・提案チップ・入力欄から始め、エージェントはモデルを選ぶと決まる（先にエージェントを選ぶ段階をやめる）。
6. **入力欄**: Mac と同じ 2 段（本文／＋・モデル・思考の強さ・権限・プロジェクト・送信と停止）。選択肢と表示名は Mac から受け取り、iPhone で持たない（macOS ADR 0216）。
7. **承認**: Mac の承認カードと同じ 1 つの部品を、Codex（`/approvals`）と Claude Code（許可の質問）の 2 つの経路から作る。ボタンは 4 つ、出た直後 0.6 秒は押せない。Codex の 4 択シートと独立した質問の回答画面は消す。
8. **セッション画面の左上**: 「＜ 戻る」をホームのボタン（家の形）にし、端スワイプで戻る操作は残す。ADR 0033 の「戻るを差し替えない」を、見本（利用者の指示）を正として覆す。会話は Mac と同じカード（コマンド・ツール実行・ファイル変更・思考）にし、出力は 20 行ずつにする（ADR 0038 の 50 行を改める）。

## 棄却案

- **iPhone 独自の作法を残し、色だけ揃える**: 手順の違い（エージェントを先に選ぶ・承認が 2 通り）が残る。
- **iPhone 側に選択肢と表示名を持つ**: Mac の変更に追随できない（ADR 0216 と同じ理由）。

## 結果

- ADR 0016（ピル型の 1 段の入力欄）はこの ADR で superseded。ADR 0018（ドラッグ・音声の撤去）と 0042（送信と停止の出し分け）は有効。
- ADR 0033 のうち「戻るの差し替え」、ADR 0038 のうち「50 行」は、この ADR が置き換える。システムのナビゲーションバーを使う判断と、閉じたカードで行データを作らない判断は有効。
- ADR 0033 は「leading に自前の項目を置くと UIKit が端スワイプの pop を拒否する」と観測している（ADR 0032 の差し替えも失敗した）。ホームのボタンと端スワイプの両立は、段階 6 の最初に実機に近い形で確かめ、両立できなければ止めて判断を仰ぐ。→ 段階 1 の最初にシミュレーターで UIKit の状態を確かめ、作り方を [ADR 0048](0048-home-button-is-the-system-back-button-with-a-house.md) に決めた（指での操作は実機で確かめる）。
- 一覧の「無応答」「終了」「未読」と子セッションは、今の `GET /sessions` に元の値が無い（仕様書 15 章 U-3）。Mac に揃えるには Mac 側の追加が要る。

## 段階 6 追記（2026-10-18）

- セッション画面の上部は `DSSessionNavigationChrome` にまとめ、名前・状態語とエージェント名・「…」をシステムナビゲーションバーへ載せる。iOS 26 は地色のグラデーション、iOS 18 は半透明の地と 1pt の下線に分けた。
- 左上は既存の `NavigationStackHomeBackButton` を使い、UIKit の戻る操作を残す。端スワイプそのものは XCUITest を使わず、今回の描画確認では未検証。

## 段階 6b 追記（2026-10-18）

- 会話本文を Mac に合わせた。返答は全幅 Markdown、自分の発言は右寄せの吹き出し、添付は本文上のサムネイル。単独コマンド・複数ツール・1 ファイルごとの diff・思考・サブエージェント・確定質問・エラーをそれぞれ対応するカードにした。
- 実行中の活動語・要約とターンの使用量行は Mac の recap・turn cost の規則に合わせた。コマンド出力は 20 行ずつ表示する（ADR 0038）。無応答行は既存の `m:ss` 規則を保つ（仕様 U-19）。
- 入力欄上の承認・未回答質問カードは今回の変更対象外で、次の段階に残した。

## 段階 6c 追記（2026-10-18）

- Codex の `/approvals` と Claude Code の単一質問項目のツール許可を、同じ承認カードへ統合した。操作名と経過時間の文言は Mac に揃えた。iOS の誤承認防止時間は仕様 AC-9-4 の 0.6 秒とした。
- 通常質問は承認の下に置く。複数質問を含む `userQuestion` は一部だけを許可として送らず、Mac の判定に合わせて質問カードに保つ。Cursor には承認を表示しない。
- API には個別の承認要求時刻が無いため、iOS はセッションの `statusEnteredAt` を使い、欠落時はカード表示時刻を起点にする（仕様 U-19）。Mac の個々の要求時刻と一致しない場合がある。

## 段階 8a 追記（2026-10-18）

- 起動ゲート、QR 接続・再接続、接続待ち、設定区画、カタログエラーの画面と文言を再設計の盤面へ揃えた。QR URL は起動復元とロック解除が済むまで保留する。接続待ちは一覧取得成功で閉じ、失敗時は原因・次の操作・技術値を順に示す。
- 429 はエラー表示の赤色を使わず、無彩色で出す。設定の区画順を接続・通知・セキュリティ・外観・このアプリについてに揃え、DotGothic16 のライセンス行を保つ。
- `Errors.dc.html` に D2 が無いため、D2 の文言は追加しない。未撮影の OS 標準 UI と残った盤面差は [作業記録0028](../delivery/0028-ios-redesign-stage8-worklog.md) に記録する。
