# 削除失敗の再試行後にアラートが戻らない問題

所有: ios_integration_fixes。対象はDeleteConfirmationView/ViewModelと既存DeleteConfirmationViewModelTests。他担当の変更は保持する。

## 原因と修正契約

ViewはEquatableなstateをonChangeで監視していた。同じ失敗の再試行ではfailed(同文)→deleting→failed(同文)となるため、即時API失敗で途中の描画が合成されると値の変化として通知されない。失敗アラートはボタン操作で閉じるので、再提示の入口を失う。AlertItemのIDも技術脚注由来で同じ失敗を区別できなかった。

削除失敗が実際に完了するたびViewModelのfailureGenerationを単調増加させる。Viewはこの世代を監視し、世代を含むAlertItemで提示する。文言/state/API/成功callbackは維持する。sleep/yield/ランダムIDでのタイミング調整はしない。失敗ごとのイベントを識別する値でありテスト専用状態ではない。

登録回帰は即時throwする既存MockAPIで同じ失敗を2回実行し、文言/stateは同一でも世代が更新され、APIは2回、成功callbackは0回となることを検査する。最終提示は既存の本物nativeRootInteractive検査（確認→失敗→実再試行→再失敗→閉じる）で確認する。モデルのunit成功をnative提示成功とは扱わない。
