## 実装前の根拠と方針

- 現コードは説明を1行に限定し末尾を省略する。説明の文字サイズには AX1 の上限、操作には large 固定と高さ40ptがある。本文側に同じ説明があっても、下部バーの全文表示の代わりにはしない。
- `DSPlatformTabView` は iOS26 で OS の `tabViewBottomAccessory`、iOS18 で `safeAreaInset` に同じ内容を渡す。前者の配置は通常時にタブ上、縮小時にインラインになる。[Apple の仕様](https://developer.apple.com/documentation/swiftui/view/tabviewbottomaccessory(content:)) はこの配置を定義するが、任意高さを保証する記述は確認できていない。親の高さが固定とも可変とも仮定しない。
- 通常文字サイズでは既存の見出し・補足と右側操作の配置、文言、色を保つ。補足を折り返し可能にし、縦方向は自然な高さを要求する。AX1以上では補足と操作を縦に並べる。文字サイズを制限せず、操作は44pt以上で内容に応じて伸びる。
- 再接続状態は AppRoot が所有する実処理中フラグを受け取る。処理中は「再接続しています…」と0.9秒周期のインジケータを示し、操作を無効化する。視差効果を減らす場合は回転を止め、文言を保つ。AppRoot 側でも同時実行を防ぐ（別担当）。
- OS標準タブ、ガラス、縮小動作は変更しない。

### 初回実行の記録と計測修正

iOS18.3.1の初回実行は `host-large-428-idle` のAX一覧記録で停止した。公開AXが返した非有限座標をJSONへ直接渡したため `NSInvalidArgumentException: Invalid number value (infinite) in JSON write` が発生した。画像とowner記録のみで、24条件は未確認。再起動後の0件表示は成功ではなく、実行全体はexit65だった（親担当の実行記録: `.verification/ios-redesign-stage8b/logs/remaining-native-offline-ios18.log`）。製品の高さ不足かどうかを判断する前の検証側の不具合である。

非有限座標はraw文字列とfiniteフラグを残し、JSONへ数値として渡さない。AX要素の実型・UIViewの場合のhidden/alpha/window/bounds、ウィンドウ/host/OS globalの文字サイズとUIFont値を保存する。再接続ボタンの座標は有限であることを必須とし、44pt・画面内・OCRの検査は維持する。他要素の非有限frameだけで製品不良や公開AX未対応とは断定しない。未解決の公開AX座標と実描画の欠落は、保存画像と対象要素の計測を照合して判断する。

r3のbuild-for-testingは記録用 `NSStringFromCGRect` がSwiftでは廃止済みというコンパイルエラーで停止した。正式APIの `NSCoder.string(for:)` に置換した。検査の意味・製品コードは変更していない。r3はruntime未実行であり、構文parseの成功をコンパイル成功と扱わない。

r4のiOS18実行は、公開AXの `SwiftUI.AccessibilityNode` が識別子プロトコル経由でIDを返さず、対象選択で停止した。記録には全文ラベル、button trait、実矩形 `{{12, 775}, {404, 60}}` が存在する。描画も保存済みであり、製品のID欠落と断定しない。対象選択は完全一致の全文ラベル＋公開button trait＋有限で可視の実矩形の一意一致へ変更した。識別子の取得能力は補助記録とする。実frame44pt/ウィンドウ内/OCR/disabledの検査は維持する。

24条件はSwift Testingの引数付きテストに分け、条件ごとにfixture・本物のウィンドウ・片付けを独立させる。1条件で座標やOCRを取得できなくても他条件の証拠を収集する。global AX5 と large条件のwindow/host Lの相違は、この条件の明示的な文字サイズ指定どおりであり、違反と扱わない。

## 最終iOS26のOCR混線の修正

自然高修正後は24条件中23条件が成功し、圏外・AX5・428pt・再接続中の1条件で見出しOCRだけが失敗した。対象PNGを原寸で確認し、前景の「インターネット」「につながって」「いません」は欠けていない。透けた背後の青い「あり」をOCRが右側の独立行として認識し、全行を上から単純結合したため「…につながってありいません」になっていた。

バーのcropはwindow内 `x16/y443/w396/h392`。Visionのcrop正規化座標（左下原点）は以下。各前景行のleadingは一致するが、「あり」は約273pt右に離れる。高さは同程度なので、高さだけで文字を排除しない。

| OCR行 | x | y | 高さ |
|---|---:|---:|---:|
| インターネット | 0.0505 | 0.8469 | 0.1088 |
| につながって | 0.0572 | 0.6990 | 0.1088 |
| あり（背景） | 0.7458 | 0.6633 | 0.1105 |
| いません | 0.0487 | 0.5572 | 0.1015 |

検証側は、各OCR行をanchorとしてleadingまたは中心が揃う行だけを上から結合する。許容幅は比較する2行のうち小さい方の文字行高の半分とする。1文字行高以内の自然な左右揺れを半文字高まで許し、別の列を混ぜないための相対的な幾何条件であり、特定の画面座標や期待文字から位置を選ばない。全文期待は各列候補の中で従来どおり厳格照合する。文字補完・語の削除・customWordsのヒントは使わず、右列の「あり」もraw OCRと列候補の両方に残す。

保存済みOCR48条件を `compact-test --full offline-spatial-ocr-proof python3 .verification/ios-redesign-stage8b/remaining/offline-spatial-proof.py` で計算した。旧native slotのr8は6成功/18失敗のまま、自然高修正後の最終画像は24成功/0失敗。従来の実クリップを成功へ変えないことを確認した。全文・raw bbox・列の構成行・欠落文字は `remaining/offline-spatial-proof.json` に保存した。これは保存画像由来の計測の再評価であり、修正後Swiftテストの実走ではない。製品コードは変更せず、Swiftの検証実装に同じ空間列結合を入れた。構文parseとdiffcheckは成功、再ビルド・24条件の実走は別途行う。

### r11の先頭文字のOCR欠落

r11の実行は23条件成功、Mac到達不可・AX5・428pt・再接続中の1条件が失敗。保存画像で先頭「再」は可視だったが、元画像のVision top5は「接続して」「接続して」「用接続して」「手接続して」「冉接続して」で、正しい文字候補がなかった。言語補正を無効にしても「冉接続して」だった。文字を補完せず、crop全体へグレースケール（彩度0）＋コントラスト1.5という固定の一般的な読み取り補正を1回行ったところ、top1が「再接続して」（confidence 1.0）、次の行が「います。」（1.0）となった。領域も元のbbox x0.2033/y0.1854/h0.1027から補正後x0.2037/y0.1872/h0.0989と同じ前景を読んでいる。
