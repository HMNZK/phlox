下部タブ（2.2）
標準のタブバー: セッション／設定の 2 面（使用量の回で「使用量」タブを廃止。使用量は 5/6 で入力欄の下の 1 行のリングにした）。iOS 26 ではガラスで、スクロールすると縮む
変更 自前実装をやめて OS 標準にする。どの面へもいつでも行ける点（ADR 0007）は維持。使用量は新規チャットとセッション画面の入力欄の下に、残りのリング（円グラフ）として常にあり、押すと吹き出しで詳細が見えるので、行く操作が要らない
使用量の面「Usage」（12）
移す前: 「Usage」タブ → 一覧の下端の使用量バー（前回）→ 移した先: 新規チャットとセッション画面の、入力欄の下の 1 行のリング（押すと吹き出し。2 回目の修正 5/6）。タブと見出しは無くなる
変更 作業中にいつでも残りが見えるように（使用量の回の指示）。詳しくは盤面「設定と使用量 — 論点・機能対応表」
一覧の大見出し「Projects」（5）
大見出し「セッション」。読み込み・空・オフライン・エラーでも同じ位置
候補 タブ名と一致させる。見出しが消えない（ADR 0036）点は守る
タブの再タップ（2.2）
ルートへ戻り、先頭へスクロール
変更 iOS 標準の挙動に合わせる（現行は何も起きない）
詳細表示中のタブバー（2.2）
隠す。一覧へは左上のホームのボタン（家の形）か端スワイプで戻る → タブ
維持。下端を承認・質問のカード・入力欄・使用量の行に使うため
対応待ち（5.2。前の「あなたの番」）
一覧の先頭の「対応待ち」の欄（Mac のサイドバーと同じ名前）＋全タブ共通の対応待ちバー＋セッションタブのバッジ
変更 一覧を開かずに気づける。タップで先頭の詳細へ、長押しで選んで開く。解消 判定を補助文の文字列ではなく状態の値で行う（21.2-4）
承認バー（7.1）
セッション画面の入力欄のすぐ上の承認のカード「承認待ち · {操作の種類}」。複数は ‹ 1/2 › で送り、経過時間を出す（2 回目の修正 4/6）
変更 移動元は本文スクロールの先頭。最下部への自動追従で画面外に出ていた。解消 詳細の更新のたびに出し入れする（21.2-1）
Codex の 4 択（7.2）
承認のカードの 4 つのボタン「許可」「このセッション中は許可」「拒否」「キャンセル」（Claude Code と Codex で同じ。Cursor には承認が無い）
移動 移動元: 4 択シート（ReplyCodexSheet は消した）→ 移動先: カードのボタン（2 回目の修正 4/6）
質問カード（7.3）
未回答のものは入力欄のすぐ上の質問のカード「質問待ち · {見出し}」と「回答を送信」。回答済み・期限切れは会話内の共通のカード（4/6）
変更 応答の置き場所を承認と揃える。カードの中身は詳細の回で描く
応答後の表示（7.1）
承認のカードが「『許可』を送信しました」に変わる。次の対応待ちへは自分で進む（‹ › と対応待ちバー）
解消 英語の識別子（accept）を出さない（21.2-3）。次の対応待ちへの導線を足すのは配置の提案で、機能は増えない
詳細の見出し（6.1）
左上にホームのボタン、タイトル＝セッション名、小見出し＝状態の文言（記号なし・文字の色だけ）とエージェント名、右上に「…」
変更 現行は詳細に状態が出ない。取得済みの値を表示するだけ
到達不可（4.4・5.1）
一覧内の表示（維持）＋対応待ちバーの位置に接続状態と「再接続を試す」（全タブ）
候補 一覧以外のタブでも接続切れに気づける。ボタンの動作は一覧と同じ
