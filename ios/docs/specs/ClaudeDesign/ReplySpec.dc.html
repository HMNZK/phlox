承認・質問・入力を、セッション画面の入力欄のすぐ上にまとめる

変更 配置・挙動を変える 候補 提案。採否を決めてほしい 解消 21.2 節などの不具合を正しい振る舞いで描いた
論点: 承認を素早く、かつ誤承認しにくく
  1. 何を許可するかをボタンより上に置く。見出し「承認待ち · Bash」→ 対象（コマンド・パスを等幅で太く）→ 説明（全文）→ 差分があれば「› 差分を見る（2 ファイル）」→ ボタン。目が上から下へ動くと、押す前に必ず対象を通る
  2. 出た直後の 0.6 秒はボタンが反応しない。カードが出た直後と、内容が別の承認に変わった直後に適用する。一覧や対応待ちバーの「開く」と同じ位置を続けて叩いても承認されない。ボタンは薄い状態から濃くなり、効くようになったことが見える
  3. 承認したら次の承認へ自動で進まない。同じセッションの承認が複数あっても「‹ 1/2 ›」で自分で送る。送信後は結果と「次の対応待ち」を出し、「次へ」を押して初めて次のセッションへ。押す癖で別の承認を許可しない
  4. キーボード表示中は承認カードを 1 行に畳む。「承認待ち · Bash · 表示」の 1 行（ReplyKeyboardAppr）。文字入力中の指が承認ボタンに当たらない。「表示」でキーボードを閉じてカードを戻す
  5. 4 つのボタンを 2 段に分け、許可と拒否を別の段に置く。1 段目に「許可」（主ボタン・アクセントの塗り）と「このセッション中は許可」（副ボタン）、2 段目に「拒否」（副ボタン・赤い文字）と「キャンセル」（文字ボタン）。高さ 46 のカプセル、間は 8pt。Dynamic Type 最大では 1 列に積む（許可が上）。スワイプで承認、のような取り消せない近道は作らない
速さのほうは、対応待ちバー → セッション画面（入力欄の上に承認のカードが出た状態）→ 許可 の 2 タップで保つ。確認ダイアログは足さない（毎回出ると読まずに押す癖がつくため）
提案: 質問への回答画面（7.4）はセッション画面に統合する

回答画面は独立画面として残さず、セッション画面の入力欄の上の質問のカードに統合する。実データでは到達しない経路で、会話の文脈も添付・停止も無い。セッション画面の中で答えれば、直前の会話を見ながら答えられる。

エージェント種別による違い（14 章）
  • 承認: Claude Code と Codex で同じ 4 つのボタン、押すとすぐ送る。見出しの操作の種類だけが違う（Claude Code は Bash・Edit など、Codex は Shell）。Cursor には承認が無い（承認のカードも「承認待ち」も出ない）

  • 添付・質問・入力欄の形に種別差は無い。思考の強さの段階と権限の選択肢はエージェント（とモデル）ごとに違う
