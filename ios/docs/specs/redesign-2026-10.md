# iOS アプリ再設計（2026-10）— 画面ごとの要件と受け入れ基準

> **このファイルの役割**: 再設計後の iPhone アプリが満たすべきこと（画面ごとの要件・受け入れ基準・見本との対応・見本の食い違いの決定・未決の論点）。
> **書かないもの**: 作業の段取り（→ [delivery/0020](../delivery/0020-ios-redesign-plan.md)）、決定の理由（→ ADR 0043〜0047）、ワイヤの形（→ [mobile-api-extensions-contract.md](mobile-api-extensions-contract.md)）。
> 再設計前の画面の棚卸しは [ui-feature-inventory.md](ui-feature-inventory.md)（superseded）。見本が節番号（「7.1」「21.2-6」など）で引いているのはこの棚卸しの節。

## 0. 読み方

- **見本** = `ios/docs/specs/ClaudeDesign/` の盤面（版 241・248 枚）。盤面名はファイル名から `.dc.html` を除いたもの（例 `ReplyCodex`）。外枠の盤面は親（`List`・`Draft`・`Reply`・`Chat`・`Detail`・`Dialogs`・`Pair`・`DS` など）を props で呼ぶだけなので、**文言・寸法・色の正本は親のファイル**。
- **正本の順位**: この仕様書 ＞ 盤面の親ファイルの描画 ＞ 盤面の説明文（`*Spec`・`Revision20261017`・`Review*`）。説明文どうし・描画との食い違いは 14 章で決めた。
- **受け入れ基準**は `AC-<章>-<番号>` で引く。「描画テストで確かめる」は `make -C ios snapshot` の画像（428×926・375×667、ライト・ダーク、Dynamic Type 最大）と盤面との見比べ。「単体テストで確かめる」は `swift test --package-path ios/Packages/PhloxKit`。
- 見本に描かれていない状態は決めずに 15 章に「未決」として並べた。実装中に当たったら、そこで止めてユーザーに確かめる。
- 文言は見本の原文を「」で引く。英語表示の文言は見本に無い（15 章 U-20）。

## 1. 前提

| 項目 | 決定 | 根拠 |

| 配布対象 | iOS 18.0 以上。Liquid Glass は iOS 26 だけ。iOS 18 は同じ配置で不透明に描く | ADR 0043、`Shell`・`Shell18`・`Detail`・`Detail18`・`DS` 7 章 |
| 機能 | 見本に描かれたものだけ。足さない | 計画書 1 章 |

| D1 一覧のプロジェクト | 一覧に出すのはセッションが 1 つ以上あるプロジェクトだけ（見本のまま）。空のプロジェクトは、新規チャットのプロジェクトの選択肢には `GET /projects` で出す | 計画書 4 章 D1 |
| D2 承認の操作の種類 | Codex の承認は `GET /approvals` の `actionKind`（契約 §8.9）から、Claude Code の許可は質問の `header`（ツール名）から作る。見出しの語は 15 章 U-1 | 計画書 4 章 D2 |

## 2. 共通（色・ロゴ・状態の語・文字・動き・ガラス）

### 2.1 色（`DS`・`DSDark`）

| トークン | ライト | ダーク | 使い道 |
|---|---|---|---|
| `accent` | #1D1D1F | #F2F2F4 | 主ボタン・送信の面・選択中・フォーカス・リンク（下線で区別）だけ。装飾に使わない |
| `accentOnFill` | #FFFFFF | #000000 | accent の面の上の文字と記号 |
| `text` / `text.secondary` / `text.tertiary` | #1D1D1F / #56565E / #6B6B73 | #F2F2F4 / #AFAFB6 / #9D9DA5 | |
| `stop` / `badge` | #D62F26 | #E5483F | 停止の丸・件数のバッジ（白い記号を載せる） |
| `status.approval` | #A8430A（地 #FFEBD6） | #FFB46E | 承認待ち |
| `status.question` | #1555C0（地 #E3EEFF） | #8DB9FF | 質問あり |
| `status.error` | #B8241C（地 #FDE7E5） | #FF8C82 | エラー・失敗・取り返しのつかない操作 |
| `status.stalled` | #5B3FA8（地 #F1ECFB） | #C9B6FF | 無応答（Mac と同じ紫） |
| `status.caution` | #8A5300 | #F4BD68 | 使用量の残り 20% 未満だけ |
| `status.success` | #1F7A3A | #6FD08C | 完了（アプリ外の表示と差分の追加） |
| `status.neutral` | #3A3A42 | #D4D4DA | 実行中・待機・起動中・終了（アプリ外の表示） |

面（`bg.base`・`bg.card`・`bg.raised`・`bg.code`・`fill`・`separator`・`glass`・`bar`・`sheet`・`menu`・`dim`）は `DS` 1 章の表の値。

- AC-2-1: アクセントは白黒。紫・ピンクのグラデーション（`DSGradient.brand`）、エージェント別の色（`campAgentColor`）、略号のバッジは画面のどこにも出ない（描画テストと、トークンが消えていることを `rg` で確かめる）。
- AC-2-2: 塗りの面の上の文字は `accentOnFill`。ダークで白い面に白い文字が載らない。

### 2.2 ロゴ（`DS` 4 章）

- AC-2-3: エージェントは実物のロゴで示す。Claude・Codex は形をマスクにして `text.secondary` の単色、Cursor は元の色。ライト・ダークとも同じ規則（画像は `ClaudeDesign/logos/`）。
- AC-2-4: VoiceOver はロゴをエージェント名で読む。行など親が読むときは重ねて読ませない。

### 2.3 状態の語（`ListSpec`・`List`・`DS` 5 章）

アプリ内は**文字だけ**で、記号を付けない（例外は会話のエラーの面の三角 1 つ。8.7）。記号はロック画面・ウィジェット・Live Activity・Dynamic Island だけ（12 章）。

| 状態 | 一覧の右端 | 色 | 太さ |
|---|---|---|---|
| 待機 | 出さない | — | — |
| 起動中 | 起動中 | `text.tertiary` | 標準 |
| 実行中 | 実行中 | `text.secondary`。名前に光の帯 | 500 |
| 承認待ち | 承認待ち | `status.approval` | semibold |
| 質問あり | 質問あり | `status.question` | semibold |
| エラー | エラー | `status.error` | semibold |
| 無応答 | 無応答 | `status.stalled` | semibold |
| 完了 | 完了 | `text.tertiary` | 標準 |
| 終了 | 終了 | `text.tertiary` | 標準 |

- AC-2-5: 状態の語はこの 9 つだけで、画面ごとに言い換えない（「質問待ち」は質問のカードの見出しだけで使う。9.3）。
- AC-2-6: 承認待ちになるのは Claude Code と Codex だけ。Cursor のセッションには承認のカードも「承認待ち」も出ない。
- 「無応答」「終了」「未読」は今の Control API に元の値が無い（15 章 U-3）。

### 2.4 文字（`DS` 2 章）

- 和文 Hiragino Sans・欧文 SF Pro（OS 標準）、等幅 SF Mono。等幅はコマンド・差分・接続先・エラーの詳細など技術値だけ。
- DotGothic16 は新規チャットの中央の見出しだけ（`display.dot` 28／xxxL 34／AX5 44）。Mac と同じ ttf を同梱し `UIAppFonts` に登録する。ライセンス（SIL OFL）を「このアプリについて」に出す。
- AC-2-7: 段は `DS` 2 章の表（largeTitle 34・headline 17・body 17・callout 16・subheadline 15・footnote 13・caption1 12・caption2 11・mono.inline 15・mono.block 13）。Dynamic Type に追従する。
- AC-2-8: Dynamic Type が AX1 以上では、横に並べた補足（時刻・%）を次の行へ回す。切り捨てるのは名前の末尾だけ。ボタンは最小 44pt で文字に合わせて高くなり、アラートのボタンは縦に積む。コードと差分は折り返さず横スクロール。

### 2.5 動き（`DS` 3 章）

- AC-2-9: 押す 0.1 秒／戻す 0.2 秒、開閉 0.25 秒（高さだけ）、シート・push は OS 標準、新着への追従は最下部から 80pt 以内のときだけ 0.3 秒、承認カードの無効時間 0.6 秒（9.1）、スピナー 0.9 秒で 1 周、外観の切り替え 0.2 秒、削除した行は 0.3 秒で詰める。
- AC-2-10: 「視差効果を減らす」では回転・光の帯・スライドを止め、フェードと文言の切り替えだけにする。状態は文言で伝わる。

### 2.6 ガラス（Liquid Glass）と iOS 18 の描き方（`DS` 7 章、ADR 0043）

| 部品 | iOS 26 | iOS 18 |
|---|---|---|
| タブバー | 「セッション」「設定」のガラスのカプセル（スクロールで丸に縮む） | OS 標準のタブバー（端から端・上に線） |
| 新規チャット | タブバーの右に 10pt 離した丸いガラス（62pt） | 一覧の大見出しの右（44pt） |
| 対応待ちバー | タブバーの上に浮くガラス（角丸 28、左右 16pt） | タブバー直上の素材の帯（角丸 16、左右 12pt） |
| 入力欄 | 2 段のガラス（角丸 26） | 素材の欄＋細い線 |
| 承認・質問のカード | ガラス（角丸 22） | 不透明寄りの面＋1pt の線（角丸 18） |
| ナビの丸ボタン（ホーム・「…」） | ガラスの丸 44pt | 印だけ（丸い地なし）。タップ領域は 44pt のまま |
| 使用量の行 | ガラスにしない | 同じ |
| 「…」メニュー・長押し・シート | OS 標準 | OS 標準 |

- AC-2-11: ガラスは操作の層（上の表）だけ。行・カード・会話・ダイアログの中身はガラスにしない。
- AC-2-12: iOS 26 と iOS 18 の分岐は共通の部品の中だけにあり、画面のコードに `#available(iOS 26, *)` が散らばらない（`rg` で確かめる）。

## 3. 下部のナビゲーションと対応待ちバー（`Shell`・`Shell18`・`ListSpec`・`Main`・`Mapping`・`Layers`）

- AC-3-1: タブは「セッション」「設定」の 2 つ。使用量のタブ・画面・設定の区画は無い（`Shell`）。
- AC-3-2: 「新規チャット」は iOS 26 ではタブバーの右に離した丸で、どのタブでも同じ位置（`Shell`、`FlowUsage`）。iOS 18 は一覧の大見出しの右（`Shell18`。設定タブ・スクロール時は 15 章 U-14）。
- AC-3-3: セッションのタブのバッジは対応待ち（承認待ち＋質問あり）の件数。0 件では出さない。タブの VoiceOver は「セッション、対応待ち 2 件」の形。
- AC-3-4: 一覧をスクロールすると、iOS 26 ではタブバーが左の丸（56pt）に縮み、対応待ちバーが丸と新規チャット（56pt に縮む）の間に入る（`ListManyScrolled`）。iOS 18 では縮まない。
- AC-3-5: 対応待ちバーはタブバーの上に出し、「対応待ち N」・先頭の「セッション名 · 状態」・「開く ›」を並べる。押すと先頭の対応待ちのセッション画面を、入力欄の上にカードが出た状態で開く（`Shell`）。0 件・読み込み中・接続判定中・空・取得エラーでは出さない。
- AC-3-6: 対応待ちバーの長押しで、対応待ちを選んで開くメニュー（各行「状態 · エージェント · プロジェクト」と「セッション一覧で見る」）を出す（`FlowMenu`）。
- AC-3-7: Mac に届かないときは、対応待ちバーの位置に「Mac に届きません」「最終取得 3 分前 · スリープ中か Tailscale 切断」「再接続を試す」を出す。どのタブでも同じ（`ShellOffline`、`SetDisc`）。
- AC-3-8: セッション画面・新規チャットに入るとタブバーと対応待ちバーを隠す。タブを押し直すとルートへ戻り先頭へスクロールする（`Layers`、`Mapping`）。
- AC-3-9: 重なり順は手前から 起動ゲート → 全画面の接続中 → アラート → シート → push 画面 → タブのルート。シートとアラートは同時に 1 つだけ（`Layers`、ADR 0013）。

## 4. セッション一覧（`List*`・`ListSpec`）

### 4.1 構成

- AC-4-1: 大見出しは「セッション」で、読み込み・空・オフライン・エラーでも同じ位置（`List`）。
- AC-4-2: 上から「対応待ち」→ プロジェクトごとの欄 → 「その他」（プロジェクト未割当）の順（`List`、`ListMulti`）。並べ方の細部は 15 章 U-6。
- AC-4-3: 「対応待ち」は件数の丸つきの見出しと中立の細い縁のカード。開閉しない。入るのは承認待ち・質問ありだけで、そのセッションはプロジェクトの欄に重ねて出さない（`ListMulti`、`ListAllAttention`。エラー・無応答を入れるかは 15 章 U-4）。
- AC-4-4: プロジェクトの欄はセッションが 1 つ以上あるものだけ（D1）。見出しは「開閉の印・名前」と右端の「＋」。「＋」は常に出し、タップ領域 44pt、押すとそのプロジェクトで新規チャットを開く（`DraftFromProject`）。見出しの残りを押すと開閉する。既定は開。
- AC-4-5: 「その他」は開閉でき、「＋」は付けない。
- AC-4-6: 閉じた欄の見出しの右に内訳を「語 数」で空白 1 つずつ並べる（例「エラー 1 実行中 2 未読 3」）。順は 承認待ち → 質問あり → エラー → 無応答 → 実行中 → 未読。語は 2.3 の色と太さ、未読は `text.secondary` の 500。子セッション（孫まで）も数える（`ListCollapsed`）。

### 4.2 行

- AC-4-7: 行は名前と右端の状態の語（2.3）だけ。ロゴ・記号・相対時刻・ワークスペース名は出さない。高さ 48pt（Dynamic Type 最大で 64pt 以上。名前は折り返し、状態の語は折り返さない）。
- AC-4-8: 未読は名前を `text`・semibold、既読は `text.secondary`・標準。未読の丸は使わない。
- AC-4-9: 実行中は名前に光の帯が 3.2 秒で 1 回流れる（ライト #C9C9D0、ダーク #FFFFFF）。視差効果を減らす設定では止めて普通の色で出す。
- AC-4-10: 子セッションは 1 段 22pt 字下げし、左に 1.5pt の案内線。子を持つ行は左端の開閉の印（44×44）で開閉し、閉じると名前の後ろに「+N」（孫まで数える。`text.tertiary`）。子を持たない行は印の代わりに 20pt の空白（`List`、`ListCollapsed`）。開閉の既定と記憶は 15 章 U-5。
- AC-4-11: どの行を押してもセッション画面へ。承認待ち・質問ありは入力欄の上にカードが出た状態で開く（`ListPressed`、`ListTapDetail`）。
- AC-4-12: VoiceOver は行を「名前、状態、未読、N 段下の子セッション」と読む。開閉の印は「名前 の子セッション N 件、展開中／折りたたみ中」、プロジェクトの見出しは「名前、N 件、展開中／折りたたみ中」、「＋」は「名前 で新規チャット」。

### 4.3 読み込み・空・接続・エラー

- AC-4-13: 引っ張って更新は OS 標準のインジケータで、使用量も取り直す。表示は消さない（`ListPull`）。3 秒ごとの取得は前面にいる間だけ。
- AC-4-14: 読み込み中は見出しとカードの形のスケルトン（視差効果を減らす設定では静止。`ListLoading`）。
- AC-4-15: 接続の判定中は「Mac に接続しています…」と等幅の接続先。オフラインの表示は判定して失敗したときだけ（約 20 秒で打ち切り。`ListJudging`、ADR 0027）。
- AC-4-16: 空は図・「セッションがありません」・説明・主ボタン「新規チャット」（`ListEmpty`）。説明は「Mac でエージェントを動かすと、ここにセッションが並びます。iPhone から始めるときは「新規チャット」を押してください。」。
- AC-4-17: オフライン 3 種は本文のカード 1 枚: 圏外「インターネットにつながっていません」（無彩色）、Mac に届かない「Mac に届きません」（赤）＋等幅「100.64.0.1:8765 · 無応答」、確認中「接続を確かめています」＋「最大 20 秒ほどかかります」（無彩色）。末尾に「最終取得 3 分前 · 下の「再接続を試す」で今すぐ確認」（`ListOffNet`・`ListOffHost`・`ListOffUnknown`）。
- AC-4-18: 取得エラーはカード（赤い見出し・本文・ボタン）。500「Mac の Phlox でエラーが起きました」＋「再試行」、401「Mac に接続を断られました」＋「QR で再接続」（`ListError`・`ListError401`）。ほかの種類は `Errors` の F1〜F8。

## 5. 新規チャット（`Draft*`・`DraftSpec`）

- AC-5-1: 入口は下部の「新規チャット」・プロジェクトの見出しの「＋」・空の一覧の「新規チャット」。エージェントを先に選ぶ段階は無い（`Draft`、`DraftFromProject`）。
- AC-5-2: 上部は左上のホーム（家の形・44pt。VoiceOver「ホーム（セッション一覧に戻る）」）だけ。「…」は出さない（14 章 C-2）。端スワイプで一覧に戻れる。
- AC-5-3: 中央の見出しは開くたびに次の 10 種から 1 つ（DotGothic16・中央寄せ・ロゴなし）:「何から始めますか？」「今日は何を進めますか？」「さあ、始めましょう」「次は何を作りますか？」「どこから手をつけますか？」「アイデアを形にしましょう」「今日の課題を教えてください」「どんな変更を加えますか？」「続きを進めましょう」「何をお手伝いしましょうか？」。選び方（乱数か順番か）は実装で決めてよいが、描画テストでは固定できること。
- AC-5-4: 開いた時点で入力欄にフォーカスが入りキーボードが上がっている（`Draft`）。
- AC-5-5: 提案チップ 5 つ（コードレビュー・バグ修正・テスト追加・コードの説明・リファクタ）を横に並べ、はみ出しは横スクロール。押すと定型文を入力欄の末尾に足し、送らない。カーソルは末尾、キーボードは上がったまま（`DraftSuggest`）。定型文は見本の仮の値で、段階 5 で Mac の文言に合わせる（14 章 C-9）。VoiceOver「提案: {名前}。入力欄に追記します」。
- AC-5-6: プロジェクトのチップは 2 段目の右寄せ（フォルダの印・名前・⌄）。初期値は、下部の入口なら前回使ったもの、「＋」の入口ならそのプロジェクト。選択肢は `GET /projects`（セッションが 0 件のものも含む。D1）。古い Mac では一覧のセッションから組み立てる（契約 §8.6）。選択中に ✓、前回使ったものに「前回使った」（`DraftProject`）。
- AC-5-7: プロジェクト未選択で送ると、入力欄の上に赤い 1 行「プロジェクトを選んでください」を出して送らない（`DraftEntryEmpty`）。
- AC-5-8: モデルのチップ（ロゴ・表示名・⌄。エージェント名の文字は出さない）を押すと、3 エージェントの全モデルを 1 枚のシートに出す。見出し「モデル」・「閉じる」・絞り込み欄「絞り込み」、Claude Code → Codex → Cursor の順に区切り、選択中に ✓、既定に「既定」。注記「モデルを選ぶと、エージェントもそのモデルのものに切り替わります」（`DraftModel`）。表示名は Mac から届いたまま。
- AC-5-9: 一覧を取れないエージェントの欄は「取得できません」の行で選べない。ほかの欄は選べる（`DraftModelNa`）。

## 6. 入力欄（`Reply*`・`ReplySpec`・`Draft*`）

### 6.1 形

### 6.2 モデル・思考の強さ・権限

- AC-6-7: セッション画面のモデルのシートはそのエージェントのモデルだけ（`ReplyModel`、`Dialogs` M1〜M4）。行を押した時点で反映し、反映中は行にスピナー、失敗はシート内の赤い帯で元のまま。

### 9.1 承認のカード

- AC-9-1: 入力欄のすぐ上に 1 枚ずつ出し、会話の中には出さない。上から 見出し「承認待ち · {操作の種類}」（`status.approval`）＋経過時間（「2 分」）＋複数のとき右端に「‹ n/m ›」（44pt）→ 対象（等幅 15pt 太字・折り返す）→ 説明（全文）→ 差分があるとき「› 差分を見る（N ファイル）」→ ボタン（`Reply`、`ReplyApprovalDiff`）。
- AC-9-2: ボタンは 4 つ。1 段目「許可」（塗り）と「このセッション中は許可」、2 段目「拒否」（赤い文字）と「キャンセル」（文字だけ）。押すとすぐ送り、確認しない（`FlowApprove`）。Dynamic Type 最大では 1 列で 許可 → このセッション中は許可 → 拒否 → キャンセル（`ReplyDT`）。
- AC-9-3: 1 つの部品を 2 つの経路から作る（Mac の `ChatReplyApproval.swift` と同じ組み方）:

  | | Codex | Claude Code |
  |---|---|---|
  | 届く経路 | `GET /approvals` | 会話の `userQuestion`（ツール使用の許可の質問。契約 §8.7） |
  | 許可 | `POST /approvals/{id}` `accept` | 質問に `"Allow"` |
  | このセッション中は許可 | `acceptForSession` | 質問に `"AllowForSession"`。`allowsSessionScope` が true のときだけボタンを出す |
  | 拒否 | `decline` | 質問に `"Deny"` |
  | キャンセル | `cancel` | ターンの中断（`POST /sessions/{id}/interrupt`） |
  | 見出しの操作の種類 | `actionKind`（契約 §8.9） | 質問の `header`（ツール名） |

- AC-9-4: 誤承認を防ぐ: 出た直後と内容が別の承認に変わった直後の 0.6 秒はボタンが反応せず、薄い状態から濃くなる。承認の後に次の承認へ自動で進まない（「‹ ›」で自分で送る）。スワイプなどの取り消せない近道は作らない。
- AC-9-5: キーボード表示中はカードを 1 行（高さ 48）に畳む:「承認待ち · {種類} · {対象}」と右に「表示」。「表示」でキーボードを閉じてカードに戻す。VoiceOver「承認待ち · Bash、{対象}。表示するとキーボードを閉じます」（`ReplyKeyboardAppr`）。
- AC-9-6: 送れなかったらカードを残し、上に赤い 1 行「承認を送信できませんでした（Mac に接続できません）」（`ReplyApprovalFail`）。
- AC-9-7: 送れたらカードを「「許可」を送信しました」に変え、残りがあれば「次の対応待ち（残り n）」と「次へ ›」を出す。自動では進まない（`FlowNext`）。
- AC-9-8: Codex の承認一覧に `actionKind` が無い（古い Mac）・値が未知のときは、見出しを「承認待ち」だけにする。

### 9.2 差分

- AC-9-9: 「› 差分を見る（N ファイル）」を押すと、カードの中で先頭のファイルを開いた差分（行番号つき）、残りは閉じた行。文言は開いても変えず矢印だけ下向き（`ReplyApprovalDiff`）。

### 9.3 質問のカード

- AC-9-10: 見出し「質問待ち · {最初の質問の見出し}」（複数なら「ほか n 問」。`status.question`）。質問ごとに番号つきの見出し・「1 つ選ぶ」／「いくつでも」・質問文・選択肢（単一は丸、複数は四角）・自由入力「選択肢以外で答える」（入力すると選択は外れる）。「回答を送信」は全問に答えるまで押せず、下に「あと n 問に答えると送信できます」（`ReplyQuestion`、ADR 0024）。
- AC-9-11: 選択肢の無い質問は補足「選択肢のない質問です。下の入力欄に書いて送信してください。」を出し、入力欄のプレースホルダを「回答を入力」にする（`ReplyQuestionPlain`）。
- AC-9-12: 送れなかったら上に赤い 1 行「回答を送信できませんでした。選んだ内容は残っています」（`ReplyQuestionFail`）。
- AC-9-13: 独立した質問の回答画面は無い（ADR 0044 の廃止一覧）。Claude Code のツール使用の許可の質問は質問のカードでなく承認のカードで出す（9.1）。
