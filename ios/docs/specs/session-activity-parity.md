# 問題定義: iOS の実行状態・完了表示・履歴操作を Mac に揃える

2026-10-25 ユーザー承認済み。実装・検証を進めるための仕様。実行状態・履歴操作に加え、使用量の表示と更新、新規チャットの作業場所・起点・履歴再開を Mac と統一する。

## 解決したい問題

同じセッションを Mac と iPhone で見た際に、実行中・完了の意味と見た目、過去の会話を読む操作が異なる。Mac の新しい状態表示へ iOS を揃え、上端で履歴を引いて離す操作も採用する。

対象は iOS アプリ内のセッション一覧（子セッションを含む）、会話の状態表示、会話末尾の進行表示、履歴の追加表示、および承認済みの使用量・新規チャット追加要件。既存の再設計仕様と競合する箇所は、本仕様を優先する。

### 追加で統一する要件（2026-10-25 承認）

- 使用量は横棒を既定にし、設定で数値表示へ切り替える。選択は端末に保存する。小さい画面と大きい文字では折り返し、詳細・残量の読み上げ・欠損値の扱いは維持する。
- アプリが前面で接続・認証済みの間は使用量を起動時と60秒ごとに再取得する。背面・接続解除・ロック中は停止する。手動更新も維持し、重複した取得はまとめる。リセットを過ぎた古い枠は表示から除き、0%使用済みと偽って埋めない。
- 新規チャットは登録済みプロジェクトから「そのままの作業場所／新しいworktree」を選べる。worktreeでは開始ブランチ・タグ・コミットを Mac と同じ候補・検証規則で指定する。
- Claude・Codex は選択プロジェクトの履歴から再開できる。Macで既に開いている履歴は再開候補から除外する。履歴再開時に通常の初回メッセージを二重送信しない。Cursor等の未対応エージェントへ再開を提示しない。
- 新しいAPIでも既存の認可、親子関係、起動数制限を維持する。登録外プロジェクト、不正な起点、別プロジェクト・別エージェントの履歴を拒否する。内部の履歴ファイルパスをスマホへ返さない。
- 追加受け入れ条件: 使用量の設定保存・定期取得のキャンセル・期限切れ、起点一覧と不正入力、履歴選択と再開時の送信0回をテストする。通常起動・既存Control呼び出しも回帰確認する。

上の照合表の「追加候補」は、この承認によって今回の実装対象となった。旧 iOS 仕様の AC-5-15、AC-7-2、U-7 と競合する範囲は本仕様を優先する。

### 表示仕様

「未確認の完了」は、正常終了を利用者がまだ確認していない状態を指す。単なる待機・中断・失敗とは区別する。

| 状態 | iOS で揃える表示・動作 |
|---|---|
| 実行中 | 一覧の状態文言に加え、Mac と同じオレンジの半円スピナーを表示。名前に対する実行中の光の帯は廃止。会話のヘッダーでも同じ状態部品を使用 |
| 未確認の正常完了 | 緑の円とチェック。一覧の既存の未読強調は維持。回転表示は止める |
| 確認済みの完了 | 緑のチェックを消し、既存の完了文言を表示。通常の再描画や再接続で未確認へ戻さない |
| 前面で同じ会話を閲覧中に正常完了 | 確認済みとして扱い、完了チェックを残さない。初回・継続ターンとも同じ |
| 別会話・一覧・アプリ背面で正常完了 | 未確認の完了を保持し、対象の会話を前面で表示して確認したときに消す |
| 中断要求中 | 要求を受け付けたことだけで正常完了にしない。実際の状態確定に追従する |
| 中断確定 | 実行中表示を止める。以前の未確認完了チェックを残さない。新しい正常完了チェックも作らない |
| 承認待ち・質問・エラー・無応答・起動中・待機 | 共有の状態解決規則と既存の文言・操作を維持。実行中スピナーや成功チェックで置き換えない |

実行中スピナーは直径18pt、線幅2.5pt、オレンジ `RGB(1, 0.53, 0)` の半円と薄い下地。0.8秒で等速に1周し、Mac と同じ時刻基準で位相を決める。セッション間の再描画で回転をリセットしない。

完了は同じ18pt枠で、円を0.5秒で描き、0.1秒待ち、チェックを0.3秒で描く。繰り返さない。緑はライト `RGB(0.05, 0.58, 0.34)`、ダーク `RGB(0.29, 0.82, 0.58)` を基準とする。表示が残っている間の再描画では再生し直さない。

会話末尾の「考え中」等の活動ラベル、光の帯、要約は既存の共有実装を使う。一覧の回転表示とは用途を分ける。承認待ち・質問・無応答へ移った際に古い実行中表示を併記しない。初期読み込み・起動待ち・送信中は別状態のままとし、一律にオレンジの実行中表示へ変えない。

### 上端の履歴操作

1. 表示窓の外に古い履歴があるとき、会話の上端からさらに下方向へ引くと、上端中央に履歴用のリングを出す。単に上へスクロールしただけでは展開しない。
2. 指を離すと既存の表示窓を1段階だけ広げ、展開前の先頭メッセージの画面上の位置を保つ。1ジェスチャーで重複展開しない。
3. 引いている途中で上端から離れる方向へ戻せば表示を消し、展開しない。古い履歴が残っていなければリングも出さない。
4. 過去を読んでいる間、新着・活動ラベル更新・完了で最下部へ飛ばさない。既存の最新位置へ戻る操作と、戻った後の自動追従を維持する。
5. VoiceOver 等でも同じ展開を行えるよう、既存の「以前のメッセージを表示」操作を利用可能にする。指の操作だけを唯一の入口にしない。

履歴用リングは `CometLoader` を基準に直径22pt、線幅2pt、透明→灰→白のグラデーション、0.9秒で1周とする。実行中のオレンジとは区別する。表示は履歴展開の準備・処理中だけで、人工的な待ち時間を設けない。ライト・ダークで背景との視認性を確認する。

### アクセシビリティ

「視差効果を減らす」では回転と光の帯を止め、完了は完成したチェックを直ちに表示する。状態文言は残す。親が状態を読む場合は装飾アイコンを重複して読み上げない。履歴リングの読み上げは「以前のメッセージを読み込み中」。ボタンは44pt以上、Dynamic Type で状態語が欠けない配置とする。

## 仮定 / 未知

- スマホはリポジトリ内の iOS アプリを指す。Android は対象外。
- 上端操作の参照 `4a326088` は main 未統合。今後 Mac 側が変わった場合は実装前にこの節と受け入れ条件を照合する。
- 従来のAPIは未確認完了の受信だけだった。本件では `completionToken` と `POST /sessions/{id}/completion-seen` を追加して確認状態を共有する。古い要求が次の完了を消さないよう、runtimeでの適用時にもtokenを照合する。端末内だけで隠して同期済みと扱わない。
- iOS の「前面閲覧」はアプリが active で、対象会話が表示され、別画面に覆われていない状態とする。画面を上へスクロールしていても、会話自体を閲覧中なら Mac と同じく確認済みとする。
- 会話ヘッダーへの共通インジケーター追加と、履歴用リングのライト背景での見え方は本仕様での提案。描画比較で確定する。

## 制約（技術・運用・期限）

- 既存の `SessionDisplayState.resolve` と共有 DesignSystem を再利用し、iOS 独自の状態判定を増やさない。
- 実装前に [再設計仕様](redesign-2026-10.md) の「文字だけ」「名前の光の帯」「スピナー0.9秒」の対象箇所、関連見本・API契約を本仕様へ揃える。実行中は0.8秒、履歴は0.9秒と区別する。
- 変更の到達先は共有表示部品、一覧・会話、履歴展開と追従、完了確認の同期、関連テスト・描画fixture・文書。既存のウィジェット等への状態投影も回帰確認する。
- XCUITest は実行しない。入力ソースは追加しない。検証物は作業専用の `.verification/` に分離する。
- 実装は専用worktree `mobile-desktop-parity-20261025` で行い、元の作業場所にある利用者の未コミット変更には手を加えない。

## スコープ外

- ウィジェット・Live Activity・Dynamic Island の常時回転。OS の更新制約があるため、アプリ内と同じ連続アニメーションは要求しない。状態の意味は維持する。
- 会話全体の再設計、添付画像・入力カーソルの修正、不要な依存追加。会話本文の新しい履歴取得APIは対象外（再開候補・起点取得APIは対象）。

## 既知リスク

- 完了確認を端末間で共有するため、iPhone で確認した完了は Mac でも確認済みになる。要求時・runtime適用時のtoken一致確認で、次の完了を誤って消すことを防ぐ。
- 表示窓の展開中に新着が届くとスクロール位置がずれる可能性がある。IDによるアンカー維持と競合テストが必要。
- 既存見本は「文字だけ」の旧仕様を含む。旧見本だけで新しい記号を不具合と判断しないよう、承認後に参照を更新する。
- `@karpathy-CLAUDE.md` は指定位置と今回の検索範囲で見つからず、内容は未確認。
