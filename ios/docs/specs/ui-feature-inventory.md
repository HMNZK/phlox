# Phlox iOS UI 機能インベントリ

> 再設計前の棚卸し。正本は [redesign-2026-10.md](redesign-2026-10.md)。

この文書は、Phlox iOS アプリ（PhloxMobile 本体と PhloxWidget 拡張）の UI を、機能は変えずに 0 から再設計するデザイナー向けに、現行 UI の機能・状態・文言を「画面（情報設計上の単位）」別に棚卸ししたものである。調査は、本体の View・ViewModel・ドメイン型を直接読了した分と、ADR 42 本・ウィジェット／Live Activity／通知・デザインシステムを 4 本の委譲調査で読んだ分とで構成する（範囲は 23 章）。根拠は現行コードの `file:line` を正とする。docs・ADR・コメント由来で実コードを確認していない記述は「未確認（文書のみ）」、推測は「推測」と明記する。文書と実コードが食い違う場合はコードを正とし、21 章に書く。対象は iOS アプリ（`ios/App`・`ios/PhloxWidget`・`ios/Packages/PhloxKit/Sources`）と、そこから参照される macOS 側の共有パッケージ（`macos/Packages/DesignSystem`・`AgentDomain`〔`ChatRenderKit` を含む〕）のうち iOS 画面に出る部分に限る。Mac アプリ、CLI、サーバ（MobileProxy）自体の仕様は対象外で、UI に現れる範囲でのみ触れる。アプリアイコンは対象外。

**パス略記**: `K/` = `ios/Packages/PhloxKit/Sources/`、`F/` = `K/Features/`、`DS/` = `K/DesignSystemIOS/`、`M/` = `macos/Packages/`。`App/` = `ios/App/`。

## 2. 全体のナビゲーション

### 2.1 ルートの状態分岐

`AppRoot` は `AppModel.state` で本体を切り替える（`App/AppRoot.swift:131-143`、純粋ロジックは `F/AppModel.swift:64`）。

| 状態 | 条件 | 表示 | 根拠 |
|---|---|---|---|
| `locked` | Face ID ロックが有効で未認証（起動時・バックグラウンド復帰） | 起動ゲート | `AppRoot.swift:42-44, 80-86`、`AppModel.swift:75-80` |
| `setupRequired` | 認証済みで接続設定（host/port）が無い | 接続設定（NavigationStack。QR スキャンへ push） | `AppRoot.swift:147-157` |
| `sessions` | 認証済みで接続設定がある | 3 タブ構成 | `AppRoot.swift:161-173` |

到達性は分岐に使わない（`AppModel.resolve` は reachability を無視）。到達不可は一覧の内部表示で扱う（5 章）。ロックはロック無効に切り替えた時点で即解除される（`AppRoot.swift:91-95`）。

### 2.2 下部タブ（自前実装）

- 3 タブ: 「セッション」（`list.bullet`）／「設定」（`gearshape`）／「Usage」（`chart.bar`）（`AppRoot.swift:197-223`）。標準 `TabView` は使わず、自前の `Button` 群（ADR 0006・0007）。
- 選択中はアクセント色＋太いアイコン、非選択は補助色。再タップしても何も起きない（ルートへ戻らない。`AppShellViewModel.handleTabTap`＝単なる選択）。
- 各タブは独立した `NavigationStack` を持ち、スタック状態は `AppRoot` が保持する（`AppRoot.swift:17-20`）。
- **セッションタブでスタックに 1 画面以上 push されている間はタブバーを隠す**（詳細・回答画面・QR 画面共通。入力バーを下端／キーボード直上に置くため。`AppRoot.swift:175-179`）。設定・Usage タブはタブバーを隠さない。初回セットアップ（`setupRequired`）にはタブバー自体が無い。

| セッション | 一覧 | セッション詳細・下書き詳細・質問への回答画面 |

### 2.5 外部からの遷移

| 入口 | 動作 | 根拠 |

### 2.6 その他の全体挙動
- 外観切替（システム／ライト／ダーク）は再起動なしで即反映（ルートを再構築。`AppRoot.swift:55-57, 96-102, 546-550`、ADR 0004）。再構築のため、一時的な画面内状態は失われる。
- 前面復帰時、一覧は購読を再開（`SessionListView.swift:64-72`）。バックグラウンド移行でポーリング停止。
- ナビバーは不透明な surface 色（背景色に溶けない）。一覧のみ大タイトルを自前描画（ADR 0036）。

## 3. 起動ゲート（Face ID / パスコード）

構成（`F/LaunchGate/LaunchGateView.swift:42-93`）: ロゴ（84pt のグラデ角丸＋スパークル）→「Phlox」→ タグライン → Face ID 枠（66pt・緑の枠線・`faceid`）→ 状態文 → 補足（Keychain）→ 下端に「パスコードを使用」。

| 項目 | 内容 |
|---|---|
| 自動認証 | 画面表示と同時に認証を開始（`.task`、`:92`）。Face ID 枠のタップでも再認証（`:110`） |
| 「パスコードを使用」 | 同じ認証を再実行するだけ（`:82-84`）。OS は生体が使えない端末ではパスコードに切り替わる（`PhloxSecurity/BiometricGate.swift`：生体不可なら `deviceOwnerAuthentication`）。ボタン自体がパスコードを強制するわけではない |
| 認証理由（OS ダイアログ） | 「Phlox のロックを解除」（`LaunchGateViewModel.swift:32`） |
| 失敗 | 失敗・キャンセル・エラーのいずれも同一文言「認証に失敗しました。もう一度お試しください。」を赤で表示（`:33-35`）。回数制限・ロック・待機表示は無い |
| ロックの有効化 | 設定タブの「Face ID / Touch ID でロック」。**既定オフ**（ADR 0017）。オンのとき、起動時とバックグラウンド移行のたびにロック |
| ネットワーク | 認証前は API を呼ばない設計（ViewModel が API を持たない） |
| 権限文言（Info.plist） | 「保存したセッション情報を保護するため、起動時に Face ID で本人確認します。」（`App/Info.plist`） |

## 4. 接続設定・QR ペアリング・接続中・到達不可

### 4.1 接続設定（初回／設定タブ）
同じ部品を 2 か所で使う。初回は全画面（`ConnectionSettingsView`）、設定タブでは先頭セクション（`ConnectionSettingsSection`）（`F/ConnectionSettings/ConnectionSettingsView.swift`）。

| 要素 | 内容 |
|---|---|
| 見出し（初回のみ） | 「接続設定」／「Mac の Phlox に QR コードで接続」 |
| セクション名 | 「接続」 |
| 現在の接続先 | 「現在の接続先」＋ `host:port`（未設定は「未接続」）。長押し選択可 |
| QR ボタン | 未設定「QR で接続」／設定済み「QR で再接続」 |
| 疎通テスト | 「疎通テスト」。接続先が無い間は押せない。実行中はスピナー。結果は成功「接続成功 · GET /sessions → 200」／失敗「到達不可 · Mac がスリープ中の可能性」バナー。接続先が無いときは「QR コードを読み取って接続してください」（`ConnectionSettingsViewModel.swift:6-17, 76-92`） |
| 手入力 | **無い**。host/port/token を入力する欄は存在しない（QR のみ） |

### 4.2 QR スキャン（`F/Pairing/QRScanScreen.swift`）
ナビバータイトル「QR でスキャン」（インライン）。

| 状態 | 表示 | 根拠 |
|---|---|---|
| 読み取り中（カメラ可） | カメラを画面全体（ナビバー下〜下端）に表示。上部に半透明黒帯＋「Mac に表示されたペアリング用 QR を読み取ります」。QR 1 件を検出すると停止して処理。ピンチズーム・ガイド・ハイライト有効 | `:320-337, 351-381` |
| カメラ不可（シミュレータ・権限拒否・非対応） | 案内「カメラを利用できません。シミュレーターの場合は「写真から読み取る」で QR 画像を選択してください。」＋「写真から読み取る」ボタン（写真ピッカー）。権限拒否でも同文言 | `:208-212` |
| 適用中 | 接続中アニメ（96pt）＋「接続情報を適用しています…」 | `:239-258` |
| 成功 | 緑バナー「接続しました（<Mac 名>）」（名前が無ければ「接続しました」） | `QRScanCopy.successMessage` |
| 接続不可（保存は成功） | 赤バナー「Mac に接続できませんでした。Tailscale の接続を確認し、Mac 側で QR を再表示して、もう一度スキャンしてください。」＋「もう一度スキャンする」 | `PairingApplyViewModel.swift:44, 50-51` |
| 読み取り失敗 | 赤バナー＋「もう一度スキャンする」 | `:239-246` |

**QR パースエラー 5 種**（検証順固定。`PhloxCore/Pairing/PairingPayload.swift`、文言は `QRScanCopy.message`）:
1. 「ペアリング用の QR コードではありません」（`phlox://pair` 形式でない）
2. 「未対応の QR バージョンです」（`v` が無い／`1` 以外）
3. 「ホスト情報が見つかりません」（`host` 欠落・空）
4. 「ポート番号が不正です」（1〜65535 以外）
5. 「トークンが不正です」（64 桁の小文字 16 進以外）
別に、写真から QR を検出できないとき「画像から QR コードを読み取れませんでした」。

- 適用の挙動: 接続設定とトークンは**常に保存**（疎通失敗でも巻き戻さない）。保存先は host/port が UserDefaults、トークンが Keychain。その後、疎通を 1 回確認して成功／接続不可を表示（`PairingApplyViewModel.swift:34-45`）。
- 初回セットアップでは、成功した時点で自動的にルートへ戻り、接続中オーバーレイへ進む（`AppRoot.swift:447-454`）。**設定タブからの再ペアリングでは自動で戻らず**、成功バナーを出したまま QR 画面に留まる（`qrScanOnApplied` が nil。同 `:447-449`）。
- 外部 URL（`phlox://pair?...`）経由でも同じ処理に合流し、QR 画面を開いて自動適用する（`:429-444`）。
- カメラ権限文言（Info.plist）:「Mac とのペアリング用 QR コードを読み取るためにカメラを使用します。」

### 4.3 接続中オーバーレイ（初回ペアリング直後のみ。`AppRoot.swift:456-485, 594-651`）
| 状態 | 表示 |
|---|---|
| 接続待ち | 背景色で全面を覆い、132pt の接続アニメ＋「接続中…」（`title2`）。約 1.2 秒間隔で到達性とセッション一覧を再取得し、**一覧が読めたら**閉じる。到達性が先に online になっても閉じない（オフライン画面を一瞬も見せない） |
| 失敗（約 20 秒で一覧が読めない） | 閉じずに同じ画面を失敗表示へ切替え: 赤い `wifi.exclamationmark`・見出し・本文・（あれば）等幅の詳細・「再試行」（primary）・「閉じる」（secondary） |
| 「閉じる」 | オーバーレイを閉じて一覧側のオフライン表示になる |
| 対象外 | 設定タブからの再ペアリングでは出さない（ADR 0021） |

失敗表示の文言の出どころ（`AppRoot.swift:487-506`）: 一覧がエラーのとき見出し「接続できませんでした」＋エラー本文（16 章のエラー表）。それ以外は到達不可カードと同一文言（4.4）。

### 4.4 到達不可の全状態（一覧内。到達性 `Reachability` の 4 状態は 15 章）
| 到達性 | カード見出し | 本文 | 補助 |
|---|---|---|---|
| `offlineNetwork` | オフライン | 圏外です。Wi-Fi またはモバイル通信を確認してください。 | なし |

### 5.2 loaded の構成
1. **あなたの番**: 承認待ち・質問待ち（`needsAttention`）のセッションだけを先頭に。見出しは発光するピンクの点＋「あなたの番 · N」。行は専用の強調カード（左にピンクの帯）。
2. **プロジェクト別グループ**: 残りのセッションをプロジェクト単位にまとめる。見出し（太字・大文字・字間広め）をタップで開閉（既定は展開。新しく現れたグループも展開）。グループの中身はカード（枠付き）に行を並べ、その下に「+ セッションを追加」（そのプロジェクトで新規セッションを作る）。グループ順は出現順、**プロジェクトに属さないものは末尾の「その他」**（`F/SessionList/SessionGrouping.swift`）。
3. グループが 1 つも無い（全セッションが「あなたの番」にいる）ときは、単独の「+ セッションを追加」（プロジェクト未指定）だけを出す（`SessionListView.swift:216-224`）。
4. 「あなたの番」に入ったセッションはプロジェクトグループからは外れる（重複表示しない）。
5. 並べ替え・絞り込み・検索は無い。セッションの並びはサーバ応答順。

### 5.3 行の構成要素
**通常行**（`DS/Molecules/DSSessionRow.swift`）: エージェントのブランドロゴ（38pt の角丸バッジ）／セッション名（1 行）／補助 1 行「<補助文> · <相対時刻>」（補助文が空なら状態ラベル）／右端に状態チップ（アイコン＋ラベル。色・アイコンは 15 章）。完了行は不透明度 0.82、待機（idle）行は 0.7（`:57-65`）。行間に区切り線。VoiceOver ラベルは「エージェント名、セッション名、状態、補助行」。
**あなたの番の行**（`DS/Molecules/DSAttentionRow.swift`）: エージェント名のカプセル（ブランド色の枠）／セッション名（1 行）／補助（最大 2 行）／右端に「承認待ち」または「質問待ち」チップ。タップ先は下表。相対時刻の付与規則: 補助文が既に「N分前」等を含む・「今」で終わる・「回答待ち」で始まるときは付けない。

**タップ先の分岐**（`SessionListView.swift:331-337`）: 「あなたの番」の行は、補助文が「回答待ち」で始まれば質問への回答画面、そうでなければセッション詳細へ。通常行は常にセッション詳細。**実データでは補助文はワークスペース名なので「回答待ち」で始まらず、回答画面へは遷移しない**（19・21 章）。

### 5.4 更新・取得
- 引っ張って更新（`refreshable`）。ただし内部は一覧を取得するだけで、表示の更新は次のポーリングで反映される（`PhloxCore/SessionRepository.swift:28-30`。21 章）。

## 7. 承認・質問・回答

### 7.1 承認バー（`ApprovalBarView`、本文スクロール領域の先頭）

### 7.3 質問カード（`UserQuestionCard.swift`。会話内の 1 行）
- 1 つのカードに複数の質問が入りうる。質問ごとに: 見出し（`header`、大文字の小さな補助文字）／質問文／選択肢（ラベル太字＋任意の説明）／自由入力欄（「自由入力」、1〜4 行）。

| 状態 | 見た目 |
|---|---|
| `pending` | 枠は琥珀色（35%）。選択肢・自由入力・「回答する」が操作できる |

### 7.4 質問への回答画面（ChatAnswer、`F/ChatAnswer/ChatAnswerView.swift`）
質問を 1 つだけ文字で答える専用画面。ナビバー: 標準の戻る・タイトル＝セッション名・右に「質問待ち」チップ（`questionmark.bubble.fill`）。本文: エージェントのバブル（質問文）→ 送った回答のバブル（送信中は不透明度 0.72）→ 送信失敗の赤バナー。下端に全幅の入力欄（プレースホルダ「回答を入力…」・グラデの丸い送信ボタン）。質問文は承認プロンプト、無ければ補助文「回答待ち: 「…」」から括弧内を抜く、無ければ「質問があります」（`ChatAnswerViewModel.swift:51-66`）。送信は `send`（`SendRequest`）。**送信後に画面は閉じない**。**画像添付・モデル選択・停止は無い**。到達条件が実データで満たされない可能性が高い（19・21 章）。

## 8. 入力バー・添付・モデル選択・新規セッション（下書き）

### 8.1 入力バーを出す条件（`SessionDetailView.swift:149-151`）
`isInputBarEnabled`（開始中〔starting〕以外で、かつ送信中でない）**または**（実行中かつ停止可能）。完了・エラー後も入力できる（ADR 0028）。承認待ち・質問待ち・待機・実行中でも入力できる。**開始中（starting）は出ない**。実行中でないセッションで送信している間は、入力バーごと一時的に消える（21 章）。

### 8.2 構成（`DS/Molecules/DSInputBar.swift`）
上から: [使用量行（6.7）] → [添付エラー（赤・小）] → [添付ストリップ] → [コンテキスト行] → ピル（Capsule）。
- ピルの中（左から）: ＋（写真）ボタン／テキスト欄／モデルチップ／停止・送信ボタン。
- **テキスト欄**: プレースホルダ「回答を入力…」、1〜4 行で伸び、超えるとスクロール。Return キーは改行（送信は専用ボタンのみ。`onSubmit` なし）。キーボードは本文のスクロールで閉じる（`scrollDismissesKeyboard(.interactively)`）。キーボード上の「完了」ボタンは無い。入力欄の枠色はフォーカスで変わらない（ADR 0016）。
- **コンテキスト行**: `arrow.triangle.branch`＋プロジェクト名（小・弱い文字・1 行）。ブランチ名ではなくプロジェクト名の代用表示で、押せない（ADR 0012）。プロジェクト名が無ければ非表示。
- **モデルチップ**: 「<モデル表示名> ⌄」のカプセル。選択可能なモデルが 1 件以上あるときだけ出る。押すとモデル選択シート。

### 8.3 送信／停止の出し分け規則（`DSInputBar.swift:200-208`、`SessionDetailViewModel.swift:128-130`）
| 状況 | 停止ボタン（赤丸・`stop.fill`） | 送信ボタン（アクセント丸・`arrow.up`） |
|---|---|---|
| 実行中でない | なし | 常に置く。本文が空（空白のみ）または送信中は淡色（不透明度 0.45）で無効 |
| 実行中・本文が空 | あり（単独） | なし |
| 実行中・本文あり | あり（左へ寄る） | 右から現れて併置（アニメ）。追加指示を送れる |
| 送信中 | （実行中なら）併置 | スピナー表示。ボタンスロットは保つ |
| 下書き（未作成）の最初の送信前 | なし（実行中扱いでも出さない） | 常に置く |
停止は実行中のみ有効で、停止が非対応（サーバが 409）と分かったら停止ボタンを隠す（`SessionDetailViewModel.swift:205-216`）。送信時の挙動: 本文と添付を楽観的に消し、失敗したら復元（6.6）。

### 8.4 添付（画像のみ）
| 項目 | 内容 |
|---|---|
| 追加 | 入力バーの＋（写真ピッカー・複数選択。添付が 4 枚になると＋は消える）。写真権限ダイアログは出ない（ピッカー方式） |
| 上限 | **最大 4 枚**・1 枚 4MB・合計 8MB。超えると**そのバッチ全体を弾き**、赤文字（「画像は最大4枚までです」「1枚あたり最大4MBまでです」「画像の合計サイズは最大8MBまでです」、読めない画像は「画像を読み込めませんでした」） |
| 形式 | PNG・JPEG はそのまま。それ以外（HEIC 等）は JPEG（品質 0.85）へ再エンコード |
| ストリップ | 横スクロールの 56pt サムネイル（左上に「#N」バッジ、右上に ✕）。✕ で削除 |
| 本文との連動 | 追加時、カーソル位置に `[Image #N]` を挿入。本文からそのトークンを消す（一部だけ消しても残骸ごと）と添付も外れる。✕ で消すと本文のトークンも消える（ADR 0025） |
| 送信後 | 本文に「画像」バッジが付く（6.2） |
エージェント種別による添付可否の差は UI に無い（14 章）。ファイル・音声・動画の添付は無い。音声入力は撤去済み（19 章）。

### 8.5 モデル選択シート（`ModelPickerSheet.swift`）
`.medium`/`.large`。ナビバー（インライン）タイトル「Model」・左に「閉じる」。検索欄（プロンプト「Search」）。セクション「Active」（現在の選択 1 行・チェックマーク）と「More」（その他の行）。行: モデル表示名＋エージェント種別名（小・弱い文字）。検索は表示名・種別名・モデル ID の部分一致。選ぶとシートを閉じて反映。
- **既存セッション**: そのセッションのエージェント種別のモデルだけが並ぶ。選択はサーバへ送られる。失敗しても表示は変わらず、エラーは出ない。モデル一覧が取れない・空のとき、チップとメニューの効果は無い（メニューの「モデル変更」は押せるが空のシートが開く。21 章）。
- **下書き**: Claude Code・Cursor・Codex の 3 種すべてのモデルが並ぶ。Codex はモデル一覧が空または取得失敗のとき「Codex」の 1 行だけ（種別だけ選べる）。初期選択は Claude Code の既定モデル → Cursor の既定 → 先頭。選んだ行が一覧から消えても種別は保持し、同種別の既定モデル→同種別の任意の行の順で選び直し、無ければ未選択表示（ADR 0030）。選ぶ＝作成されるエージェント種別とモデルを決める。

### 8.6 新規セッション（下書き compose、ADR 0008）
- 入口: 一覧の各プロジェクトの「+ セッションを追加」、一覧の単独追加行、空状態の「+ 新規タスクを作成」。専用の作成画面（旧 Spawn 画面）は廃止済みで、**詳細画面の未作成モード**を開く。
- 画面: ナビバータイトル＝プロジェクト名（無ければ「新規セッション」）。本文は空白（初回取得中の接続アニメも出さない）。下端に入力バー（常に有効）。入力バーにプロジェクト名ラベル・モデルチップ。ポーリングしない。
- 最初の送信で「作成（spawn）→ 準備完了待ち → メッセージ送信」を 1 操作で実行。以降は通常の詳細として動く（タイトルが作成されたセッション名に変わる）。
- 失敗時（作成拒否・準備未完・通信）: 赤バナー、本文は復元。
- 未作成の間、メニューの「名前変更」は意味を持たず、「削除」は何も起きない（21 章）。「モデル変更」は有効。

## 13. ウィジェット・Live Activity・プッシュ通知

（委譲調査の結果を、コードで裏取りした範囲で圧縮。ADR 0009・0011 と `macos/docs/specs/apns-companion-contract.md` の記述は「未確認（文書のみ）」を除きコード側の事実を採用。）

### 13.1 ウィジェット（`PhloxWidget/SessionStatusWidget.swift`）
- 種類: `StaticConfiguration`（kind `SessionStatusWidget`）、表示名「Session Status」、説明「Shows the latest Phlox session state.」。**対応サイズは 2 つだけ**: ロック画面 `accessoryRectangular`、ホーム `systemSmall`（`:56-58`）。背景は固定の濃紺（ライト/ダーク非対応）。
- 表示するのは**直近更新の 1 セッション**。データは App Group `group.com.phlox.mobile` に保存した表示用の最小項目（状態ラベル・名前・補足・更新時刻）。アプリが一覧を取得するたびに書き込み、ウィジェットを再読込する。時間経過による自動更新は無い（タイムライン 1 件・`.never`）。

| サイズ | 表示項目 |
|---|---|
| systemSmall | 状態アイコン＋状態ラベル（大文字）／セッション名（白・最大 2 行）／補足（白 72%・最大 2 行）／右下に「View ›」（飾り。リンクではない） |
| accessoryRectangular | 状態ラベル（大文字・太字・小）／セッション名（1 行）／補足（1 行）＋右端「View ›」。アイコンも色分けも無い |

- 状態ラベル（英語固定）と補足の既定文（`PhloxCore/Shared/SharedSessionWriter.swift:40-60`）: Starting（Preparing session）／Waiting＝待機・承認待ち・質問待ちの 3 状態が同じラベル（Ready／Approval required／Input required）／Running（In progress）／Finished（終了コード 0 は No Changes、それ以外は Exit N）／Error（メッセージ、無ければ Session failed）。**補足にはセッションの補助文（ワークスペース名）が優先して入る**。
- アイコンと色（small のみ）: Finished＝`checkmark.circle.fill` 緑／Error＝`exclamationmark.triangle.fill` 赤／Waiting＝`hourglass` オレンジ／その他＝`circle.dotted.circle.fill` シアン。
- 空・未接続: 「NO SESSIONS」（`rectangle.stack`）・「Open PhloxMobile」・「Session status will appear here.」。未接続とセッション 0 件は同じ表示。起動直後の空配列では上書きしない（直近の非空状態を保持。全セッション削除後も古い表示が残る。`App/AppRoot.swift:552-557`）。
- ギャラリー用のプレースホルダは固定サンプル（Finished／「Add mobile widget」／No Changes）。
- **タップは起動のみ**（`widgetURL` なし）。ウィジェット設定項目（構成の選択）は無い。

### 13.2 Live Activity（`PhloxWidget/SessionLiveActivity.swift`）
- **アプリ側は開始・更新・終了を行わない**。Mac が APNs で start/update/end を送る（push 駆動）。アプリはトークン登録（push-to-start と Activity ごとの更新トークン）と重複 Activity の即終了だけを担う（`F`ではなく `K/PhloxCore/LiveActivity/LiveActivityCoordinator.swift`、ADR 0011）。
- ContentState: `sessionId`／`sessionName`／`status`／`summary`（すべて文字列）。`summary` は **Mac が作る文言**（Mac の表示言語。例: 作業が完了しました／承認待ち／質問があります／エラーで止まりました／応答がありません／セッションが終了しました。英語は Work finished／Awaiting approval 等。終了のみ「 · exit <コード>」付き）。iOS 側に固定文言は無い。
- 状態コード `status` と記号（`:48-58`）: `session_completed`＝`checkmark.circle.fill`／`approval_pending`＝`exclamationmark.circle.fill`／`question_pending`＝`questionmark.circle.fill`／`session_error`＝`xmark.octagon.fill`／`session_stalled`＝`hourglass.circle.fill`／`session_exited`＝`stop.circle.fill`／未知＝`circle.dotted.circle.fill`。色分けは無い。
- ロック画面: 左に記号（`title2`）、右にセッション名（`headline`・1 行）と `summary`（`caption`・補助色・最大 2 行）。濃紺背景・白文字。
- Dynamic Island: **expanded** — leading＝記号／center＝セッション名（1 行）／bottom＝`summary`（最大 2 行）／trailing は定義なし。**compact** — leading＝記号、trailing＝短縮ラベル（英語固定）`Done`（完了）／`End`（終了）／`Error`／それ以外（承認待ち・質問待ち・応答なしを含む）は一律 `Wait`。**minimal** — 記号。
- 期限（Mac 側の `stale-date`）: 承認・質問・エラー・応答なしは +15 分、完了・終了は +60 秒（`macos/.../APNsNotificationBridge.swift`）。**期限切れ（stale）の見た目の分岐は UI に無い**。
- **タップは起動のみ**（`widgetURL` なし）。

1. **ADR 0005**: Usage 取得失敗時に「リトライ UI は出さない」と決めたが、コードは失敗画面に「再試行」を出す（`UsageView.swift:74-94`）。
2. **ADR 0008**: 送信失敗時に「入力が消えて打ち直し」とあるが、コードは本文と添付を復元する（`SessionDetailViewModel.swift:776-786`）。
3. **ADR 0021**: 20 秒で閉じてオフラインへ落ちると書くが、コードは同じオーバーレイに原因＋再試行/閉じるを出す（`AppRoot.swift:476-480, 622-650`）。
4. **ADR 0003**: Tailscale 等以外へは認証トークンを付与しないとあるが、到達性チェックとペアリング疎通は信頼判定なしでトークンを付ける（`PhloxReachability/HostHealthChecker.swift`、`App/AppEnvironment.swift`）。
5. **ADR 0013／0020**: 構造（外側 ZStack/内側 VStack）、バッジ位置（テキスト下）が現コードと異なる（本文は VStack 単層、バッジはバブルの外・下・右寄せ）。
6. **ADR 0026／README**: 見出し書式「ツール実行 ×N」は ADR 0041 で原文見出しに置換済み（0026 本文は未更新）。コードコメント（`SessionDetailToolCallGrouping.swift:6-7`）も古い。
7. **ADR 0016 など**: 送信/停止の排他は 0042 が置換済みだが 0016 に参照が無い。`DSInputBarActionState` は enum ではなく struct。
8. **ADR 0040 とコードコメント**: 0040 は「遅延描画は効かなくなった」とするが、`TerminalScreenView.swift:55-57` は行ごとの遅延描画のまま（`LazyVStack`）。`TerminalScreenMetrics.swift` の冒頭コメントは「折り返す」と書くが、実際は折り返さず横スクロール。
9. **ADR 0009／契約**: ADR 0009 は拡張の deployment target 17.0、実際は 18.0（`project.yml`）。`apns-companion-contract.md` の `status` は 2 値だが実際は 6 値、`stale-date` の対象も 4 種＋2 種に拡張、`environment` 判定はビルド構成ではなく `embedded.mobileprovision`、フォアグラウンド受信時のアプリ内更新は無い（3 秒ポーリング）。

### 21.2 UI として気になる点（再設計の機会、または確認すべき挙動）
1. **承認バーは詳細を開いた時の 1 回しか取得しない**: 開いたままセッションが承認待ちになってもバーが出ない可能性（コード上は再取得なし。実機未確認）。
2. **質問カードの送信失敗は無表示**（成功・失敗の区別が画面に出ない）。
3. **承認の結果文言に英語識別子**: 「応答を送信しました（accept）」。
4. **質問待ち／承認待ちの判定が補助文の文字列一致**: `subtitle.hasPrefix("回答待ち")`（一覧の行の種類・タップ先・チップ・回答画面の入口）。実データでは補助文＝ワークスペースなので常に「承認」側。質問待ちは状態の値（`awaitingUserQuestion`）で見分けられるが、タップ先は詳細のみ。
5. **一覧の相対時刻は実質「今」固定**（取得のたびに更新時刻を現在時刻で作り直す。`SessionDTO.toDomain(now:)`）。一覧の完了経過時間等を出す設計はデータが無い。
6. **削除確認の子孫件数は常に 0**。ドラフト画面の「削除」は何も起きない。ドラフトの「名前変更」は存在しないセッションへ要求を送る（失敗は無表示）。
7. **「パスコードを使用」はボタンとして独立した機能ではなく**、認証を再実行するだけ。
8. **一覧の「引っ張って更新」は即時反映しない**（次のポーリングで反映）。
9. **空状態の案内が存在しない UI を指す**: 「+ をタップして…」（一覧に「+」ボタンは無く、CTA は「+ 新規タスクを作成」）。
10. **詳細の本文が空**（メッセージも出力も空）のとき空白で案内が無い。
11. **実行中でないセッションで送信中は入力バーごと消える**（`isInputBarEnabled` が送信中に false。`SessionDetailView.swift:149`）。進捗スピナーは実行中のときだけ見える。実機での見え方は未確認。
12. **Usage タブ**: 更新のたびにスピナーへ置き換わる（表示済みの一覧が消える）。システム大タイトルのため他タブと作りが違う。使用率が高くても色は変わらない。
13. **モデル変更**: 一覧が取れないセッションで、メニューの「モデル変更」は空のシートを開く。失敗は無表示。
14. **通知の許可は起動直後に OS ダイアログが突然出る**（事前の説明画面なし）。通知トグルは登録判定にのみ使われ、オフにしても受信は止まらない。
15. **ウィジェット**: 状態ラベル「Waiting」が待機・承認待ち・質問待ちを区別できない。全セッション削除後も古い表示が残る。ウィジェットの文言は英語固定でアプリ本体の日本語と不統一。
16. **Live Activity**: compact の「Wait」は承認待ち・質問待ち・応答なしを区別できない。タップで詳細へ行けない。
17. **`DSChatBubble` の「/approvals」固定強調**: 用途不明の特殊処理（推測せず記録）。
18. **画面外の読み込み**: 通知タップ時に詳細が既にスタックにあっても別の詳細を重ねて push する。
19. **サブエージェントの状態**（`running`/`completed`）は取得するが UI に出ない。
