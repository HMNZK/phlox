# Claude Design 用プロンプト集 — 下部パネル（ターミナル）・ファイル操作・Git タブ

今の Phlox の見た目に、3 つの新しい要素を足すためのプロンプト。要件の正本は `macos/docs/specs/bottom-panel-shell-files-git.md`。
送付時は、添付するもの（下の 1.）を 1 つのフォルダに写してまとめた（送付後に削除。元はすべて `macos/docs/specs/` にある）。
「既定のシェル」の設定は既存の設定の行で組めるので、デザインは依頼しない。

## 使い方

1. Claude Design で新しいプロジェクトを作り、次を添付する。
   - 要件書 `macos/docs/specs/bottom-panel-shell-files-git.md`
   - 今の見た目の見本: `11 Project Tabs.dc.html`・`12 Header and Usage Bar.dc.html`・`2 File Tree.dc.html`・`6 Unsaved Changes Dialog.dc.html`・`PhloxTabsWindow.dc.html`・`support.js`（見本を描画するのに要る）。いずれも `macos/docs/specs/ClaudeDesign/` にある。見本の一部はアクセントが藍やコーラルの旧配色。色は「0. 共通プロンプト」が優先
   - あれば今の Phlox のスクリーンショット（右サイドバーを開いた状態・ターミナルの子タブ・「変更」の子タブ）
2. 「0. 共通プロンプト」を送る。
3. 「1. 配置の確認」で置き場所を確定させてから、2 → 3 → 4 の順に 1 つずつ送る。
4. 最後に「5. 横断レビュー」を送る。
5. できたモックは `macos/docs/specs/ClaudeDesign/13 Bottom Panel Files Git/` にフォルダごと保存した（2026-10-14、確定版。実装時に `DesignSnapshotRenderTests` の画像と見比べる見本になる）。

各プロンプトの「参照」は要件書の番号（BP = 下部パネル、FO = ファイル操作、GT = Git タブ、NF = 共通、§ = 章）。

## 0. 共通プロンプト（最初に 1 回だけ送る）

```
あなたは macOS ネイティブアプリの UI デザイナーです。Phlox という macOS デスクトップアプリに、新しい要素を 3 つ足します。
添付の要件書が正本です。添付の見本（今の Phlox の画面）の見た目と操作感に溶け込む、高忠実度のモックを作ってください。
既存の画面を作り直すのではなく、既存の画面に要素を足す前提です。

## Phlox とは
複数の AI コーディングエージェント（Claude Code / Codex / Cursor。アプリ内では「ハーネス」と呼ぶ）を 1 つのウィンドウで同時に走らせ、
監視・指示・承認する開発者向けアプリ。利用者は数〜十数のセッションを並行させる上級開発者。

## 足すもの（要件書 §0）
1. 下部パネル: 中央の下から引き上げて開く欄。中身はそのプロジェクトのターミナル（プロジェクトごとに 1 つ）。
2. ファイル操作: 右サイドバーのファイルツリーで、新規ファイル・新規フォルダ・名前の変更・ゴミ箱に入れる。
3. Git タブ: 右サイドバーの上に「ファイル / Git」の切り替えを置き、Git では作業中の変更ファイルの一覧と小さな差分を出す。
   大きく見る・コミットするのは、今ある「変更」の子タブで行う（Git タブにはコミット欄を置かない）。

## 今のメインウィンドウの構成（ここに足す）
- 上段: プロジェクトのタブ列（高さ 34pt）。下段: そのプロジェクトの子タブ列（高さ 36pt。会話・新規チャット・ターミナル・変更・ファイル・ブラウザ・シミュレーター。右端に「＋」）。その下が子タブの中身（左右 2 区画に分割できる）。
- 左サイドバー（幅 220〜360pt）: プロジェクトとセッションの一覧（行 28pt）。
- 右サイドバー（幅 260〜340pt、既定 280pt）: 今はファイルツリーだけで、上部に切り替えは無い。見出しにルートのパスとブランチ名と更新ボタン。
- 画面の最下端: 使用量のバー（高さ 24pt、横幅いっぱい）。押しても何も開かない。このバーはそのまま残す。
- 「変更」の子タブ: 変更ファイルの一覧と差分（追加 / 削除の行の色）と、コミット欄。

## 使うデザインの値（既定のダークテーマ「Phlox」。コードの正本は Packages/DesignSystem）
- 基調はモノクロのグレー階調。アクセントも色を持たず、主文字色と同じ白黒（ADR 0189）。主要な操作・選択・フォーカス・リンクにだけ使う。
- 背景: ウィンドウ #1E1E20 / サイドバー #262629 / ツールバー #2A2A2D / パネル #242427 / カード #27272A /
  コード #2B2B2F / 入力欄 #1A1A1C / ポップオーバー #2F2F33 / タブ列 #232326 / ターミナル #141416
- 文字: 主 #F2F2F4 / 副 #ABABB1 / 補助 #8E8E94。区切り線は主文字色の 10%、枠線は 14%。
- アクセント: ダークでは主ボタンの面 #F2F2F4 に文字 #1E1E20、アクセントの文字とフォーカス枠 #F2F2F4。ライトでは面 #1D1D1F に文字 #FFFFFF、文字と枠 #1D1D1F。フォーカス枠は不透明。選択の塗りは主文字色の半透明（ダーク 24%・ライト 17%）。
- 注意の色（印 / 文字）: 承認待ち #F0AE4A / #F4BD68、質問 #5D98F0 / #8DB6F7、エラー #EE5A5F / #FF8A8D、無応答 #A876EB / #C4A2F4。
- 差分: 追加 #6FD08C、削除 #FF8A8D。
- 文字サイズ: 本文 13pt、補助 12pt、メタ 11pt、等幅 11pt。システムフォント（SF Pro / SF Mono）。
- 間隔は 8pt グリッド（2 / 4 / 8 / 12 / 16 / 24 / 32）。角丸: タグ 4、ボタン・行 6、カード 8、パネル 10、入力欄・シート 12。一覧の行 28pt。アイコンは SF Symbols。
- 分割線は見た目 1pt・当たり 8pt、ホバーでアクセントの 3pt。
- ライトテーマもある（ウィンドウ #FFFFFF、サイドバー #F2F2F4、タブ列 #ECECEF、差分 追加 #1F7A3A / 削除 #B4232A。ターミナルはライトでも暗い面 #1B1B1D）。主要な画面はダークで作り、最後にライトで 1 枚確認する。

## デザイン原則
- macOS Human Interface Guidelines に沿う。静かな chrome（装飾を足さない）。注意が必要なものだけが目立つ。
- キーボードだけで全操作できる。VoiceOver で各要素の役割と状態が読める。
- 状態は色だけに頼らず、文言でも区別できること（図形の印・未読の丸・ハーネスの略号と色は使わない）。WCAG 2.2 AA（文字 4.5:1・部品とフォーカス枠 3:1）を満たすこと。
- UI 文言は日本語。英語に切り替えても崩れない幅を確保する。

## 描かないもの（要件書 §7）
- 下部パネルにターミナル以外を出すこと、パネル内のターミナルのタブ（複数ターミナル）。
- ファイルのドラッグ＆ドロップ・複数選択・一括操作・取り消し。
- Git タブでのステージ・コミット欄・破棄・ブランチ切り替え・push。
- 共通ターミナル（廃止済み。下部パネルはプロジェクトごと）。

## 各画面の出力ルール
- (1) 通常状態 (2) 要件書にある状態の描き分け（空・読み込み中・エラーなど）(3) 操作の途中（ホバー・フォーカス・押下中・無効・右クリックメニュー・確認ダイアログ）。ホバー・押下中・無効は今のボタンの見た目に合わせ、新しい表現を足さない。
- モックの横に「要件対応表」を付ける: 要件書の番号 → モック上の置き場所。置けなかった要件は明記する。
- サンプルデータは現実的に: プロジェクト `Phlox-oss`（`~/Projects/Phlox-oss`、ブランチ `feature/bottom-panel`）・`ios-companion`。ファイル名は Swift のパッケージ構成（`macos/Packages/DashboardFeature/Sources/...`）、シェルは `zsh`。

まずは了解の返事と、要件書を読んで気づいた「UI 上の難所」を 5 つ以内で挙げてください。モックはまだ作らないでください。
```

## 1. 配置の確認（全体の置き場所）

```
3 つの新しい要素の置き場所を、メインウィンドウ全体のモックで示してください。参照: BP-1・BP-2・GT-1、§8。

描くもの（ウィンドウ幅 1600pt・高さ 1000pt・ダーク）:
- 中央: 子タブ「会話」を表示し、その下に下部パネル（ターミナル。高さ 280pt）を開いた状態。パネルは中央の列の中だけに出て、左右のサイドバーは上から下まで通しの高さのまま。最下端の使用量のバーはパネルの下に残る。
- 右サイドバー: 上端に「ファイル / Git」の切り替え。「Git」を選んでいる。
- 下部パネルの開閉ボタン: 要件書 §8 の既定案（子タブ列の右端のアイコン）で描き、別案を 1 つ並べて比べる。使用量のバーは押せないまま（ボタンにしない）。

描き分け:
- 下部パネルを閉じた状態（開閉ボタンの「閉」の見た目）。
- 右サイドバーが重ね表示になる幅（中央が 480pt を割るとき。左 260pt・右 280pt ならおよそ 1000pt）で、下部パネルと重ね表示の右サイドバーが同時に出ている状態。
- グリッド表示（タイル 4 枚）で下部パネルを開いた状態。パネルは選択中のタイルのプロジェクトのターミナル（BP-12）。

論点として提案してほしいこと:
- 子タブを左右に分割しているとき、パネルは 2 区画の下に通しで出す前提で破綻しないか。
- 開閉ボタンの置き場所の推奨とその理由。
```

## 2. 下部パネル（ターミナル）

```
下部パネルを設計してください。参照: BP-1〜BP-12。

含めるもの:
- 上端の境目（ドラッグで高さを変える。見た目 1pt・当たり 8pt・ホバーでアクセント 3pt。カーソルは上下の矢印）。
- 見出し（高さは子タブ列に合わせて 36pt を目安）: 「ターミナル」・シェル名（`zsh`）・作業フォルダ（`~/Projects/Phlox-oss`。先頭を省略）・右端に「シェルを再起動」「パネルを閉じる」（アイコンボタン。ツールチップに名前とキー ⌃`）。
- 本体: ターミナル（背景 #141416、SF Mono 11pt）。サンプルは `git status` と `swift build` の出力。

描き分け:
- 通常（フォーカスあり / なし。フォーカスの示し方は今のターミナルの子タブに合わせる）。
- 初めて開いた直後（シェルの起動中）。
- シェルが終了した状態（「シェルは終了しました（終了コード 0）」と「再起動」）。
- 設定のシェルが見つからず、システムの既定で起動した状態（ターミナルの最初の行の注意書き。要件書 BS-4）。
- 最小の高さ（120pt）と最大の高さ（中央の 70%）。
- プロジェクトが選ばれていないとき、開閉ボタンが無効の見た目（BP-11）。
```

## 3. ファイルツリーの作成・名前変更・削除

```
右サイドバーのファイルツリーに、ファイル操作を足してください。参照: FO-1〜FO-11。添付の `2 File Tree.dc.html` の今のツリーに足す（配色は 0 の値に置き換える）。

含めるもの:
- 右クリックメニュー（ファイル行・フォルダ行・空白部分の 3 種）: 既存の「右に分割して開く」「Finder で表示」「パスをコピー」に、「新規ファイル」「新規フォルダ」「名前を変更」「ゴミ箱に入れる」を足した並びと区切り。キー（Return・⌘⌫）を右に表示。
- ツリー見出しの「＋」（新規ファイル / 新規フォルダを選ぶ小さなメニュー）。
- 新規作成の入力行: 対象フォルダが展開され、その中の正しい並び位置に、アイコン付きの名前の入力欄がその場に出る（行 28pt に収める）。
- 名前の変更: 行の名前がその場で入力欄になり、拡張子より前が選択されている。
- 名前の誤りの表示（入力欄の下に理由）: 「同じ名前のファイルがあります」「名前に / は使えません」「名前を入力してください」。
- ゴミ箱に入れる確認ダイアログ（添付 `6 Unsaved Changes Dialog.dc.html` と同じ形）の 3 種:
  (a) 開いていないファイル（「notes.md をゴミ箱に入れますか？」）
  (b) 開いているファイルで未保存の変更がある（「開いているタブを閉じます。未保存の変更は失われます」）
  (c) フォルダ（「docs と中の 12 項目をゴミ箱に入れますか？」）
- 操作できない行（ルートそのもの・ルート外を指す symlink・.git の中）で「名前を変更」「ゴミ箱に入れる」が無効のメニュー。
- 失敗の一時表示（ツリーの上。例「名前を変更できませんでした: 権限がありません」）。
- 操作の後、新しい / 名前を変えた行が選択されて見えている状態。
```

## 4. 右サイドバーの Git タブ

```
右サイドバーの「Git」タブを設計してください。参照: GT-1〜GT-9。幅 280pt（最小 260pt・最大 340pt）で成り立つこと。

含めるもの:
- 上端の「ファイル / Git」の切り替え（キーはツールチップに: ファイル ⌃⌘B、Git ⇧⌃⌘G）。
- 見出し: ブランチ名（`feature/bottom-panel`。detached HEAD は短縮コミット）・変更の件数（「7 件の変更」）・更新ボタン・「コミット…」ボタン（押すと「変更」の子タブのコミット欄が開く。Git タブ内にコミット欄は置かない）。
- 変更ファイルの一覧（行 28pt）: 種類（追加・変更・削除・名前変更・未追跡。文字の短いラベルで区別し、色は補助）・ファイル名・フォルダ（薄く、先頭を省略）・+12 / −3 の行数。
- 選んだ行の差分（一覧の下。境目をドラッグして比率を変えられる）: 280pt 幅で読める形（行番号は省く or 細く・長い行は折り返し）。長い差分は先頭だけと「続きを『変更』タブで見る」。
- 行の右クリックメニュー: 「『変更』タブで開く」「ファイルを開く」「Finder で表示」「パスをコピー」。ダブルクリック・Return で「変更」タブが開くことが分かる手がかり。

描き分け:
- 変更なし（「変更はありません」）/ Git 管理外（「Git 管理外のフォルダです」）/ 読み込み中 / git の失敗（理由と「再試行」）。
- バイナリファイルを選んだとき（「バイナリファイル」）、未追跡のテキストを選んだとき（全文を追加行として）。
- エージェントのターンが終わって一覧が自動で更新された直後（新しく出た行の控えめな示し方。点滅や未読の丸は使わない）。
- 最小幅 260pt と最大幅 340pt。重ね表示（浮いたカード）になったとき。
```

## 5. 横断レビュー（最後に送る）

```
ここまでのモック（1〜4）を横断して点検してください。

1. 要件書の BP・FO・GT・NF の全番号について、モック上の置き場所を表にする。置けていない番号を挙げる。
2. キーボードだけで、次の操作が最後までできるか手順を書く: 下部パネルを開いて閉じる（フォーカスが元に戻る）／ツリーで新規ファイルを作って名前を変えてゴミ箱に入れる／Git タブで行を選び「変更」タブで開く。
3. VoiceOver で読む文言（役割と状態）を、パネルの見出し・ツリーの入力行・確認ダイアログ・Git の行について書く。
4. 文字と部品のコントラストが WCAG 2.2 AA を満たすか、差分の色・種類のラベル・無効のメニュー項目について数値で確認する。
5. 英語の文言（例 "Move to Trash", "Show Bottom Panel", "No changes"）に替えたとき、切れる・はみ出す箇所を挙げる。
6. ライトテーマで、下部パネルと Git タブを 1 枚ずつ描く。
直すべき点があればモックを直し、直した点を一覧にしてください。
```
