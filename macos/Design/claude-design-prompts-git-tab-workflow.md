# Claude Design 用プロンプト集 — Git タブへの作業の集約（GW）

右サイドバーの Git タブに、コミット欄・ステージ・コミット／ブランチ／リモートブランチ／スタッシュ／グラフの一覧を集め、「変更」の子タブを差分の表示だけにする。要件の正本は `macos/docs/specs/git-tab-workflow-and-worktree-start.md` の §3（GW）。
同じ要件書の FX・BD・WS は見本なしで実装するので、デザインは依頼しない。

## 使い方

1. Claude Design で新しいプロジェクトを作り、次を 1 つのフォルダにまとめて添付する（送付後にフォルダは削除。元はすべて `macos/docs/specs/` 以下にある）。
   - 要件書 `git-tab-workflow-and-worktree-start.md`
   - 今の Git タブ・ウィンドウの見本: `ClaudeDesign/13 Bottom Panel Files Git/` の `GitTab.dc.html`・`GT_GitTabDesign.dc.html`・`PhloxWindow.dc.html`・`TrashAlert.dc.html`・`support.js`（見本の描画に要る）
   - 今の Phlox のスクリーンショット（「変更」タブと Git タブを並べた状態。ユーザーが 2026-10-15 に共有したもの）
2. 「0. 共通プロンプト」を送る。
3. 1 → 2 → 3 の順に 1 つずつ送る。
4. 最後に「4. 横断レビュー」を送る。
5. できたモックは `macos/docs/specs/ClaudeDesign/14 Git Tab Workflow/` にフォルダごと保存する（実装時に `DesignSnapshotRenderTests` の画像と見比べる見本になる）。

各プロンプトの「参照」は要件書の番号（GW = Git タブ、NF = 共通）。

## 0. 共通プロンプト（最初に 1 回だけ送る）

```
あなたは macOS ネイティブアプリの UI デザイナーです。Phlox という macOS デスクトップアプリの、右サイドバーの「Git」タブを作り直します。
添付の要件書（§3 GW）が正本です。添付の見本（前回あなたが作った Git タブ・ウィンドウ）とスクリーンショット（今の実装）の見た目と操作感に溶け込む、高忠実度のモックを作ってください。

## Phlox とは
複数の AI コーディングエージェント（Claude Code / Codex / Cursor）を 1 つのウィンドウで同時に走らせ、監視・指示・承認する開発者向けアプリ。
エージェントがプロジェクトのフォルダのファイルを書き換え、利用者は Git タブでその変更を確かめてコミットする。利用者は上級開発者。

## 今の形と、変えること
- 今: 右サイドバー（幅 280pt、最小 260pt・最大 340pt）の上に「ファイル / Git」の切り替え。Git タブは、見出し（ブランチ名・件数・「コミット…」・更新）、変更ファイルの一覧、その下に選んだファイルの小さな差分。
  中央の「変更」の子タブは、左に変更ファイルの一覧（コミットするファイルを選ぶチェックボックス付き）、右に差分／内容、下部にコミットメッセージ・「コミット」「プッシュ」「PR を作成」。
- 変えること（要件書 GW-1〜15）:
  1. コミットメッセージ・「コミット」「プッシュ」「PR を作成」を Git タブの最上部へ移す。
  2. その下に、折りたためる区画: 変更（ステージ済み／変更 に分ける）→ コミット → ブランチ → リモートブランチ → スタッシュ → グラフ。
  3. 変更の行の右に、ホバーで「＋」（ステージ）／「−」（ステージを外す）。コミットはステージ済みだけ。チェックボックスは廃止。
  4. Git タブの中の差分表示は廃止。行を押すと、常に中央の「変更」タブにそのファイルの差分を出す。
  5. 「変更」タブは左の一覧とコミット欄を廃止し、1 ファイルの差分／内容だけ。
  6. 一覧は見るだけでなく、右クリックなどで操作できる（切り替え・作成・名前変更・削除・取得・スタッシュの適用など）。

## 使うデザインの値（前回の依頼と同じ。コードの正本は Packages/DesignSystem）
- 基調はモノクロのグレー階調。アクセントも色を持たず、主文字色と同じ白黒。主要な操作・選択・リンクにだけ使う。
- 背景（ダーク）: ウィンドウ #1E1E20 / サイドバー #262629 / ツールバー #2A2A2D / パネル #242427 / カード #27272A / コード #2B2B2F / 入力欄 #1A1A1C / ポップオーバー #2F2F33 / タブ列 #232326
- 文字: 主 #F2F2F4 / 副 #ABABB1 / 補助 #8E8E94。区切り線は主文字色の 10%、枠線は 14%。
- 主ボタン: 面 #F2F2F4 に文字 #1E1E20。選択の塗りは主文字色の 24%（ライト 17%）。
- 差分: 追加 #6FD08C、削除 #FF8A8D。エラーの文字 #FF8A8D。
- 文字サイズ: 本文 13pt、補助 12pt、メタ 11pt、等幅 11pt（SF Pro / SF Mono）。間隔は 8pt グリッド。角丸: タグ 4、ボタン・行 6、カード 8。一覧の行 28pt。アイコンは SF Symbols。
- 一覧に入力先があっても、一覧の外側に枠は描かない（要件 FX。選択行の塗りだけで示す）。
- ライトテーマもある（ウィンドウ #FFFFFF、サイドバー #F2F2F4、差分 追加 #1F7A3A / 削除 #B4232A）。主要な画面はダークで作り、最後にライトで 1 枚確認する。

## デザイン原則
- macOS Human Interface Guidelines に沿う。静かな chrome。280pt の幅で、文字が切れず、操作が詰まりすぎないこと。
- キーボードだけで全操作できる。VoiceOver で役割と状態が読める。状態は色だけに頼らない。WCAG 2.2 AA。
- 文言は日本語。英語（Stage, Unstage, Commit, Push, Create PR, Fetch, Stash など）に替えても崩れない幅にする。

## 描かないもの（要件書 §6）
マージ・リベース・チェリーピック・リセット・プル・強制プッシュ・衝突の解消画面、リモートブランチの削除、タグの作成と削除、行の一部（ハンク）単位のステージ。

## 各画面の出力ルール
- (1) 通常状態 (2) 要件書にある状態の描き分け (3) 操作の途中（ホバー・押下中・無効・右クリックメニュー・確認ダイアログ）。ホバー・押下中・無効は今のボタンの見た目に合わせ、新しい表現を足さない。
- モックの横に「要件対応表」（要件書の番号 → モック上の置き場所）。置けなかった要件は明記する。
- サンプルデータは現実的に: プロジェクト `Phlox-oss`、ブランチ `feature/git-tab-workflow`、リモート `origin`、ファイルは `macos/Packages/DashboardFeature/Sources/...` など。

まずは了解の返事と、要件書を読んで気づいた「UI 上の難所」を 5 つ以内で挙げてください。モックはまだ作らないでください。
```

## 1. Git タブの全体（上部のコミット欄と区画の並び）

```
Git タブの全体を設計してください。参照: GW-1〜GW-6、GW-14。幅 280pt で描き、最小 260pt と最大 340pt を 1 枚ずつ並べる。

含めるもの:
- 最上部: ブランチ名（`feature/git-tab-workflow`。detached HEAD は短縮コミット）・更新ボタン・コミットメッセージの欄（複数行に伸びる）・「コミット」（主ボタン）・「プッシュ」・「PR を作成」。押せないときの理由の 1 行（例「ステージされた変更がありません」「メッセージを入力してください」）と、実行中の表示。
- 折りたためる区画の見出し（開閉の矢印・名前・件数・その区画の操作ボタン）が縦に並ぶ: 変更 / コミット / ブランチ / リモートブランチ / スタッシュ / グラフ。既定は「変更」だけ開く。
- 「変更」区画: 「ステージ済み」と「変更」の 2 つの小見出し（件数と「すべてステージ」「すべて外す」）。行（28pt）は、種類の 1 文字（M・A・D・R・U。色は補助）・ファイル名・フォルダ（薄く）・+12 −3。ホバーで行の右に「＋」または「−」（行数の表示と重ならない置き方を提案）。押した行は選択の塗り。
- 中央の「変更」の子タブ（ウィンドウの一部として横に描く）: 一覧が無く、選んだ 1 ファイルの差分／内容の切り替え・「ファイルタブで編集」・差分の本体だけ。何も選ばれていないときの「Git タブで変更を選んでください」。

描き分け:
- ステージ済みが 0 件（「コミット」が押せない）／変更が 0 件（「変更はありません」）／Git 管理外（「Git 管理外のフォルダです」）／読み込み中／git の失敗（理由と「再試行」を上部に）。
- プッシュ中・PR 作成中、PR を作った後（PR へのリンク）。
- 全区画を開いて縦に長くなったとき（Git タブ全体がスクロールし、上部のコミット欄をどう扱うか: 固定かスクロールで流すか、推奨を理由付きで）。
```

## 2. コミット・ブランチ・リモートブランチ・スタッシュ・グラフ

```
「変更」以外の区画を設計してください。参照: GW-7〜GW-13。幅 280pt。

含めるもの:
- コミット: 行は要約・作者・相対時刻（「3 時間前」）・短縮 ID。行を開くと、そのコミットで変わったファイルが字下げで並ぶ（押すと「変更」タブにそのコミットでの差分）。末尾の「さらに読み込む」。右クリック: 「ID をコピー」「ここからブランチを作成」。
- ブランチ: 今のブランチに印（色だけに頼らない）、最近使った順。見出しの「＋」（今の位置から新しいブランチ。名前の入力をその場で）。右クリック: 「切り替え」「ここからブランチを作成」「名前の変更」「削除」。ダブルクリックで切り替え。
- リモートブランチ: リモート（`origin`）ごとにまとめる。見出しに「取得」。右クリック: 「チェックアウト」「ここからブランチを作成」。
- スタッシュ: メッセージ・相対時刻。見出しの「＋」（メッセージは任意の入力）。行を開くとファイルが並ぶ。右クリック: 「適用」「取り出す」「削除」。
- グラフ: 全ブランチのコミットの線（3〜4 本の線が分岐・合流する現実的な例）。行の左に線、要約の前にブランチ名・タグの札（`main`、`origin/main`、`v1.10.0`）。280pt で読める線の幅と札の省略のしかたを提案する。

描き分け:
- 確認ダイアログ（今の確認の形に合わせる）: ブランチの削除（マージ済み）／マージされていないブランチの削除（その旨を書き、承認で強制削除）／スタッシュの削除／実行中のエージェントがいるプロジェクトでの切り替え・スタッシュ（「このフォルダで動いているセッションがあります。ファイルが書き換わります」）。
- 切り替えに失敗したとき（git の理由を上部に出す。例「error: Your local changes to the following files would be overwritten by checkout」）。
- 各区画の空状態（コミットなし・スタッシュなし・リモートなし）と、取得中。
```

## 3. キーボードと VoiceOver

```
Git タブをキーボードだけで操作する手順と、VoiceOver の読み上げを設計し、必要ならモックを直してください。参照: NF-4。

- 区画の間・行の間の移動、区画の開閉、行のステージ（「＋」のキー）、行を「変更」タブで開く、右クリックメニューを開く、コミット欄へ移る、の各キーを決め、ツールチップか見出しに示す。
- 行・区画見出し・ホバーのボタン（「＋」「−」）・グラフの行の VoiceOver の文言（役割と状態。例「AppSettings.swift、変更、ステージされていません、追加 18 行」）。
```

## 4. 横断レビュー（最後に送る）

```
ここまでのモック（1〜3）を横断して点検してください。

1. 要件書の GW-1〜15 の全番号について、モック上の置き場所を表にする。置けていない番号を挙げる。
2. キーボードだけで、次の操作が最後までできるか手順を書く: ファイルを 2 つステージ → メッセージを書いてコミット → プッシュ ／ ブランチを作って切り替え ／ 変更をスタッシュして取り出す。
3. 文字と部品のコントラストが WCAG 2.2 AA を満たすか、種類の文字・ホバーのボタン・グラフの線・札について数値で確認する。
4. 英語の文言に替えたとき、280pt と 260pt で切れる・はみ出す箇所を挙げる。
5. ライトテーマで Git タブを 1 枚描く。
直すべき点があればモックを直し、直した点を一覧にしてください。
```
