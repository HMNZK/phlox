# Claude Design 用プロンプト集 — 共通の新規チャット開始画面

今の Phlox の見た目のまま、セッションの始め方を「共通の新規チャット画面」1 つにまとめるためのプロンプト。
要件の正本は `macos/docs/specs/unified-new-chat-start.md`、設計は `macos/docs/specs/unified-new-chat-start-design.md`。

## 使い方

1. Claude Design で新しいプロジェクトを作り、次を添付する。
   - 要件書 `macos/docs/specs/unified-new-chat-start.md`（必須。正本）
   - 参考画像 `macos/docs/specs/ClaudeDesign/new-chat-start-reference.png`（Claude アプリの開始画面。配置の手本）
   - 今の Phlox のデザイン原本 `design_handoff_phlox_ui/designs/` から `12 Design System.dc.html`・`05 Reply Area.dc.html`・`03 Sidebar.dc.html`・`08 Start and New Session.dc.html`（これらはコーラルのアクセント・略号・状態の図形を含む旧版。色と印は「0. 共通プロンプト」と要件書が優先）
   - あれば今の Phlox のスクリーンショット（起動カードの画面・チャットの入力欄・サイドバー）
2. 「0. 共通プロンプト」を送る。
3. 「1」から順に 1 つずつ送る。
4. 最後に「7. 横断レビュー」を送る。
   - 0・1 を旧版で送った場合（2026-10-11 時点）: 要件書を新しい版に差し替えて添付し直し、「8. 修正依頼」を送ってモック 1 を直してから、2 → 6 の順に送る。0・1 は送り直さない（8 が差分を含む）。
   - 6 まで送った後: 9（未送信なら）→ 10 → 7（横断レビュー）→ 11 → 12 → もう一度 7 の順に送る。7 は修正をすべて入れた後の状態を点検させるため最後に回す。
   - 11・12 のモックを見た後: 要件書 2 つ（`unified-new-chat-start.md`・`project-tabs.md`）を最新の版に差し替えて「13」を送り、13 の結果を見た後に「14」を送ってから、もう一度 7 を送る。
5. できたモックは `macos/docs/specs/ClaudeDesign/` に保存する（2026-10-12 に `10 New Chat Start`・`11 Project Tabs`・`12 Header and Usage Bar` と部品 `Phlox*.dc.html`・`HarnessLogo.dc.html` を保存済み。実装時に `DesignSnapshotRenderTests` の画像と見比べる見本になる）。

各プロンプトの「参照」は要件書の番号（FR = 機能要件、D・E = 決定事項、§ = 章）。

## 0. 共通プロンプト（最初に 1 回だけ送る）

```
あなたは macOS ネイティブアプリの UI デザイナーです。Phlox という macOS デスクトップアプリの「セッションの始め方」を作り直します。
添付の要件書が正本です。添付の参考画像（Claude アプリの開始画面）の配置を手本にしつつ、今の Phlox の見た目と操作感に溶け込む高忠実度のモックを作ってください。

## Phlox とは
複数の AI コーディングエージェント（Claude Code / Codex / Cursor。アプリ内では「ハーネス」と呼ぶ）を 1 つのウィンドウで同時に走らせ、
監視・指示・承認する開発者向けアプリ。利用者は数〜十数のセッションを並行させる上級開発者。

## 何を変えるのか（要件書 §1・§3）
今は「新規セッションの表（種類 × チャット/ターミナルを選ぶポップオーバー）」「起動カード」「同じフォルダで別セッションが動いているときの確認ダイアログ」があり、
書き始める前に選択や確認が割り込む。これを全部やめて、プロジェクトの ＋ や ⌘N を押すと、中央に「挨拶の見出し＋大きな入力欄＋提案チップ」の
新規チャット画面が出るようにする。ハーネスとモデル（例: Codex の gpt-6.1-sol）、worktree で分けるかどうかは、入力欄の中のチップで選ぶ。
最初のメッセージを送った時点でセッションができる（それまではセッションは存在しない）。

## 今のメインウィンドウの構成
- 上部ツールバー（高さ 52pt）。
- 左サイドバー（幅 220〜360pt。既定 260pt）: プロジェクトとその下のセッションの一覧（行の高さ 28pt）。プロジェクト行にホバーすると「＋」と「⋯」が出る。下端に「＋ 新規セッション ⌘N」ボタン。
- 中央: 上段にセッションのタブ列（32pt）、その下に子タブ列（32pt）、その下が会話（チャット）。
- 右サイドバー（インスペクタ。幅 260〜340pt）。
- チャットの入力欄（今の形）: 角丸 12 の入力欄。下段に「＋（添付） / モデル / effort / 権限」のチップが左、「ブランチ / コンテキスト使用量 / 送信」が右。

## 使うデザインの値（既定のダークテーマ「Phlox」。コードの正本は Packages/DesignSystem。アクセント色だけは今回コーラルから変える。要件書 §6.8）
- 基調はモノクロのグレー階調、アクセントは藍色 1 色だけ。アクセントは主要な操作・選択・フォーカス・リンクにだけ使う。
- 背景: ウィンドウ #1E1E20 / サイドバー #262629 / ツールバー #2A2A2D / パネル #242427 / カード #27272A /
  入力欄 #1A1A1C / ポップオーバー #2F2F33。
- 文字: 主 #F2F2F4 / 副 #ABABB1 / 補助 #8E8E94。区切り線は主文字色の 10%、枠線は 14%。
- アクセント: 主ボタンの面（白文字を載せる）は #3B469B。アクセントの文字（リンク・選択中のタブ）とフォーカス枠はダークで #959CD0、ライトで #3B469B。フォーカス枠は不透明。
- 注意の色（承認待ち・質問あり・エラー・無応答）は今のまま。
- ハーネスごとの色は使わない（廃止）。
- 文字サイズ: 本文 13pt、補助 12pt、メタ 11pt。システムフォント（SF Pro / SF Mono）。
- 間隔は 8pt グリッド（2 / 4 / 8 / 12 / 16 / 24 / 32）。角丸: タグ 4、ボタン・行 6、カード 8、パネル 10、入力欄・シート 12。アイコンは SF Symbols。
- ライトテーマもある（ウィンドウ #FFFFFF、サイドバー #F2F2F4、アクセント #3B469B）。主要な画面はダークで作り、最後にライトで 1 枚確認する。

## デザイン原則
- macOS Human Interface Guidelines に沿う。静かな chrome。参考画像の「中央に大きな入力欄」の構図は借りるが、Claude アプリの配色・ロゴ・書体（明朝の見出し）は使わない。ロゴは Phlox のアプリアイコン（紫〜ピンクのグラデーションの角丸正方形に、ノードがつながった図形）。
- キーボードだけで操作できる（⌘N → 入力 → ↩ で送信。チップは Tab で移れ、Space・↩ で開き、矢印で選び、Esc で閉じる）。
- VoiceOver: 入力欄は「メッセージ」、各チップは役割と今の値を読む（例「ハーネスとモデル、Codex: gpt-6.1-sol」）。
- 状態は色だけに頼らず、文言で区別できること（図形の印は使わない）。WCAG 2.2 AA（文字 4.5:1・部品とフォーカス枠 3:1）を満たすこと。
- UI 文言は日本語。英語に切り替えても崩れない幅を確保する。

## 描かないもの（要件書 §13・D3・D4）
- 音声入力（マイク）・参考画像の「チャット / Cowork」切り替え。
- 同じフォルダで別のセッションが動いていることの通知や確認ダイアログ（廃止する。何も出さない）。
- プロジェクト単位の「git worktree で隔離する」スイッチ（廃止する）。
- 画面からターミナルのセッションを始める手段（メニュー「新規ターミナルセッション」を含め、どこにも置かない。要件書 D1・FR-19）。カスタムエージェント（廃止。D22）。

## 各画面の出力ルール
- (1) 通常状態 (2) 要件書にある状態の描き分け (3) 操作の途中（ホバー・押下中・無効・メニュー展開・フォーカス）。ホバー・押下中・無効は今のボタンの見た目に合わせ、新しい表現を足さない。
- ハーネスの略号（CC・CX・CU）・ハーネスごとの色・状態の図形（◆・回転・○ など）・未読の丸は、どの画面にも描かない。状態は文字で示す（要件書 §6.7）。
- モックの横に「要件対応表」を付ける: 要件書の番号 → モック上の置き場所。置けなかった要件は明記する。
- サンプルデータは現実的に: プロジェクト `Phlox-oss`（`~/Projects/Phlox-oss`、ブランチ `dev`）・`ios-companion`・`site`、モデル名は今のアプリの表示名を使う（Claude Code: Default / Opus (1M context) / Fable 5.1 / Sonnet 5 / Haiku 5.5、Codex: gpt-6.1-sol / gpt-6-sol / gpt-6-astra / gpt-6-luna / gpt-5.6-sol、Cursor: Auto / Composer 2.5 / Claude Opus 5.5 / GPT-5.6 Sol ほか多数）。

まずは了解の返事と、要件書を読んで気づいた「UI 上の難所」を 5 つ以内で挙げてください。モックはまだ作らないでください。
```

## 1. 新規チャット画面の全体

```
新規チャット画面をメインウィンドウ全体のモックで設計してください。参照: §5.1〜§5.5、FR-1〜FR-4、FR-2a。

描くもの（ウィンドウ幅 1440pt、左サイドバー表示、右サイドバー非表示）:
- 中央の上下中央に、上から: 見出し → 入力欄 → 提案チップ 5 個 → 「履歴から再開…」。
- 見出し: Phlox のアイコン（小）＋「何から始めますか？」（名前は出さない。要件書 §5.2 の 10 種類からランダムに 1 つ）。
- 入力欄（幅は中央の幅に応じて最大 760pt 前後。提案してよい）:
  - 上: プレースホルダ「やりたいことを入力（/ でコマンド）」。
  - 下段左: ＋（添付） / ハーネス・モデル「(Codex のロゴ) gpt-6.1-sol ⌄」 / effort「高 ⌄」 / 権限「Full Access ⌄」。
  - 下段右: プロジェクト「Phlox-oss ⌄」 / 作業場所「既存ディレクトリ ⌄」 / 送信ボタン（↑）。
- 提案チップ: 「コードレビュー」「バグ修正」「テスト追加」「コードの説明」「リファクタ」（SF Symbols のアイコン付き）。
- サイドバー: 選択中のプロジェクト Phlox-oss が強調されている。セッション行は新規チャット画面のあいだ選択されていない。

描き分け:
- 入力済み（2〜3 行の本文＋画像の添付 1 つ）で送信ボタンが有効。
- 空で送信ボタンが無効。
- プロジェクトが未選択（プロジェクトのチップが「プロジェクトを選択 ⌄」。入力欄の下段の上に 1 行「プロジェクトを選んでください」）。FR-2a、E7。
- 中央が狭い（ウィンドウ 1000pt・右サイドバー表示）と、最小幅（ウィンドウ 720pt・左サイドバー表示）。E6 のまとめ方（effort・権限を「…」に、プロジェクト・作業場所はアイコンだけ）で、切れたり重なったりしないこと。NFR-7。
- 入力欄にフォーカスがある状態と、送信ボタンにフォーカスがある状態（フォーカス枠）。ライトでは枠と送信ボタンの面がどちらも #3B469B なので、見分けられる描き方にする。
- ライトテーマで 1 枚。

論点として提案してほしいこと:
- 見出しの大きさと、入力欄・チップの縦の間隔（参考画像より情報密度を少し上げたい。開発者向けで毎日何度も開く画面）。
```

## 2. 入力欄の下段のチップとメニュー

```
入力欄の下段のチップを、メニューを開いた状態も含めて設計してください。参照: §5.3、§5.4、E4、D2、FR-6。

描くもの（どれもポップオーバーのメニューとして。ポップオーバーの背景 #2F2F33・角丸 10）:
- プロジェクト: 登録済みプロジェクトの一覧（名前＋パスを薄く）。チェックで選択中を示す。
  選び直すと、そのプロジェクトの下書きに切り替わる（本文がプロジェクトごとに別）ことが分かる手がかりが要るか提案してほしい。
- 作業場所: 「既存ディレクトリ」（説明: このフォルダで直接作業する）/「新しい worktree」（説明: 別の作業コピーを作って分けて作業する）。
  git リポジトリでないプロジェクトでは「新しい worktree」が押せず、項目の下に説明文で理由（git リポジトリではないため worktree を作れません）が出る（ツールチップにはしない）。
  「新しい worktree」を選んだ後のチップの見た目（例: 分岐のアイコン＋「新しい worktree」）。
- effort（Claude / Codex）: 低・中・高・非常に高・最大（Codex は ultra も。今のアプリの表示名）。Cursor を選んでいるときは effort の代わりに mode（既定・ask・plan）。
- 権限: Claude（acceptEdits・auto・bypassPermissions・manual・dontAsk・plan）、Codex（Full Access・Default・Read Only。今のアプリの表示名）。
- ＋（添付）: 「ファイルを添付…」「画像を添付…」。

描き分け:
- 画像を添付したまま Cursor（画像非対応）に切り替えた: 添付は残り、入力欄の下段の上に 1 行「Cursor は画像を送れません。画像を外すか、画像を送れるハーネスを選んでください」と出て送信できない。§5.3、E7。
- 入力中に「@」で出るファイル候補の一覧、「/」で出るコマンド候補の一覧（今のセッション画面と同じ見た目でよい）。
```

## 3. ハーネス・モデル選択

```
ハーネスとモデルを組で選ぶチップとメニューを設計してください。参照: §5.4、§2「ハーネス・モデル選択」。

描くもの:
- チップの表示: 「{ハーネスのロゴ} {モデル名}」。例「(Codex のロゴ) gpt-6.1-sol」「(Claude のロゴ) Fable 5.1」「(Cursor のロゴ) Composer 2.5」。
  ハーネス名の文字は出さない。ロゴは各社の SVG。ハーネスの色の印・略号・図形は付けない（要件書 D14）。ホバーで「Codex: gpt-6.1-sol」と出す。
- 開いたメニュー: ハーネスごとの区切り（見出し）の下にモデルを並べる。選択中にチェック。既定のモデルに「既定」の小さなタグ。
  例: Claude Code（Default 既定 / Opus (1M context) / Fable 5.1 / Sonnet 5 / Haiku 5.5）、Codex（gpt-6.1-sol 既定 / gpt-6-sol / gpt-6-astra / gpt-6-luna / gpt-5.6-sol）、Cursor（Composer 2.5 既定 / Auto / Claude Opus 5.5 / GPT-5.6 Sol ほか 20 以上）。
- キーボード操作（↑↓ で移動、↩ で決定、文字入力で絞り込み）の手がかり。

描き分け:
- CLI が見つからないハーネス（例 Cursor）: 区切りごと薄く「未検出」と出て選べない（薄くするだけに頼らず「未検出」の文字で分かること）。
- モデル一覧を取得できず内蔵の一覧を出している: 区切りの見出しに控えめな「再試行」。
- モデルの数が多くメニューが長いとき（スクロールか、絞り込み欄か）。
- ハーネスを替えると、effort・権限のチップがそのハーネスのものに入れ替わる様子（Claude → Cursor で effort が mode に替わる）。
```

## 4. 送信した後: 起動中と失敗

```
送信した後の表示を設計してください。参照: FR-7、FR-10、FR-11、D7、D8、D11、§9 の 6。

流れ: 送信するとサイドバーに新しいセッションの行が「起動中」で出て、その会話画面に移る。最初のメッセージはこのセッションが預かり、
起動が終わったら送られる。起動に失敗したら、行は消さずに失敗を表示し、本文を入力欄に戻す。

描くもの:
- 「既存ディレクトリ」で送った直後: サイドバーに新しい行（右端に「起動中」の文字）。会話欄に預かった本文が「送信待ち」の文字を添えて出る。入力欄は空で「起動しています…」と出て送れない（ただの無効と見分けられること）。
- 起動が終わって最初のメッセージを送った後: 「送信待ち」が外れて通常の発言になり、行の右端は「実行中」。
- 「新しい worktree」で送った直後: 行はまだ無く、画面下部にトースト「worktree を作成しています」。数秒後に行が出る。
- 起動に失敗した行: サイドバーの行の右端に「エラー」の文字、会話画面に「起動できませんでした」と理由（例: claude のプロセスを起動できませんでした）、
  入力欄に本文が戻っている。「再起動」（新しいセッションとして起動し直す。入力欄の本文はそのまま残り、自動では送らない）と「閉じる」のボタン。
- 起動後、最初の送信が失敗した: 会話にエラー、入力欄に本文と添付が戻っている（今のセッション画面のエラー表示に合わせる）。
- worktree の作成に失敗した（行が出る前）: 今のダイアログ「worktree を作れませんでした」（git の出力、「隔離なしで起動」「既存の worktree を使う」「閉じる」）。閉じると新規チャット画面に戻り、本文が下書きに戻っている。
```

## 5. 履歴から再開

```
新規チャット画面の「履歴から再開…」を設計してください。参照: FR-13、FR-13a、FR-13b、FR-14、D10。

描くもの:
- 新規チャット画面の下部の「履歴から再開…」（控えめなリンクかボタン）。選択中のハーネスが Claude Code か Codex で、履歴があるときだけ出る。
- 押したときの一覧（ポップオーバーかシート。提案してほしい）: 最大 20 件、更新日時の新しい順。
  各行: 最初のメッセージの冒頭・相対時刻（例「3 時間前」）・どこで進めた会話か（「Phlox-oss」か「worktree」。worktree が既に消えていても出る）。
- 選ぶと、そのハーネスでセッションを作ってその会話を再開する。作業場所は新規チャット画面の選択に従う（worktree の会話を選んでも元の worktree には戻らない）ことが分かる手がかり。

描き分け:
- 履歴が無いとき（「履歴から再開…」自体を出さない。場所の高さは保つ）。
- 一覧の読み込み中・一覧が空（「履歴がありません」）・読み込みの失敗（「履歴を読み込めませんでした」＋「再試行」）。FR-13b。
- Cursor を選んでいるとき（出さない）。
```

## 6. 入口とメニューの変化

```
新規チャット画面への入口を設計してください。参照: FR-1、FR-1a、FR-3、FR-19〜FR-21、FR-15、E3、D21。

描くもの:
- サイドバー下端のボタン: 「＋ 新規チャット ⌘N」（旧「新規セッション」）。
- プロジェクト行にホバーしたときの「＋」（押すとそのプロジェクトの新規チャット画面。ポップオーバーは出ない）。
- プロジェクト行の右クリック・「⋯」のメニュー: 「新規チャット」「プロジェクト名を変更…」「削除…」（「新規ターミナルセッション」は無い）。
  旧メニューにあった「git worktree で隔離する」は無い。
- メニューバー「ファイル」: 「新規チャット ⌘N」（「新規ターミナルセッション」は無い）。
```
