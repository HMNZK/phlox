# Claude Design 用プロンプト集 — Phlox macOS UI 再設計

## 使い方

1. Claude Design で新しいプロジェクトを作り、`macos/docs/specs/ui-feature-inventory.md`（以下「機能一覧」）を添付する。
2. 最初に「0. 共通プロンプト」を送る。以後の画面プロンプトはすべてこの前提の上で動く。
3. 「1. 全体の骨格」を先に確定させてから、2 以降を 1 画面ずつ送る（骨格が揺れると全画面を作り直すことになるため）。
4. 最後に「13. 横断レビュー」で機能の抜け漏れと一貫性を点検させる。

各画面プロンプトの「参照」は機能一覧の章番号。

---

## 0. 共通プロンプト（最初に 1 回だけ送る）

```
あなたは macOS ネイティブアプリの UI デザイナーです。添付の「ui-feature-inventory.md」は、
Phlox という macOS デスクトップアプリの現行 UI 機能を画面ごとに棚卸しした一覧です。
これを要件として、UI を 0 から再設計した「理想的な」高忠実度モックを画面ごとに作ってください。

## Phlox とは
複数の AI コーディングエージェント（Claude Code / Codex / Cursor と、ユーザーが JSON で追加する
カスタムエージェント）を 1 つのウィンドウで同時に走らせ、監視・指示・承認するための開発者向けアプリ。
利用者は同時に数〜十数セッションを並行させる上級開発者。主な仕事は
「どのセッションが自分の対応を待っているかを即座に知る → 承認・回答・追加指示を返す → 次へ」。

## 要件の扱い
- 機能一覧にある機能は 1 つも落とさないこと。置き場所・まとめ方・見せ方は自由に変えてよい
  （現行の配置を踏襲する必要はない。より良い情報設計を提案すること）。
- 「実装済み・UI 未配線」と書かれた機能は、置くと価値が出るなら候補として配置し、候補である旨を注記する。
- 「推測」「未確認」と書かれた項目は確定仕様として扱わず、デザイン上は分岐候補として扱う。
- 機能を削る・統合する提案をするときは、削る機能と理由を明記する（黙って消さない）。
- 対象外: 機能一覧 6章の「チームビュー」と「Agora 討論」は新しい UI では廃止する。表示モードは single と grid の 2 つだけにし、
  チームビュー・討論に関する要素（表示モードの選択肢、宛先付きチーム向けコンポーザ、討論ヘッダなど）はどの画面にも置かないこと。

## デザイン原則
- macOS Human Interface Guidelines に沿ったネイティブな見た目と操作感（ツールバー、サイドバー、
  インスペクタ、ポップオーバー、シート、コンテキストメニュー、キーボード操作）。
- 情報密度は高く、しかし読める。長時間見続ける画面なのでノイズを減らし、注意が必要なものだけが目立つこと。
- 状態（起動中 / 待機 / 実行中 / 承認待ち / 質問待ち / 完了 / エラー / 無応答）は
  色だけに頼らず、形・アイコン・文言でも区別できること。
- エージェント種別の違い（Claude / Codex / Cursor / カスタム）は識別できるが、主張しすぎないこと。
- ライトモードとダークモードの両方を用意する。
- アクセシビリティ: コントラスト比、キーボードだけでの全操作、VoiceOver のラベルを意識する。
- UI 文言は日本語（アプリは日本語/英語切替対応。英語で長くなっても崩れない幅を確保する）。

## 各画面の出力ルール
- 画面ごとに: (1) 通常状態のモック (2) 機能一覧にある状態の描き分け（空・読込中・エラーなど）
  (3) 主要な操作の流れ（クリック後・ホバー時・右クリックメニュー・ポップオーバー展開時）。
- モックの横に「機能対応表」を付ける: 機能一覧の機能名 → モック上の置き場所。未配置の機能があれば明記。
- 現行 UI から大きく変えた点は、変えた理由を 1〜2 行で添える。
- サンプルデータは現実的に: 実在しそうなリポジトリ名、コード、ツール呼び出し、エラーメッセージを使う。

まずは了解の返事と、機能一覧を読んで気づいた「現行の情報設計の問題点」を 5 つ以内で挙げてください。
モックはまだ作らないでください。
```

## 4. 承認・質問・入力欄（コンポーザ）

```
ユーザーがエージェントへ返答する部分を設計してください。参照: 機能一覧 4.2節（承認・質問）・4.3節（コンポーザ）・16.2〜16.5節。

含めるもの:
- 承認要求（許可 / 拒否 / このセッション中は許可 / キャンセル の 4 択）。何を許可するのかが一目で分かる表示
- エージェントからの質問（見出し・質問文・選択肢（ラベル＋説明）・複数選択の有無）への回答 UI

  スラッシュコマンドの候補、モデル選択（種別ごとの一覧・CLI から取得失敗時の表示）、
  権限/承認モードの選択（種別ごとに選択肢の数が違う: Claude 3 種・Codex キー選択式・Cursor 2 種）、送信 / 中断

描き分け: 空 / 入力中 / 候補表示中 / 送信中 / 実行中（中断可能）/ 承認待ち / 質問待ち / 添付不可のエージェント。
論点: 承認を素早く安全に捌ける配置（誤承認を防ぎつつ 1 キーで返せる）。
```

## 14. エージェント状態カード（会話ログ。2026-11-06 追加）

要件は `macos/docs/specs/agent-status-card.md`。**このプロンプトは 0〜13 の再設計とは独立に、単独で送る**（2026-11-07 ユーザー決定: アプリは現行のまま。変えるのはチャット画面に出す表示だけ）。添付に今のチャット画面のスクリーンショット（ライト・ダーク）を加える。添付するもの: 要件書、ユーザーの手描きスケッチ（`macos/docs/specs/ClaudeDesign/agent-status-card-sketch.png`）、参考動画（Elia @eliakuratli「Agent status component」 https://x.com/eliakuratli/status/2113618712066711970 ）の画面の切り出し。

```
Phlox のチャット画面（1 セッションの会話表示）に、「エージェント状態カード」を設計してください。
前提: アプリは添付のスクリーンショットの現行のままです。ツールバー・サイドバー・インスペクタ・グリッドの見出し・入力欄・キー割り当て・配色・状態の表し方は一切変えないでください。
以前に作った全画面の再設計案（ツールバーの変更、状態の図形、青いフォーカス色など）は採用しないので、持ち込まないこと。
変えてよいのは会話ログの中の表示だけです（Claude と Codex のチャット。Cursor は今のまま）。
要件は添付の agent-status-card.md（特に §3 の決定表、§4 の機能要件）。手描きスケッチと参考動画のフレームは見た目の方向性の参考で、要件と食い違う部分（進捗バー・Step N of M・モデル名・Pause・Open run）は入れないこと。

カードの役割:
- ユーザーの入力 1 回につき 1 枚、会話ログの末尾に出る。終わったらその位置に記録として残る。
- 1 行目（見出し）: 左に点描アニメーション（完了で ✓、中断・エラーで印）、中央に今の作業（種類のアイコン＋「api.swift を編集中」）、右に経過時間 0:13。
- その下に、エージェントが登録したタスクの縦の一覧。印（✓ / 進行中の小さい点描 / ○ / 中断）を縦線でつなぐ。完了タスクは取り消し線＋薄い文字で非活性の見た目。各行の右端にタスクの所要時間。
- 進行中のタスクは自動で開き、その下に作業の行（種類のアイコン・何をしたか・所要時間 1.9s）が増えていく。進行中の作業は薄い文字で「〜中」。同じ種類の連続はまとめる（「5 ファイルを編集」）。
- 作業の行を開くと、差分やコマンド出力（今のツールカードの中身）が見える。
- どのタスクにも属さない作業は「タスク外の作業」の行にまとめる（タスク登録前の作業はタスクの上）。
```
