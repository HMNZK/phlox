# ADR 0146: ファイル変更をコードビューで描く（行番号は推測しない）

> **このファイルの役割**: diff 表示に行番号と構文ハイライトを入れ、外部依存を足さずに済ませた理由と、
> 行番号を「分からないときは出さない」と決めた理由。
> **書かないもの**: カードの装飾（→ [ADR 0144](0144-quiet-chat-chrome.md)）、
> ツール実行グループの見出し（→ [ADR 0145](0145-tool-group-recap-header.md)）。

> **後継**（2026-07-31・[ADR 0147](0147-chat-code-card-and-header-dedup.md)）: 決定「**`@@` の hunk ヘッダは
> 区切りとして残す**」は**覆した**——hunk ヘッダ行は表示しない（分類・採番のデータとしては保持する）。
> あわせて「パスは末尾 2 階層へ短縮し、ツールチップで完全パスを出す」も廃止し、カード外のパス行を消して
> **カード内ヘッダのフルパス 1 行**へ統合した（`.help` も不要になった）。行番号を 1 つも確定できない diff では
> **番号列そのものを幅 0** にする。**本 ADR の核心＝「外部依存を足さない」「行番号は根拠があるときだけ出す・
> 分からないときは推測しない」「コピーは元の diff 全文」は不変**で、ADR 0147 がこれを引き継ぐ。

## 文脈

`FileChangeCell` の diff は、行を addition / deletion / hunk / fileHeader / context の 5 種に分類して
前景色と 12% の背景を敷くだけだった。トークン単位の構文ハイライトも行番号も無く、
`--- <path>` / `+++ <path>` の重複ヘッダと `\ No newline at end of file` が本文に混じり、
セクション見出しには絶対パスが丸ごと出ていた。「diff は読めるが、コードとしては読みにくい」状態。

リポジトリには構文ハイライトの外部 SPM 依存が無く、自前の `ChatCodeHighlighter`（Swift の
キーワード・文字列・数値・コメントのみ）が markdown の fenced code block 用に存在していた。

## 決定

**外部依存を足さず、既存のトークナイザを diff へ広げる。行番号は根拠があるときだけ出す。**

- **`Highlightr` 等は入れない。** WebKit/JS 同梱でアプリが重くなる割に、チャットに出る diff は
  短い断片が中心で得るものが小さい。既存 `ChatCodeHighlighter` のトークナイザを 1 本化して共有し、
  diff 本文用の入口だけを足した（markdown 側の出力は旧実装と完全一致することを実ソース 218KB で検証済み）。
  拡張子で言語を決め、**未対応の拡張子は全トークン `plain`** にフォールバックする。
- **行番号は hunk ヘッダ `@@ -a,b +c,d @@` から起算する。** 削除行は旧側、追加行とコンテキスト行は新側。
  hunk / fileHeader 行には番号を付けない。
- **分からないときは推測しない。** hunk ヘッダが無い diff、解釈できない壊れたヘッダ、
  加算がオーバーフローする値（`Int.max` 起点）では、その時点以降の採番を諦めて空欄にする。
  壊れたヘッダの後で直前 hunk の連番を続けるのも「推測」なのでやめた。
  diff はエージェントが供給する任意テキストであり、**`split(...)[0]` の素朴な実装は実際に
  index out of range でアプリごと落ちた**（独立レビューが再現）。ここは防御的に書く。
- **ノイズを本文から外す。** `---`/`+++` とファイル末尾改行の注記は描かない（パスは見出しに出ている）。
  `@@` の hunk ヘッダは区切りとして残す。**コピーは元の diff 全文**（表示から消した行も含む）を返す。
  表示用データから復元して返すのは退行なので、テストで表示データと原文が食い違う状態を作って担保している。
- **パスは末尾 2 階層へ短縮し、完全パスはツールチップで出す。** ツールチップはカード全体ではなく
  **各セクション見出しの短縮パス**に付ける。カード全体に付けると、複数ファイルの変更で他セクションの
  行にも先頭ファイルのパスが出てしまう。
- **行番号・ハイライト・表示対象行の算出は `ChatMessageRenderCache` にメモ化する。**
  body の計算プロパティに置くと、評価のたびに全行を走査し直す。

## 結果

- Claude セッションの Edit/Write 由来 diff は、生成側（`ClaudeChatClient+Formatting.swift`）が
  `@@` としか出さないため**行番号が空欄のまま**になる。生成側は old/new を丸ごと並べるだけで実ファイルの
  行番号を持たず、1 起算の番号を出すと誤情報になるため、この run では生成側を変えなかった。
  番号付き hunk ヘッダを出すかどうかは別途の判断とする（既知の制約）。
- 回帰保護: `AcceptanceFileChangeCodeViewTests`（複数 hunk の採番・ヘッダ無し／壊れたヘッダ 15 種・
  オーバーフロー・no-newline 注記が採番を進めないこと・ノイズ除去・パス短縮・言語別トークン分類・
  コピー契約）と `ChatTranscriptFormattingTests`。
