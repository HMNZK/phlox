# ADR 0147: コードビューを枠線付きカードへ 1 本化し、見出しの重複・時刻・件数を落とす

> **このファイルの役割**: ADR 0144〜0146 を実機で使った結果の手直し（実装 3 巡ぶん）を確定する。
> 時刻・件数・「実行中」・重複テキストを落とした理由、diff とコマンド実行を同じ `ChatCodeCard` に
> 収めた理由、ツール名ラベルを `ChatItem` を変えずに表示側で導出した理由。
> **書かないもの**: 装飾撤去そのものの判断（→ [ADR 0144](0144-quiet-chat-chrome.md)）、
> 見出しを recap にした判断（→ [ADR 0145](0145-tool-group-recap-header.md)）、
> 行番号を推測しない判断（→ [ADR 0146](0146-diff-code-view.md)）。

## 文脈

ADR 0144〜0146 の実装を実機の transcript で使ったところ、静かにしたはずの chrome がまだ残っていた。

- カードヘッダに時刻が出続け、シェブロンは `Spacer` で右端へ飛ばされていて、見出しとの関係が読めない。
- ツール実行グループの見出しが `swift test を実行` のように**接尾辞つき**で、しかもサブタイトルに
  `実行中 ×1` が併記される。`×1` は情報量ゼロで、`実行中` は orb（ADR 0142）と重複していた。
- Reasoning は短い断片が多く、抽出見出しと本文が**同一文**になる。閉じても開いても同じ文が出る。
- diff は行ごとに背景矩形を敷いていたため、行の縦 padding のぶんだけ帯が途切れ、**角がぼこぼこ**に見えた。
  さらにカード外に `doc.text` アイコン＋短縮パスの行があり、カード内のヘッダと二重にパスが出ていた。
- コマンド実行は枠も背景も無い素のテキストで、diff とは見た目が揃っていなかった。

ユーザーが提示した理想像は「枠線付き・角丸のカード 1 枚の中に、ツール名ラベル＋コピーアイコン、
`$ command`、その下に出力」であり、diff もコマンドも同じ器に収まっている形だった。

## 決定

**器を 1 つにし、二度出る情報は片方を消す。**

- **`ChatCodeCard<Header, Content>` を新設し、枠線・背景・角丸・`clipShape`・ホバー・コピーボタンを
  そこへ集約する。** diff もコマンド実行もこのカードの中身になる。`DisclosureCard` は
  「見出し＋シェブロン＋展開状態」だけを持ち、枠や背景を持たない（責務が混ざると、
  カードの中にカードが入ったときに枠が二重になる）。markdown の fenced code block（`CodeBlockView`）は
  同じトークン（`DSColor.chatCard` / `DSColor.border` / `DSRadius.m`）を使うが**触っていない**——
  既存の挙動を回帰テストで固定したうえで据え置いた。
- **カードヘッダの時刻を消す。** 時刻は `AvatarMessageRow`（メッセージ単位）にだけ残し、
  カードごとには出さない。代わりに**ホバーで現れるコピーボタンの右**に置く。
  常時表示の情報を減らし、必要なときだけ出す。
- **シェブロンをタイトルの直後へ置く**（`AGENTS.md >`）。`Spacer` で右端へ押し出すと、
  タイトルとシェブロンの間の空白が「何が開くのか」を曖昧にする。ヘッダ全体がクリック領域である性質
  （`.contentShape(Rectangle())`）は維持する。
- **見出しはコマンドそのものにする。** ADR 0145 が入れた `を実行` / `を読み込み` / `を編集` の
  接尾辞と、`RecapActivity` による分類をやめ、`CommandGroupTitle.derive(items:)` は最後のコマンドを
  空白正規化して `ThinkingRecap.clamp` で 60 文字に切っただけの文字列を返す。分類ラベルは
  コマンドを読めば分かることを言い換えているだけで、原文より情報が少ない。
  コマンドが 1 件も無いグループのフォールバック `"ツール実行 ×N"` だけは残す（他に出す情報が無い）。
- **`liveRecap` クロージャを廃止する。** グループの `items` は新しいコマンドが来るたび変わるので、
  `Equatable`（ADR 0116）経由の再評価だけでタイトルは追従する。毎秒駆動の `TimelineView` は不要になり、
  `ChatRecap.derive` / `ChatSessionViewModel.recap(now:)` も未使用になったため削除した
  （`deriveActivityState` は orb が使うので残す）。
- **サブタイトルを廃止する（常に `nil`）。** `×N` は件数だけを伝えて何をしたかを伝えない。
  `実行中` は orb と同じことを二度言っている。実行中かどうかはヘッダに出さない。
- **見出しと本文が同一なら折りたためない 1 行にする。** Reasoning で見出しと本文（trim 後）が一致するとき、
  `DisclosureCard` を使わず半透明グレー（`DSColor.chatToolCallText`）の 1 行として描く。
  開いても新しい情報が出ないトグルは、トグルであること自体がノイズ。
- **diff の帯を途切れさせない。** 行ごとの縦 padding をやめ、全幅の矩形を隙間なく積む。
  **hunk ヘッダ行（`@@ …`）は表示しない**（分類・採番のデータとしては保持する）。
  **行番号を 1 つも確定できない diff では番号列そのものを幅 0 にする**（ADR 0146 の「推測しない」を
  レイアウトまで貫くと、空欄の列が残るのは無意味なため）。番号が分かる行と分からない行が混在する場合は
  列幅を保ち、分かる行にだけ番号を出す。カード外の `doc.text` ＋短縮パス行は廃止し、
  カード内ヘッダの**フルパス 1 行**へ統合した。
- **ファイル変更は既定で折りたたみ、見出しに増減行数を出す。** `編集済み lessons.md +2 -1` の形。
  動詞（`FileChangePresentation.verb(for:)`）と増減数（`.counts(for:)`）は純粋関数として切り出し、
  行数依存の自動展開（`isExpanded` が `lineCount` を見る既定）は廃止して `userOverride ?? false` にした。
- **コマンド実行は「ツール名ラベル＋ `$ command` ＋出力」で描き、ツール名は表示側で導出する。**
  設計案にあった「`ChatItem` にツール名フィールドを足す」は**採らない**。`ChatItem` は永続化される
  transcript の型で、表示都合の変更を入れると移行が要る。代わりに `CommandToolLabel.derive(command:)` が
  先頭トークンを既知ツール名の集合（`Read`/`Write`/`Edit`/`Glob`/… ）と**完全一致**で照合し、
  一致しなければ `Bash` とする。生成側（`ClaudeChatClient+Formatting.commandDescription`）が
  Bash は生コマンド、それ以外は `"<Tool> <arg>"` を出す仕様なので、この照合で足りる。
- **シェル用トークナイザは `ChatCodeHighlighter` の別入口として足す。**
  コマンド名・サブコマンド・変数・演算子・オプションを分類する。Swift と markdown 側の出力は不変
  （回帰テストで固定）。継続行は `$ ` の幅ぶんだけ `HStack` のインデントで揃え、
  **コピーは原文のまま**（表示用のインデントを混ぜない）。
- **表示データはすべて `ChatMessageRenderCache` に載せる。** diff 行・シェルハイライト・
  コマンド表示のいずれも body の計算プロパティに置かない（キーは内容同一性のみ。`item.id` は使わない）。

## 結果

- **ADR 0146 の「`@@` の hunk ヘッダは区切りとして残す」は本 ADR で覆した**（非表示）。
  行番号の採番規則・「分からないときは推測しない」・コピーは元の diff 全文、は不変。
- **ADR 0145 の「件数はサブタイトルへ移す」「live recap をクロージャで渡し `TimelineView` で追従する」
  「完了形ラベルにする」は本 ADR で覆した**。同 ADR の核心（見出しで何をしているか読める・
  トグルは既定シェブロンを使わない・`Equatable` を壊さない）は不変。
- 継続行のインデントは、最初の実装で `HStack` のインデントと `"\n  "` の文字列置換が二重に効き、
  左端が x=34 へずれていた。独立レビューが `ImageRenderer` の実測で検出し、置換を削って x=18 にした。
  「見た目の整形は 1 箇所でだけやる」——表示木と文字列の両方でやると必ずずれる。
- 回帰保護: `AcceptanceChatCodeCardTests`（カードの器・ツール名導出・シェルトークン分類・
  継続行インデント・コピー原文）、`AcceptanceFileChangeCodeViewTests`（hunk 非表示・番号列の可変幅・
  既定折りたたみ・増減数）、`AcceptanceCommandGroupRecapHeaderTests`（接尾辞なし・サブタイトル不在）、
  `AcceptanceQuietChatChromeTests`（時刻引数の不在・シェブロン位置）、`ChatCodeBlockTests`
  （Swift・markdown の出力不変）。
- 既知の制約は ADR 0146 のまま: Claude セッションの diff は生成側が `@@` としか出さないため
  行番号が付かない。本 ADR の「番号列を幅 0 にする」により、その場合は番号列自体が消える。
