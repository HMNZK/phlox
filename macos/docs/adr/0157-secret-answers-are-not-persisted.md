# ADR 0157: 伏せ字（`isSecret`）の回答は wire 送信後に破棄し、保存しない

> **このファイルの役割**: codex の質問が `isSecret` のとき、入力を伏せ字にするだけでなく
> **回答そのものを保持しない**ことにした決定。
> **書かないもの**: 質問カードへの合流と回答キーの決定（→ [ADR 0155](0155-codex-request-user-input-as-question-card.md)）。

## 文脈

codex の `questions[].isSecret` は「パスワード・API キーのような伏せ字入力」を意味する。
最初の実装では入力欄を `SecureField` にし、回答済みカードの表示をマスクしただけだった。
しかし回答は `ChatItem.userQuestion(answers:)` に**平文のまま**積まれるため、
会話の永続化 JSON と Markdown エクスポートにパスワードが平文でディスクへ残っていた
（画面のマスクは見た目だけ）。

## 決定

**平文は wire へ送った直後に捨てる。** マスクは表示層ではなく保持層で行う。

- `approvalBroker.answerUserInput` へ渡す値は素の回答（codex は本物を受け取る）。
- 送信の**あと**、転写へ積む前に `isSecret == true` の質問の回答を**固定長のマスク文字列**へ
  置き換える。以後どこから読んでも平文は取れない（永続化 JSON もエクスポートも同じ値を見る）。
- マスクは固定長にして**回答の長さも漏らさない**。
- マスク規則の正本は `ChatUserQuestion.persistedAnswers` の 1 箇所に置き、
  Claude 経路と Codex 経路の 2 つの保存箇所が同じ関数を通る。

表示側（エクスポータ）でマスクする案は採らなかった。表示箇所が増えるたびに漏れるうえ、
永続化 JSON は依然として平文のままだからである。

## 結果

- 伏せ字で答えた値がディスクに平文で残らない。エクスポートしても出ない。
- 回答済みであること自体は残る（`answers` を空にはしない）ので、カードは `answered` のまま。
- 一度答えた秘密の値は**アプリ側から再取得できない**。会話を再開しても平文は復元されない
  （それが目的なので受け入れる）。
- 既知の残課題: 秘密の質問が選択肢を持つ場合、選択肢の説明文（`options[].description`）は
  従来どおり平文で表示・保存される。選択肢の文言は codex がモデル側で作る固定文であり、
  ユーザーの入力ではないため今回は対象外とした。
