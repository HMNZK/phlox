# 0179: iOS シミュレーターの画面内表示は、非公開部品を XPC サービスに隔離して使う

> **状態**: 採択（2026-10-03、ユーザー判断）。関門のうち Debug・ad-hoc 署名のアプリでの連続表示・タップ・ドラッグ・キー入力・ホームは確認済み。**公証済みアプリでの動作は未確認**で、確かめられなかった場合はこの ADR を置き換える新しい ADR を起こす。経緯は `delivery/0038-file-explorer-and-simulator-worklog.md`。

## 決定

要件と詳細設計は `specs/embedded-ios-simulator.md`。

1. **非公開部品（CoreSimulator / SimulatorKit）を使う**。画面を画面内に表示する公開手段が無く、既存のツールもすべてこの方式を使っている。
2. **非公開部品は XPC サービス（別プロセス）に隔離する**。本体には読み込まない。
3. **SimulatorKit の表示部品（`SimDisplayView` 等）を本体に埋め込まない**。画面は IOSurface（プロセス間で共有できる画像バッファ）で受け取り、本体が描く。
4. **子タブ（`ChildTab.simulator`）に置く**。インスペクタには置かない。
5. **`.simulator` タブは永続化しない**。
6. **入力の成否を画面の変化で判定しない**。
7. **キー入力は物理キー方式で送る**。

## 文脈

本体は作業中のエージェントセッションを抱えている。非公開部品の不具合で本体が落ちると、処理中のセッションが失われる。非公開部品は Xcode の更新で壊れうるため、Xcode のビルドと iOS ランタイムの組み合わせごとの許可リスト・実行記録・欠落シンボルの検出で扱う。

## 棄却した案

- 非公開部品を本体に直接読み込む: 部品の不具合が本体のクラッシュに直結する。
- `SimDisplayView` を埋め込む: Swift 製で外部から安定して構成できず、本体への読み込みも必要になる。
- インスペクタに表示する: 最大 340pt では端末の画面には狭い。
- タブを永続化する: 旧バージョンが未知の case を読むと、タブ配置の全体を失う。
- 画面の変化で入力の成否を判定する: 入力が無視されてもアニメーションで画面は変わり、正常なタップでも変わらないことがある。
- Mac 側の文字変換を通した文字列入力: 確定文字列を送る別の経路が要り、第 1 版の範囲を超える。

## 結果

- Xcode を更新すると、許可リストを更新するまで「Simulator.app で開く」に案内される。
- 補助プロセスの署名検査を新しいテストファイルとして足す（凍結済みの `test_signing_entitlements_variants.sh` は変えない）。
