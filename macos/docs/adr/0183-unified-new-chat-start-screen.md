# 0183: セッションの始め方を共通の新規チャット画面にまとめ、送信した時点でセッションを作る

## 決定

- 新規セッションの表（種類 × チャット/ターミナル）、起動カード、同じフォルダの確認ダイアログを廃止し、入口（⌘N・サイドバーの ＋・プロジェクト行の ＋・グリッドの空状態）をすべて共通の新規チャット画面にする。ADR 0071・0082 を置き換える。ADR 0086（プロジェクト名の選択で開始画面を出す）の開始画面はこの画面になる。
- 新規チャット画面ではハーネスとモデルを組で選ぶ（例「Codex: gpt-6.1-sol」）。ハーネスは作成後に変えられない（`agentRef` は `let`）ので、**送信するまでセッションを作らない**。下書きはプロジェクトごとにメモリにだけ持つ。
- 送信したら、起動の成功（Claude のプロセス起動、Codex の開始と設定の適用）を確かめてから最初のメッセージを送る。起動や初回送信に失敗したセッションは消さずに残し、本文をその入力欄に戻す。再起動は新しいセッションとして起動し直す。
- プロジェクト単位の「git worktree で隔離する」設定を廃止する。新規は入力欄の「既存ディレクトリ / 新しい worktree」の選択で、復元は保存済みの作業フォルダがそのセッションの worktree の場所かどうかで決める。Control API・CLI・子セッションは常に既存ディレクトリで起動する。ADR 0170（作れなければ中止し、共有フォルダへ逃がさない）はそのまま守る。
- ターミナルのセッションは、メニュー「新規ターミナルセッション ▸」（ファイル・プロジェクト行）から始める。設定「新規セッションの既定の開き方」は廃止する。
- 「履歴から再開」は新規チャット画面に置き、そのプロジェクトで過去に worktree で進めた会話も含める。

## 理由

ユーザーがやりたいのは「＋ を押してすぐ書き始める」ことで、種類・開き方・作業場所は書きながら入力欄で選べれば足りる。先に表や確認ダイアログで選ばせると、入口が 3 つに分かれ、毎回割り込みが入る。

入力欄でハーネスを選ばせるには、ハーネスが決まる前にセッションがあってはいけない。起動を送信時まで遅らせるのは、ハーネスを作成後に変えられる仕組み（描画も CLI の起動方法も違う）を作るより小さい。iOS アプリは同じ形（下書きで開き、最初のメッセージで起動）をすでに採っている（ADR 0008）。

worktree の判断をプロジェクト設定から外すのは、起動ごとに選べるなら設定は二重になり、「この起動だけ」の上書きと復元用の打ち消し印（`worktreeIsolationOptOut`）が要っていたため。作業フォルダは隔離したセッションでは必ず worktree の場所が保存されているので、事実として判断に使える。

起動の失敗で行を残すのは、送信した本文を失わず、セッションを二重に作らないため。同じセッションのまま起動し直す形は、Codex では client を作るときにプロセスを起動し、client を差し替えられないので採らない。

実 CLI で確かめたこと（2026-10-11、codex-cli 0.162.0・Claude Code 2.1.296）: Codex は `thread/start` で渡したモデルが最初のターンから効く。Codex と Claude は、別のフォルダから過去の会話を再開でき、そのフォルダで動き、元のフォルダが消えていても再開できる。

## 結果

- ＋ や ⌘N を押してもセッションはすぐにはできない。下書きはアプリを終了すると消える。
- 同じフォルダで別のセッションが動いていても何も聞かれない。変更がぶつかる場面を知らせずに許す（ユーザー判断で受け入れ）。
- 隔離オンのプロジェクトで CLI・iPhone から起動していた場合、worktree ではなく本体のフォルダで動くようになる（ユーザー判断で受け入れ）。
- 「新しい worktree」で送ると、worktree を作り終えるまでサイドバーに行が出ない（数秒。その間はトースト）。
- 凍結された受け入れテスト `AcceptanceRestoreAbortNoSpawnTests` の 1 つ目を、意図（隔離するはずのセッションを共有フォルダで起動しない）を保ったまま条件だけ書き換える（ユーザー承認済み）。
- 旧版へ戻したときの作業場所は保証しない。
