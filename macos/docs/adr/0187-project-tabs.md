# 0187: 上段をプロジェクトのタブにし、タブ列をサイドバーと一致させる

## 決定

- 上段のタブをプロジェクトにし、その下に選択中のプロジェクトのチャット・ターミナル・変更・ファイル・ブラウザ・シミュレーターを並べる。ターミナル・変更・ファイルはプロジェクトのフォルダで開き、ターミナルはプロジェクトごとに複数持てる。
- タブ列とサイドバーを常に一致させる。上段の ✕ はプロジェクトの削除、下段のチャットの ✕・⌘W はセッションの削除で、どちらも今の確認ダイアログを出し、サイドバーからも消える。タブ列からだけ外す操作は置かない。
- 共通ターミナル（ホームで開く、タブ列の右端）は廃止する。ADR 0149 の「cwd はホーム固定」と、`PhloxApp` が共通ターミナルを持つ部分を置き換える。ユーザーターミナルをセッションとして登録しないこと、アプリ終了時の後始末はそのまま。
- ヘッダーからプロジェクト名と worktree のボタンを消し、高さを必要最小（`.unifiedCompact` の帯）にする。「プロジェクト名を変更…」は上段のタブの右クリックへ移す。
- worktree で動くセッションの変更は会話画面の中で見る。そのフォルダでターミナルを開く入口は置かない。
- 新規チャット画面（ADR 0183）と同時に実装する。

## 理由

ターミナルやファイルがセッションに属すると、同じプロジェクトでもセッションを替えるたびに見えなくなる。ユーザーはプロジェクトを単位に並べて切り替えたい（2026-10-11）。

タブ列をサイドバーと一致させると、「タブから外したが動き続けているセッション」という第 3 の状態が生まれず、✕ の意味が一つになる。今の会話タブの ⌘W も確認の後にセッションを削除しており、その動きを引き継ぐ。

## 結果

- セッションを消さずにタブ列を短くする手段は無い。多いときは右端の「ほか n」にまとめる。
- worktree のフォルダでコマンドを打つときは、プロジェクトのターミナルで自分でフォルダを移る。
- タブのモデルと、ターミナル・ブラウザ・シミュレーター・ファイルの持ち主の鍵を、セッションからプロジェクト・項目へ作り替える。
