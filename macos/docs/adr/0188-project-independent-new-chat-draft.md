# 0188: 新規チャットの下書きをプロジェクトから切り離し、送信したときにそのプロジェクトのタブを作る

ADR 0183 の「下書きはプロジェクトごと」（要件 D9）と、ADR 0187 の「新規チャットをプロジェクトの子タブとして開く」を置き換える。

## 決定

- 新規チャットの下書きは**アプリに 1 つ**にする。入力欄のプロジェクトの選択は「送信先」で、選び直しても本文・添付・設定は消えない。
- 新規チャット画面は**どのプロジェクトのタブにも属さない画面**として出す。出している間は上段のプロジェクトのタブを選択しない。子タブ「新規チャット」は作らない。
- 送信すると、選んだプロジェクトのタブを選択し、その子タブとしてセッションを作る（今の `completeNewChat` の流れ）。
- プロジェクトの ＋・⌘N などの入口は、送信先のプロジェクトを決めてから同じ下書きを出す。セッションが 1 つも無いプロジェクトを選んだとき（D21）も同じ。
- 送信先のプロジェクトを削除したら送信先を空にし、本文は残す。

## 理由

プロジェクトごとの下書きでは、プロジェクトを選ぶ前に書いた本文が、プロジェクトを選んだ瞬間に消えたように見えた（未選択の下書きから選んだプロジェクトの空の下書きへ切り替わるため）。プロジェクトを選び直したときも同じだった。また、プロジェクトを選んだ時点で子タブ「新規チャット」ができるので、送る前からタブがあるように見えた。ユーザーは「送信するまでは新規チャットを独立して扱い、送信した後にそのプロジェクトのタブにする」ことを求めた（2026-10-13）。

## 結果

- 下書きの切替・「下書きあり」の印（要件 E8）・「本文と添付はプロジェクトごとに保たれます」の案内は無くなる。
- 保存済みのタブ配置に残っている子タブ「新規チャット」は、読み込むときに捨てる。
- 詳細は [要件](../specs/unified-new-chat-start.md) D27・§6.2 と [設計](../specs/unified-new-chat-start-design.md) §2.1・§3.1。

## 改訂（2026-10-13 同日）

「どのプロジェクトのタブにも属さない画面」は、送信先が決まらないときだけにした。送信先が決まっていれば（プロジェクトを選んで ⌘N、タブの無いプロジェクトを選んだときなど）そのプロジェクトを選んだまま、子タブの場所に新規チャット画面を重ねて出す。選択を外すと、サイドバーで今どこにいるか分からず、インスペクタのファイルも出なくなるため（ユーザー指示）。タブは今どおり送信するまで作らない。詳細は要件 FR-1a・D21。
