# 0193: ユーザー用ターミナルのシェルを設定から解決する

## 決定

- 設定の「一般」に「ターミナル › シェル」を追加する。システムの既定、実行可能な `/etc/shells` の項目、任意の絶対パスから選ぶ。
- `UserShellSettings` に候補の読み取り・ファイル検証・ログインシェル取得・起動時の解決を集約する。空の保存値はシステムの既定を表す。
- `UserTerminalController` は新規起動・再起動ごとに解決関数を呼ぶ。結果は実際のパスと代替した設定パスを持ち、後続の下部パネルでも共有できる。
- 代替起動の注意はシェル出力より先に表示ストリームへ流す。環境変数 `SHELL` は実際の起動パスで上書きする。
- エージェントの起動経路には適用しない。文字サイズの行は移さない。

## 理由

要件 BS-1〜BS-6・BS-8 に従い、タブと将来の下部パネルで同じ解決規則を使う。起動直前に読むことで実行中のシェルは変更せず、設定後の再起動に反映する。

## 結果

任意パスの入力は実行可能なファイルだけ保存する。起動前に削除された場合はログインシェルへ代替し、呼び出し側は代替の有無を取得できる。ログインシェル取得不能・空文字の場合は従来どおり `/bin/zsh` とする。

## 補足（2026-10-14、独立レビューへの対応）

存在確認後に設定シェルが消え、PTY 起動が ENOENT で失敗した場合も、設定シェルの不存在を再確認してシステムの既定で一度だけ再試行する。他の起動エラーと代替先の失敗は呼び出し側へ返す。初回起動では注意を最初の行に出し、再起動では注意の前にも CRLF を入れて旧プロンプトと分離する。既存の出力は保持する。
