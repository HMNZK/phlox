# 0194: ファイルツリーの Return を名前変更に使う

## 決定

- 要件 FO-1〜FO-11 に従い、右サイドバーのツリーで作成・名前変更・ゴミ箱への移動を扱う。
- Return は名前変更の開始と入力の確定に使う。ファイルを開く操作はクリックと ⌘↓、フォルダの開閉はクリックと左右キーにする。標準の右クリックメニューに Return は登録しない。
- 名前入力を行内に置き、拡張子より前を選択する。新規は対象フォルダの空名の並び位置で入力し、確定後に並べ直す。
- 確認は既存の未保存確認と同じシートの NSAlert とする。ゴミ箱から戻せる操作は軽い形にし、未保存の変更を失う場合だけ破壊的表示とキャンセル既定にする。確認内で ⌘⌫ は実行しない。
- ファイルタブの文書実体を再利用し、名前変更後も下書き・ブロック編集・Undoを保持する。

## 理由

2026-10-14 のユーザー決定（FO-3）に合わせて Finder と同じキー操作にする。従来の Return で開く方式を置き換え、作成・名前変更・削除をキーボードで完結できるようにする。既存のファイルアクセスとタブ管理を共有して、別の編集バッファを作らない。

## 結果

従来のツリーの Return 操作は変わる。複数選択・移動・複製・アプリ内のゴミ箱取り消しは追加しない。名前の衝突や操作失敗でディスクを上書きせず、対象フォルダを読み直す。

## 2026-10-14 レビュー後の補足

決定は維持する。削除は参照先の現在のパスを移動直前に包含検査し、確認後の保存待ちで対象文書・タブや未保存状態が変われば再確認する。既存の文書ロックを使い、全ウィンドウの排他制御は足さない。包含検査から OS の移動呼び出しまでの外部移動の時間差は残り、コードの `ponytail:` コメントと現行 architecture に限界を記す。

復元タブの衝突、ブロック欄の編集不可、選択行の読み上げ属性も既存の型で扱う。モック差分の修正は行内入力・誤り・失敗の帯・確認本文と札に限定し、NSAlert 標準の破壊的ボタンの見た目は保つ。
