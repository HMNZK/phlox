# 0197: 下部ターミナルの表示器をプロジェクトごとに1つにする

> **追記（2026-10-15）**: `keyDown` の `open` 化は元に戻した。Vendor の差分は 2 メソッドになった（ADR 0200）。

## 決定

ADR 0196 の共有表示器の決定を置き換える。`ProjectTerminalStore` はプロジェクトごとに `TerminalPanelSession` を1つ保持し、子タブと同じ `TerminalCoordinator`・表示器・出力購読を使う。複数ウィンドウで同じプロジェクトを表示した場合も、子タブと同じ単一の表示器の再アタッチに従う。同時表示のための仕組みは設けない。開閉状態・フォーカス復帰先は引き続きウィンドウ単位で保持する。

SwiftTerm の共有エンジン・表示更新・サイズ所有者の追加を除去し、`softReset` の既存挙動を復元する。Vendor に残す変更は `becomeFirstResponder`・`resignFirstResponder`・`keyDown` の `open` 化だけとする。前2つは入力先の取得・解除をアプリ側へ通知するため、後者は Control 単独のキーが `keyDown` に直接渡されても ⌃` をシェルより先に標準メニューへ渡すために必要。処理内容は Vendor では変更しない。

端末のアクセシビリティはアプリ側の `IMETerminalView` が `.textArea` と現在見えている行の値を公開する。全 scrollback の走査・保存は行わない。見出しは下部パネル・シェル・場所・入力先の状態を日英で公開し、操作ボタンを別の要素として保つ。端末に書く失敗案内も `AppLocalizedString` で翻訳する。

## 理由

独立レビューで共有表示器の色・カーソル同期漏れと、共有のための全 macOS 端末へのリセット変更が指摘された。既存の子タブと同じ所有・表示方式なら、同期用の状態と Vendor 拡張が不要になる。2026-10-14 の統括役の判断に従い、複数ウィンドウの同時表示より構造の簡潔さを優先する。

## 検証方針

Swift Testing で単一セッションの所有・出力保持・再アタッチ、メニュー優先と Esc 通過、表示範囲だけのアクセシビリティ値、日英の失敗案内・見出しを検査する。下部パネルだけの画面外画像を最後に生成する。画像の自動判定の追加は今回の対象外とし、統括役が目視比較する。
