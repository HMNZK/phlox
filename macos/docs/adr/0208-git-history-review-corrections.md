# ADR 0208: Git 履歴の利用順と追加取得を要件へ合わせる

## 文脈

ADR 0206 の最終コミット時刻順とグラフ200件の上限は、GW-8 の最近使った順とグラフ見本の続きを読むを満たさない。

## 決定

- ローカルブランチは HEAD reflog の `checkout: moving from … to …` の切り替え先を新しい順に採用する。重複・存在しないブランチは除き、記録がないブランチを最終コミット時刻順で後置する。
- グラフは200件ずつ取得し、末尾の「続きを読む」で追加する。追加後は取得済み全件からレーンを再計算する。更新時も取得済み件数を維持する。
- View のモデル交換時に保存済みの区画開閉を新モデルへ同期する。閉じた区画は引き続き開いたとき最新を読む。
- コミット／スタッシュのバイナリ判定は差分本文ではなく Git の `--numstat` の `-\t-` を用いる。
- スタッシュ確認には操作名、対象の重複しないファイル数、未追跡件数、HEADへ戻すことを表示する。
- リモートは個別に開閉する（origin は既定で開く）。取得時刻は `git rev-parse --git-path FETCH_HEAD` で解決したファイルの更新時刻を使い、ファイルがなければ省略する。追跡先はローカル参照の upstream から取得する。

## 理由と結果

改名後の利用順と外部コミット後の追加取得は [ADR 0209](0209-git-batch-order-and-history-continuity.md) で補う。

既存の読み取りサービス、スクロール、確認部品を再利用する。取得時刻はリモート別の通信成功時刻ではなく、リポジトリの最後の取得時刻である。自動取得は追加しない。
