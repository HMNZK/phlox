# ADR 0209: Git の一括処理順と履歴の連続性を保つ

## 文脈

ファイルを同名ディレクトリへ置き換えると、一括ステージ／解除が途中で失敗する。グラフの取得位置を件数でずらす方式は外部コミット後に重複を生み、切り替え先の名前だけでは改名後のブランチへ利用順を引き継げない。

## 決定

- ステージは対象全体の削除を先に行い、その後に追加する。解除は対象全体を HEAD にない項目の削除と HEAD の完全一致項目の復元に分け、削除を先に、復元を子から親へ行う。再帰削除と `update-index --replace` は使わず、選択外の子と衝突する復元は拒否する。
- ステージ／解除は失敗時も共有モデルの一覧を読み直し、Git の失敗理由を残す。途中で変わった index を画面に反映する。
- グラフの続きを読むは表示件数に200件を足し、必要件数と次の1件を先頭から読み直す。取得結果から一覧とレーンを置き換え、外部の履歴変更でページ境界が移っても連結による重複を生まない。
- ローカルブランチは現在のブランチを先頭にする。HEAD reflog の切り替え先を、各ローカル参照の reflog にある `Branch: renamed refs/heads/<old> to refs/heads/<new>` の記録から現在名へ引き継ぐ。連続改名も引き継ぎ、現在存在する同名ブランチを別ブランチへ読み替えない。記録がないものの最終コミット時刻順は維持する。

## 理由と結果

既存の完全一致操作と読み取り経路を再利用し、新たな状態保存を設けない。グラフは追加時の読取件数が増えるが、先端固定やページ管理の追加を避ける。改名の引き継ぎは Git に残る reflog の範囲に限る。

## 既知の制限（2026-10-15 ユーザー判断で受け入れ）

旧名を別ブランチが再利用してから再度改名した場合、旧名の対応を一つだけ持つ現行実装は利用履歴を混同する。`GitHistoryWorkflowTests.GTWRegression_改名前の名前を再利用しても利用順を混同しない` を追加し、修正前に失敗を確認した。

`reflog show --all` の出力を単純に一度走査する修正案も検証したが、同一秒の作成・切り替えの並びで既存の改名テストに失敗したため採用していない。レビュー案は改名だけ未来時刻を指定しており、操作順と記録時刻も一致しない。reflog からは、同じ名前を使った別のブランチを確実に見分けられない（同一秒の記録や、同じコミットを指す場合）。影響は一覧の並び順だけでデータには及ばないため、既知の制限として残す（2026-10-15 ユーザー判断）。テストは `withKnownIssue` で包み、直ったら気づける形にしている。
