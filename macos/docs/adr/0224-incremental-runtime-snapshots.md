# ADR 0224: 既知の履歴を共有して状態の変更部分を転送する

履歴全体の繰り返し転送を減らし、入力と送信に必要なメイン処理を空ける。[問題定義](../specs/large-session-responsiveness.md)の通信方式を実装した。固定した大履歴で転送削減、実アプリの入力反映と送信、内容の完全性を確認した。実IMEとキー単位の遅延は未測定で、現在のReleaseへの反映は別に扱う。

## 決定する形

通信境界だけに差分を置き、画面と実行側の状態モデルには完全な`DashboardRuntimeSnapshot`を渡す。新handshakeのoptional capabilityで対応を確認し、新しい取得経路を使う。旧GUIの`/snapshot`と旧サービスへの接続は維持する。

更新応答は`sequence`、任意の`baseSequence`、軽い完全状態と本文patchを持つ。本文patchは共有する先頭の項目数と、その後を置き換える配列。変更なし、末尾追加、途中変更、切り詰めを同じ規則で表す。子エージェントの本文も同じ形にする。rawイベントは最大500件で先頭が落ちるため、基準の末尾と新しい先頭の共通部分を残し、追加分だけを送る。未変更のスキル、履歴候補と要約は基準状態を再利用する。部分状態を既存GUIへ露出しない。

MainActorでは値型の状態とsequenceを同時に確定する。比較とJSON変換は別の実行場所へ渡し、通信受付actorの同期処理にも置かない。GUIは要求開始時の基準を固定し、復号と完全状態への復元を別Taskで行う。既存のsequence破棄と鮮度判定を通した状態だけを適用する。

サーバーの保持は直近2完全状態に制限する。未知の基準は完全応答へ戻す。prefixと残すログ件数の範囲、sessionとexecution、重複patch、子の存在を検証する。表示用の`ChatItem.==`は時刻を無視するため、通信の比較は時刻とUTF-8表現も含める。コマンド後の状態反映契約は維持する。ただし[ADR0225](0225-send-acceptance-without-snapshot-wait.md)の送信受付は例外とし、`.send`と`.sendControlSkill`の`.accepted`だけは画面同期を待たずに返す。表示は既存の定期同期で反映する。実装で決めるwire型・上限の詳細はテストと突合して追記する。

## 比較した案

| 案 | 判断 |
| --- | --- |
| 既知状態に対する本文patch | 採用候補。既存の完全状態と1往復の取得を残せる。末尾出力で全本文を送り直さない。 |
| 軽量一覧とversion付き内容の別取得 | 保留。二段階取得と内容キャッシュ退去の契約が増える。 |
| 不変revisionの本文だけ省略 | 棄却。実行中の末尾更新のたびに大きい本文を再送する。 |
| JSON変換の実行場所だけ移動 | 単独では採用しない。全量変換・転送を残し、ADR0223でも体感改善を確認できなかった。 |

2案を同じ親モデルの別コンテキストで検討した。異なるモデル系列によるcross-judgeはモデル設定がないため未実施。比較軸は正しい復元、変更時の転送量、旧版互換、同時実行と取消、境界の単純さ。独立した最終レビューと実測を別に行う。

## 検証状態

標準qualityはexit 0。Mac19パッケージ、iOS695件とlint・build、必須fake13件を実行した。既定の任意skipとADR0209の既知問題1件を維持し、無条件の全検査成功とはしない。AppBootstrapの新規18件は成功した。固有署名Debugの大履歴受入、画面からの送信・中断、保存一致、中断→再開の受入も成功した。

同じ2,200項目・3MiB超のfixtureで、完全応答5,385,891byteと変更なし差分3,407byteを交互に5回確認した。末尾更新は4,396byte。これらは転送量であり、入力遅延の改善率ではない。ADR0223の過去の測定値は流用しない。正確な条件・失敗・警告・終了拒否1回の原因未確定は[作業記録](../delivery/0224-large-session-responsiveness-worklog.md)に残す。
