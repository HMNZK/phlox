# ADR 0226: エージェント状態カードは会話ログから組み立て、タスクの登録は強制しない

日付: 2026-11-06。状態: 採用（保存の方式は暫定。ユーザーは「とりあえず」で承認）。

要件は [specs/agent-status-card.md](../specs/agent-status-card.md)、設計は [specs/agent-status-card-design.md](../specs/agent-status-card-design.md)。

## 文脈

チャットの会話ログに、入力 1 回ごとのカードを出すことになった。カードは、エージェントのタスク（Claude の Tasks・TodoWrite、Codex の計画）の下に、作業（ツールの実行）を振り分けて見せる。

今の Phlox には、この表示に必要な情報が 3 つ欠けている。

- どの作業がどのタスクのためか
- 作業がいつ終わったか
- 各タスクがいつ進行中になり、いつ完了したか

タスクリストはセッション全体で 1 枚（固定 id `task-list`）を上書きしているので、経過が残らない。

要件を詰める途中で、次の 2 つを順に検討した。

- エージェントにタスクの登録を強制する案（起動時の指示と、進行中のタスクが無い間はツールの使用を PreToolUse で拒否する関所）
- 並列のタスクはサブエージェントに任せることを強制する案

## 決定

1. **タスクの登録は強制しない。** Phlox は、エージェントが自分で登録したタスクと実際の作業を観察して、整理して見せるだけにする。起動時の指示も、ツールの拒否も入れない。指示の自動注入を撤去した ADR 0035 は維持する。タスクの無い入力では、カードは作業の一覧として出す。
2. **作業は、会話ログ上で直前にあるタスクの状態から振り分ける。** 進行中のタスクがちょうど 1 件ならそのタスクに属させる。0 件・2 件以上なら「タスク外の作業」にする。時刻ではなく位置で決める。書き換えた item は開始時刻を保ち、サブエージェントの印は時刻を持たないためである。
3. **カードは保存しない。会話ログから導く。** [ADR 0231](0231-semantic-chat-read-model.md) により、実行サービスは再構築可能な読取索引を増分維持し、ページ分割前に意味を確定する。 保存するのは会話ログだけにする。タスクの変化は、1 枚の上書きをやめて、スナップショットを会話ログに追記する。作業の終了時刻と、ターンの終わり方（完了・中断・エラー・次の入力へ続く）は、既存の item に省略可能なフィールドとして足す。
4. **`ChatItem` に新しい case は足さない。** 古い版のアプリは知らない case で会話全体を読めなくなり、以後の保存も止まるためである。省略可能なフィールドなら、古い版は無視して読める。古い版ではタスクのカードが更新の回数だけ並ぶが、これは許容する。

## 見送った案

- **タスクの登録とサブエージェントでの並列を、指示と関所で強制する。** 「すべての作業がどれかのタスクに属する」を保証でき、振り分けに嘘が出ない。しかし、次の理由でユーザーが撤回した。
  - 拒否のたびに理由がエージェントの文脈に積み上がる（コンテキストの汚染）。
  - 短い依頼でも毎回タスク登録の 1 手が増え、遅くなる。
  - エージェントの動き方を縛り、利便性を損なう。
- **並列中の作業を、時間の範囲で全部の進行中タスクに出す。** 同じ作業が複数のタスクの下に出て、表示に誤りが混ざる。
- **カード用の情報を補助ファイル（`.display.json` の `ChatDisplayState`）に置く。** 会話ログの形式を変えずに済み、ターン単位の情報を置く前例もある。しかし、正本が会話ログと補助ファイルの 2 つになる。巻き戻しや保存の失敗で両者が食い違いうる。D14 を見直すときの第一候補として残す。
- **`ChatItem` に `.toolCall` や `.turnEnd` の case を新設する。** 型としては素直だが、決定 4 の理由で古い版との互換を壊す。

## 影響

- 会話ログに、タスクの更新の回数だけスナップショットが増える。1 回の入力で数十件になりうるが、1 件は小さい。
- タスクを使わない、または並行で進めるエージェントでは、作業の多くが「タスク外の作業」になる。整理の度合いはエージェント次第になる。
- 巻き戻しでタスクが復活しないよう、`ClaudeChatClient.resetConversation` でタスクの手元の記憶を空にする必要がある（今のコードにある不具合）。
- Codex の計画は、末尾の `CodexSessionSurface` からカードへ移る。今は 2 つの経路で表示されている。
