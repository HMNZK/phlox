# ADR 0230: 起動状態とセッション内容を分けて取得する

## 背景

画面の起動と定期更新は、全セッションの完全な状態を取得する。本文、端末表示、子エージェントの本文、履歴、rawイベントを含む状態が64 MiBを超えると、実行サービスがHTTP 413を返して画面が起動しない。これは保存済みデータが増えるだけで再発する。通信を分割しても、[ADR 0224](0224-incremental-runtime-snapshots.md)が定めた復元後の完全状態の上限が残る。

## 決定

起動と定期更新は容量を制限した状態一覧を使う。各セッションの識別子、実行世代、状態、内容の改訂番号、短い表示文、未回答の承認と質問を送る。本文、端末表示、子エージェント本文、履歴一覧、項目別使用量、rawイベントは送らない。実行サービスは一覧を専用の処理で組み立て、完全状態を先に生成しない。可変長の値には項目ごとの上限と省略の印を設け、応答全体の容量も検査する。

表示中のチャット内容は、認証済みの別要求で末尾から符号化後4 MiB以内のページとして取得する。複数の窓がある場合は各窓の表示対象を合算する。古い内容は必要時に遡って取得する。応答にはセッションID、実行世代、改訂番号、範囲、続きの位置を含める。末尾の更新は改訂番号で照合する。過去ページと巨大項目は、実行世代、項目ID、内容のハッシュで照合し、末尾への追記だけで取得を無効にしない。「未取得」と「空」は別の状態とする。端末表示は表示中の各セッションから個別に取得し、取得時の表示改訂を照合して既存形式の64 MiB上限を各応答に適用する。一覧と内容の読み取りには別の待機枠を設ける。

未回答の承認と質問は本文ページに混ぜない。本文をまだ取得していないタイルでも、状態と操作が正しく出るようにする。承認のコマンドや権限説明が省略されているときは、全文を表示するまで承認操作を受け付けない。ファイルの最終変更元は保存競合時に実行サービスが保持する会話を調べ、名前だけ画面へ返す。照会に失敗した場合も競合を明示する。入力履歴、巻き戻し、書き出しは未取得ページを完全な本文として扱わない。

履歴カード、スキル選択、子エージェントの札に必要な補助情報は、表示中のチャットに限って容量制限付きで取得する。現行GUIから子エージェント本文を開く経路はなく、ControlServerは実行側の本文を直接読む。rawイベントと計画状態にも現行GUIの表示経路はないため、起動用一覧には載せない。

一つの項目が応答上限を超える場合は、欠落を明示する項目を返す。全文は実行世代、項目ID、内容のハッシュを指定した容量制限付き要求で取得する。別の退避ファイルは作らない。

handshakeの機能フラグで新しい取得経路を選ぶ。旧サービスとの互換経路は残す。ただし、既に413を返す旧サービスからは互換経路でも回復できない。新しい実行サービスへ切り替える必要がある。

## 比較した案

完全な状態を複数応答に分ける案は採らない。画面が全量を保持し続け、保存量の増加が起動と定期更新に影響する。上限を128 MiBに上げる案も同じ理由で採らない。

## 検証

合計64 MiBを超える保存済み本文を持つ隔離環境で、画面の起動と定期更新を確認する。本文未取得のセッションの承認と質問、改訂中の古いページの破棄、単一の巨大項目の全文取得、端末表示、入力履歴、書き出し、ファイル変更元を確認する。稼働中の実行サービスは診断のために停止しない。
