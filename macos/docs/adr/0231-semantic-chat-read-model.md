# 0231: 会話の意味を実行サービスで確定し、本文と入力履歴を有限取得する

## 問題と変更範囲

本文の末尾ページに入力が含まれないと、画面がカードを作れず個別の思考・コマンドへ戻る。入力履歴も取得済み本文から作り、全文取得まで入口を隠している。同じ問題は履歴への移動、入力の呼び戻し、Esc の巻戻し候補、狭いグリッドの見出しにも及ぶ。

ADR 0229 §6 の「全体を組み立てた結果の一部」を IPC のページ境界にも適用する。ADR 0226 の会話ログだけを保存する方針は維持し、「表示のたびに組み立てる」は再構築可能な派生索引の増分維持へ改める。新しい永続 DB や副ファイルは作らない。

## 決定

既存の SessionRuntimeContentRequest/Response に、会話ブロック、カード行、行内作業、集約作業の元項目、入力履歴、入力 ID 周辺の直接取得を追加する。カードの起点は backend の turn ID ではなく実在する userMessageID とする。

集約作業の手動ページは安定した先頭項目IDから順向きに取得できる。構造変更で移動した旧indexを新しい版へ付け替えて再送しない。`chatActionItemsFrom` は既存の詳細ページと続きカーソルを再利用し、所属しない項目は `notFound` とする。これは未公開のread-model初回導入の契約に含め、未対応サービスへ送らない。

正本のログを持つ実行サービスが、入力区間、カードの成立、タスクの所属・順序、集約作業 ID、開始・終了、最終返答のカード内外を確定する。ローカル経路と同じ Builder の規則を使い、画面は取得済み断片を再分類しない。表示文字列・色・開閉と可視要素の時計は画面に残す。

各階層を件数と符号化後バイト数で制限する。巨大な 1 入力、10 万行、10 万作業、巨大な 1 発言でも区間全件を返さない。本文は短い表示と元項目参照に分け、全文は開く・コピー・呼び戻し等の明示操作時だけ既存 itemChunk で取得する。入力履歴のプレビューを元の入力として挿入しない。

カーソルは実行・対象・構造の版・安定した境界 ID を検証する。構造の版と本文 digest を分け、本文の stream 更新だけで無関係な過去ページを捨てない。巻戻し・復元では影響範囲を無効化する。古い応答は混ぜず、整合した直前表示と再試行手段を保持する。継続 stream 中にも取得を完了できることを検証する。

timeline と入力履歴はそれぞれ構造版を持つ。既存の順序・所属・種別を保つ末尾追加では版を維持し、過去の構造変更では対応する版を進める。変更区間の再構築時にその区間のキーだけを比較し、通常の追加ごとに全ログを走査しない。この版は本文の同時刻スナップショットを表さず、本文の新旧は項目の参照とdigestで検証する。

索引は本文のコピーではなく ID・範囲・集約値を保持する。通常の追記と項目置換は影響区間だけを更新する。変更のない要求で全ログの走査や JSON prefix digest の計算をしない。連続 Read/Edit/Search の集約時に配列を毎回コピー・全再走査しない。初回構築も main actor を長時間占有しない。

入力履歴は本文から独立して最新 12 本を取得し、一覧は追加取得する。選択した入力へ直接取得で移動し、間の本文は読み込まない。表示中カードの入力 ID から現在位置を決める。画面の本文・詳細キャッシュは両端の件数・バイト予算で制限し、開閉状態とスクロールの目印は安定 ID で保つ。非 Lazy VStack と ADR 0030 の規則を維持する。

カードには当該カードの不変なキャッシュ値を渡し、内容・開閉・移動先・エラーが変わったカードを再評価する。表示に影響しない読取制御の更新と、他カードのキャッシュ更新はカード本文の再計算を起こさない。等価判定で表示変更を取りこぼさないことを回帰検査する。

概要の未回答質問と最後の返答の候補位置も、既存の追記・項目変更の情報から更新する。質問や返答がない会話で、概要を作るたびに全ログを走査しない。件数・先頭16件の順序・質問の状態・承認を含む識別値・空白プレビューを飛ばす既存の規則を維持し、巻戻し・復元・実行切替でも正本と一致させる。元ログを持つ側の待機判定にも同じ質問候補を使い、画面側の取得済み本文と未回答項目の合成順序は変更しない。再構築可能な派生値とし、会話本文・保存形式・通信形式は増やさない。

背景更新は取得済みの範囲を有限ページで組み直す。ページ・初期行・変更されたカードの既取得詳細をローカルに揃え、版と取得先を検証してから一括適用する。途中で詳細を空へ置換せず、失敗時は整合した旧表示と再試行手段を残す。未取得の閉じた詳細は取得しない。手動の行・詳細位置は実際の境界IDまたは要求カーソルで保持し、取得中の新しい手動操作・明示移動を古い応答で上書きしない。

既存ページの背景更新では、最新入力履歴の取得結果も最後の一回の表示更新へ含める。読取制御の世代と背景の待機状態は非観測の制御状態で管理する。初回・明示移動・履歴ページ操作の進捗表示は維持する。履歴の取得失敗は成功した本文を捨てず、旧履歴と履歴専用のエラーを同じ更新で示す。途中の手動履歴操作は現在の選択を優先し、実行・epoch・構造版をまたぐ古い応答を適用しない。本文の版だけで入力履歴の同値を推測しない。

通信の待機列・同一要求の共有・移動の完了待ちは、表示値とは別の非観測の制御状態へ置く。制御状態は表示モデルの epoch ごとに作り直し、表示ページとキャッシュの atomic な値置換を保つ。通信制御だけの更新で会話全体の再描画を起こさない。

カードの描画は入力ごとの不変なキャッシュ値を受け取り、同じ表示値のカードは等価境界で更新を止める。詳細の版だけでなくエラー・手動の表示範囲・移動要求・操作先の変更も比較し、別カードの取得完了が全カードの描画を無効化しない。

カード行を有限化しても進行中の行への直接移動と先頭への復帰を可能にする。行内作業の初回は従来の最新 30 件を維持し、追加表示で古い側を取得する。作業の指定先へ直接移動した場合も前後へ進め、最新へ戻れる。

handshake に任意の対応機能を追加する。旧サービスへ未知 target を送らず、新機能未対応と実行終了後のサービス更新が必要なことを明示したうえで従来表示を維持する。新しいカード・履歴の保証は対応サービスに限る。GUI更新や再接続だけではlease保持中の旧サービスを置換しないため、未対応を理由に本文全体を利用不能にはしない。使用中のサービスを終了・差替えしない。再接続時も能力を判定する。無停止のサービス更新エンジンは本変更へ追加しない。

## 受入条件と計測（実装前に固定）

- 全件から定まる ID・所属・順序・状態・時刻・最終返答位置が、ページ分割と取得順に依存しない。小ログ全切断、大ログ固定 seed、タスク変更・復帰・削除・並替え・追加入力・巻戻し・復元・遅着を検査する。
- 全応答に実 encoded bytes と件数の上限を検査する。巨大本文の表示と履歴参照で全文チャンクを要求しない。
- 本文未取得でも履歴入口・最新目盛り・古い入力への直接移動、全文による呼び戻しと巻戻しが成立する。
- 既存 workload の描画予算は ADR 0229（遡り 200ms・追加 50ms・ジャンプ 200ms）を維持する。
- 新しい 10 万項目 workload は cold 構築と warmed query を分ける。warm 応答・最新追加・本文置換・最古入力への索引取得は中央値 50ms 以下を目標とし、超過は原因と対応を記録し完了扱いしない。初回構築は非同期化し、画面の応答を止めない。
- Release の修正前後を最低 5 回交互に測り中央値・範囲、返却件数・bytes・失敗数・メモリを残す。処理を省いた速さを成功に数えない。コア数・負荷を記録し、他者のプロセスは止めない。
- 9 セッション同時表示のグリッドと隔離した実アプリで長い会話、カード展開、履歴一覧・ジャンプ・末尾復帰・再接続を確認し、見本と比較する。API テストだけを画面の成功と扱わない。
