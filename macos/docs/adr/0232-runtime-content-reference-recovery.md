# 0232: 本文参照の失効と取得結果の寿命を通信後も保持する

## 問題

取得済みのタスク行が更新で消えると、実行サービスの `notFound` が HTTP 400 に変換され、画面では `invalidRequest` になる。ADR 0231 の消失を扱う復旧処理へ届かず、本文更新が失敗し続ける。

古い取得の成功・失敗が新しい表示へ適用され、手動の再試行が成功してもエラーが残る。カードのない集約作業では構造版が固定され、発行済み参照の失効を表せない。

## 決定

本文取得の `notFound`、`staleContent`、`invalidRequest` をそれぞれ HTTP 404、412、400 として往復させる。成功応答・永続形式・接続プロトコル版は変えない。旧サービスの 400 を表示文言から推測しない。

参照は実行、対象、構造版、境界 ID で検証する。対象と負の位置を検査し、構造版を確認してから現在の範囲と境界を検査する。集約作業にも構造版を持たせ、範囲の縮小・並替え・置換で進める。純粋な末尾追加と本文更新では有効な過去の境界を保持する。

カードの取得結果とエラーは ViewModel が確定する。対象別の操作世代を非観測の制御状態に置き、古い実行・画面・操作の結果を捨てる。本文の版やキャッシュ差替えだけで要求を失効させない。対応する新しい取得が成功したときだけ、その対象のエラーを消す。View 側の成功・失敗の二重書込みは除く。

一括公開する背景更新と、カード外の集約作業の既存の局所取得は維持する。消失した子項目を除外する前に、同じ取引で親の存在と実行を有限取得で再確認する。親の消失を子の削除として成功へ変換しない。

古い参照からは既存の内容再同期へ一度だけ接続する。復旧中の再失効では直前表示を保ち、即時再予約をせず次の定期更新を待つ。過去表示の起点が消えた背景更新では、末尾ページと追従状態を同時に確定する。明示した不存在の移動先は成功扱いしない。

## 比較と検証

View 側に世代付き `perform` を残す案は、loader 側にも同じ検査と適用済み結果を渡す必要があり、責任が重複する。カードはモデル側の既存取得入口へ集約する。カード外の局所キャッシュは移管せず、既存の取得世代を生かす。設計候補は同一モデルの独立した二文脈で比較した。

全文再取得、全キャッシュ破棄、無制限再試行、推測によるタスク ID の同一視は採らない。単一要求の件数・バイト上限と、整合した旧表示を残す方針を維持する。

実 HTTP のエラー往復、実発行カーソルの縮小、保留した旧成功・失敗、連続本文更新、親削除、再試行、隔離アプリでのタスク変更を検証する。詳細は [修正計画](../delivery/body-content-recovery-plan.md)。検証結果は実走後に作業記録へ追記する。

旧常駐サービスには画面更新だけでは修正保証が届かない。コードの完成と利用環境での解消を区別し、利用中サービスの停止・置換はこの修正作業に含めない。
