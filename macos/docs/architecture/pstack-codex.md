# pstack の Codex 向け変換

Phlox の Codex セッションから pstack を選択し、調査・実装・検証の手順を利用する。Phlox 本体への専用機能の追加は、既存の `skills/list` と native skill input で不足した場合だけ行う。

## 構成と実装契約

- `integrations/pstack-codex/` に固定した上流情報、変換処理、Codex 向けの対応表、生成器のテストを置く。
- 上流のコミットと内容のハッシュを固定する。生成処理は上流を編集せず、固定内容と異なれば失敗する。
- スキル・参考資料・付属スクリプト・ライセンスを保つ。各スキルと子エージェントの入口に Codex 対応表の参照を挿入する。設定用スキルは Codex 専用版にする。
- 8,000 bytes を超えるスキルは本文を同じフォルダの `workflow.md` に保持し、入口から対応表と全文を読む。実 Codex で確認した長い本文の切り詰めを防ぎ、相対参照は維持する。
- 設定と生成物を分離する。Codex の設定ファイルに役割設定を混ぜず、専用 JSON をスキルから明示的に読む。
- 出力はローカルマーケットプレイスに登録できる Codex プラグイン。既存スキルと同名でも選択できるよう、名前とパスで識別する Phlox の既存機能を使う。

## 対応範囲

| 上流機能 | Codex 版 |
| --- | --- |
| 原則・作業手順・参考資料 | 保持する |
| Task / AskQuestion / todo | 利用中の Codex が公開するツールへ対応させる |
| poteto-agent / comment-sicko | 原本の役割指示を渡した Codex 子エージェントを使う |
| モデル・推論設定 | 既定は親から継承。明示設定は利用可能性を確認する |
| 異なるモデルによる相互レビュー | Codex 内で実際に利用できるモデルだけ使う。同一モデルで代替した場合は多モデル検証と呼ばない |
| Cursor の会話履歴 | 現在の会話の履歴を特定できる場合のみ使用。無関係な履歴は走査しない |
| cursor-team-kit の deslop / control-* | 必要な検査・操作を Codex の利用可能な手段へ明示的に対応させる。実行不能なら未検証とする |
| Cursor Automations / Grok Bot UI / cloud agent 専用操作 | 非対応。工程全体が依存する場合は停止し、成功扱いしない |
| 外部送信・コミット・マージ | 上流の自律実行指示よりユーザー・作業環境の権限と承認条件を優先する |

## 検証計画と完了条件

1. 生成物の再現性、参照整合性、上流変更の検出、既存出力の保護、設定の妥当性を自動テストで検査する。
2. 隔離した Codex home と作業ディレクトリでプラグイン一覧・`skills/list` に期待したスキルが現れることを確認する。
3. 読み取り専用調査、小さな不具合修正とテスト、子エージェントによるレビューを実行し、ツール履歴と成果物で確認する。
4. Phlox でスキル候補を選び、native input で送信した会話の結果を確認する。XCUITest は使わない。
5. 導入・更新・削除の手順と検証範囲を保存する。未実施・未対応を完了扱いしない。

テストは `~/.agents/scripts/compact-test` を経由する。使い捨ての出力とプロセス記録は作業 worktree の `.verification/pstack-codex/` にまとめる。Phlox 本体を変更した場合は、その対象パッケージを `macos/scripts/run-swift-tests.sh` で検査する。

## Phlox の更新通知と選択の保護

実機の Release と専用 Debug の両方で、選択成功直後の更新通知によって native skill input の送信が拒否された。通知は変更の可能性を示すため、通知だけを無視しない。

選択時にスキルのファイル一式の内容・相対パス・実行属性の SHA-256 を記録し、候補の再取得後に同じメタデータ・同じ内容を確認できた場合だけ選択を保持する。プラグインは共有参照もあるためプラグイン全体を対象にする。単独スキルはそのスキルフォルダを対象にする。内容は64KiBずつ読み、合計サイズでは制限しない。旧実装は合計8MiBを超えると照合できず、内容が変わっていなくても更新通知のたびに再選択を要求した。ファイルの変更・欠損、シンボリックリンク、読み取りエラー、4,096項目の上限超過、一覧取得エラーは従来どおり再選択を要求する。確認できないファイルを想像で同一扱いしない。

## 検証範囲と制約

- Codex CLI 0.163.0 で導入・59 スキルの検出、隔離した作業ディレクトリで調査・不具合修正・子エージェントレビューを手元で実行した。これらは全ワークフローの同等性の検査ではない。
- 専用 Debug の UI で候補選択・native input の送信・対応表を読んだ応答を確認した。常用 Release のバイナリは更新していない。
- 同じモデルでも別コンテキストのレビューは可能だが、異なるモデル同士のレビューとの同等性は主張しない。
- Bun を使う上流補助スクリプトは、利用する場合に固定ロックファイルから依存を準備し、その検査を実行する。スキルの読み込みだけでは実行済みと扱わない。
