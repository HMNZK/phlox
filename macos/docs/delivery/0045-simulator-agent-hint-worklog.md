# シミュレーターをエージェントに伝える

## 依頼

「Phlox からエージェントに指示するときに、Phlox で表示中のシミュレーターを簡単に指定できるようにしたい」（2026-10-06）。

## 決めたこと

- 方式: シミュレーターの帯のボタンで、端末を表す 1 行の文をそのセッションの入力欄に入れる（ユーザーが「入力欄に差し込む」を選択）。
  - 比べた案: エージェントが Phlox に表示中の端末を問い合わせるコマンド。指示は短くなるが、エージェントにそのコマンドを教える必要があり、作る量も多い。必要になったら足す。
- 仕様: `specs/embedded-ios-simulator.md` の FR-10・§3.8・§5・§6。
- ADR は書かない。ボタン 1 つで、既存の方針（ADR 0179 のシミュレーター表示）を変えないため。
- 入れる文: `対象の iOS シミュレーター: <端末名>（<iOS の版>、UDID <UDID>）。Phlox で表示中の端末です。`
  - UDID があれば、エージェントは `xcodebuild -destination 'id=<UDID>'`・`xcrun simctl … <UDID>` で端末を特定できる。
  - 状態（起動済み等）は入れない。送るまでに変わりうるため。
- 入れ先:
  - チャット型: 下書きの末尾に足す（空でなければ改行してから）。入力欄にフォーカスとキャレットを移す。`sendText(submit: false)` は画面に見えない保留文に入るので使わない。
  - ターミナル型: `sendInput` で文字だけを書き込む。Enter は送らない。`sendText` はターンの状態を書き換えるので使わない。
- 入れたあとは会話のタブを前に出す。分割で出ていればその区画へ移るだけ。

## レビューで直したこと（opus のレビュアー、1 回目 needs_changes → 2 回目 pass）

- 単一表示では、会話のタブへ切り替えたときに入力欄が新しく作られ、フォーカスの要求を取りこぼしていた。セッションごとに「処理済みの要求の番号」（`handledComposerFocusToken`）を持ち、入力欄が作られたときに未処理の要求を引き継ぐようにした。
- 送信の受付待ちの間に入れると、失敗時に戻す本文とぶつかってどちらかが消えた。受付待ちの間は入れず、警告音を鳴らす。
- ターミナル型で許可や質問の回答待ちのときに入れると、文の数字や英字が選択肢のキーとして効くおそれがあった。待機中・実行中だけ入れる。
- 分割中に会話が出ていないと、会話が端末の画面を置き換えた。シミュレーターでない方の区画に出す（`SessionTabLayout.showConversation(keeping:)`）。区画のタップと順序がぶつからないよう、切り替えは同じクリックの処理の後に回す。
- 端末名の改行などの制御文字を除く（`simctl rename` で任意の名前を付けられるため）。
- 資料: architecture・8 Cross Check・仕様の §5 を更新。
- 未対応（低）: 「この会話から戻す」の待ち時間の間に押すと、入れた文が上書きされうる。ターミナル型の状態は CLI の画面と常に一致しない（Codex の質問の検知は画面読み取りで遅れがある）。ターミナル型の状態による制限と「入れられないときはタブを切り替えない」はテストが無い（private メソッドの中）。
