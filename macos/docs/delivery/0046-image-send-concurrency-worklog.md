# 画像送信準備中の同時送信による添付消失の修正

## 問題と設計

画像送信の準備中にControl APIから別の送信が来ると、受付可否の判定前に共有の添付を消してしまう。最初の送信も添付変更として失敗する。

Control APIの入口では、共有の添付を変更する前に画像送信準備中かを検査する。本文のみ・画像付き、確定送信・入力追記のいずれでも、準備中の別送信は専用の「処理中」エラーで拒否する。通常の送信入口でも同じエラーを返す。最初の送信と添付は保持する。日英のエラー文言を追加する。

## 検証計画

既存のCodex設定待ちテスト用クライアントで最初の送信を確実に停止し、その間にControl APIから別の送信を行う。添付と本文が変わらないこと、別送信だけが拒否されること、待ちを解除すると元の画像付き送信が一度だけ成功することを検査する。時間待ちによる再現には頼らない。

SessionFeatureと呼び出し側のControlServer・DashboardFeatureのテスト、macOS Debugビルド、差分の空白検査を実行する。Swiftパッケージテストはcompact-testとrun-swift-tests.shを経由する。独立したmacOS lint・静的解析の設定は未設定。

一般的なiPhone写真の画質・容量の実測はこの同時送信修正とは別の未検証事項として残る。

## 実装と検証結果（2026-10-09）

- Control API入口の添付変更前と通常の送信入口で、準備中の別送信を専用エラーで拒否する。共有状態の変更前にはawaitがなく、MainActor上で元の添付を保持する。
- MessagingServiceは専用の送信結果へ変換し、ControlActionHandlerはHTTP 409と`image send in progress`を返す。日本語の例外文言とmacOSの英訳を追加した。iOSの送信失敗時に現在の入力を保持する既存処理は変更していない。
- 修正前の回帰テストで、4通りの条件すべてに元の添付消失または置き換えを再現した（1テスト・4ケース、10件の失敗）。修正後は成功した。全数実行では、本文のみの通常送信入口も同じ待ち区間で拒否されることを検査した。
- API処理のテストに、専用エラーのHTTPステータスと応答本文の検査を追加した。

実装後に変更差分をまとめて自己レビューした。拒否判定から添付変更まで中断箇所がないこと、本文のみの経路も処理中として返すこと、APIの応答まで専用エラーが保たれることをコードで確認した。この修正差分に対する独立レビューは未実施。

### 失敗・警告と検証の限界

- 初回のDashboardFeature全数実行で、既存のSimulator診断表示テストが「1.5秒以内に診断文言が非表示になりませんでした」で1件失敗した。該当スイート12件の単独再実行と、DashboardFeature本体・実Gitの全数再実行は成功した。期待値・時間制限・テストコードは変更していない。タイミング不安定の根本原因は確定していない。
- 既存の警告としてPTYKitの非推奨init(cString:)、SwiftTermの未使用戻り値、TerminalUIの非Sendableコールバック、DashboardViewのViewBuilder、既存テストのMainActor分離・非推奨アクセシビリティAPI・不要なtry・未使用戻り値が出た。実Gitのテストでは未マージの試験用ブランチ削除拒否がログに出たが、テスト自体は成功した。
- Debugビルドで`No AppIntents.framework dependency found`によるメタデータ抽出スキップの既存警告が出た。
- 実機MacとiPhoneの同時操作、エラー文言の画面上の表示、一般的なカメラ写真の実測は未検証。画像変換・受付制限はこの修正では変更していない。稼働中のReleaseアプリは終了・再起動していない。
- 独立したmacOS lint・静的解析・型チェックは未設定。型検査はSwiftコンパイルに含まれる。iOSは契約資料のみの変更で、iOSのテスト・ビルドは今回の対象外。
