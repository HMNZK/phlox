# コマンド候補の説明を最後まで読む

## 設計（実装前）

スラッシュコマンド候補のうち、選択中の行の説明が表示幅を超える場合だけ横送りする。先頭で1.5秒待ち、毎秒30ptで末尾へ進み、末尾で1.5秒待って先頭に戻る。文字を左へ移動し、文章を先頭から末尾へ読めるようにする。名前、右端の出どころ、行の高さ、候補の確定操作は固定する。短い説明・未選択行・ファイル候補は動かさない。

説明の全文はツールチップとアクセシビリティラベルでも読めるようにする。「視差効果を減らす」が有効な場合は従来の静的表示にする。

## 性能と寿命

選択行にだけAppKitの説明ビューを重ね、Core Animationでその文字レイヤーを動かす。SwiftUIの状態、Timer、TimelineViewを毎フレーム更新しない。文字幅は説明変更時にだけ測定する。幅が変わったときは移動距離を計算し直し、同じ設定の再描画でアニメーションを再作成しない。未接続のビュー、選択解除、候補を閉じる際には停止する。表示幅内に収まる場合はアニメーションを作らない。

Appleの[CAKeyframeAnimation](https://developer.apple.com/documentation/quartzcore/cakeyframeanimation)と[keyTimes](https://developer.apple.com/documentation/quartzcore/cakeyframeanimation/keytimes)の仕様に従い、先頭の待機・一定速度の移動・末尾の待機を1本の繰り返しアニメーションにする。

## 検証計画

- ネイティブビューのテストで、長文の末尾までの移動距離、待機、一定速度、繰り返し、短文の停止、再描画時の継続、幅変更と取り外しによる停止を確認する。
- 実際の候補ポップアップをホストして、選択行だけにアニメーションがあること、選択変更・説明変更・Reduce Motionでの切り替え、全文のアクセシビリティを検査する。
- SessionFeatureとDashboardFeatureの設定済みテストはcompact-testとrun-swift-tests.shを経由して実行する。Debugのビルド・リンクとgit diff --checkを実行する。独立したmacOS lint・静的解析・型チェックは未設定。
- 実ビューを画面外で描画して、ユーザーの見本にある固定列・選択色・行高と比較し、途中と末尾の表示を確認する。性能の実測値は計測できた範囲だけ記載する。

## 状態

初版のDebug実画面で見つかった説明の描画欠落を修正し、関連テストと修正版のDebug画面で検証した。

## 実画面で見つかった描画の修正（実装前）

NSTextFieldを表示幅より広く配置し、そのビューのレイヤーを動かす方法では、実画面で表示範囲外の文字が描画されなかった。画面外のcacheDisplay画像と、文字の移動だけを検査するテストでは、この欠落を検出できなかった。

文字全体をCATextLayerに直接描画し、そのレイヤーを動かして親レイヤーで切り取る方法へ変更する。文字幅の計測と描画用の文字列は説明変更時にだけ更新する。待機・速度・繰り返し・停止の条件は維持する。追加の回帰テストで、初期表示範囲を超えた位置にも文字の画素が描画されることを検査し、最終的には起動したDebug版の実画面でも途中と末尾を確認する。

### 描画方式の変更と検証の限界

全文を持つCATextLayerへ置き換えた。Retina表示の倍率はウィンドウから取得し、表示倍率の変更時に更新する。文字サイズの計測は説明変更時だけ、移動は同じCore Animationで行う。

画素を検査する追加テストは旧NSTextField版でも成功した。layer.render(in:)は画面外の全文を描き直せるため、この検査だけでは実画面の欠落を再現できない。新方式が初期表示範囲の外にも文字を描画できることを検査する補助テストとして保持し、修正判定はDebug版の実画面と組み合わせる。

ネイティブ文字ビューの取り除きにより、ポップアップのアクセシビリティ検査が説明単独のラベルを見つけられず1件失敗した。候補のButtonは名前・説明全文・出どころを1つのラベルへまとめていた。説明単独の重複ラベルに依存する検査を、名前・全文・出どころを含む候補ラベルの完全一致の検査へ変更した。説明の末尾を含む全文の検査は維持している。

## 検証で見つかった既存の試験データ配置の問題

DashboardFeatureのFileTreeLoaderTestsで、UNIXソケット用のパスが106バイトとなり、sockaddr_un.sun_pathの104バイト上限を超えて失敗した。従来の試験データはworktree配下に作られ、チェックアウト先の長さで試験の成否が変わる。ソケットの長さ検査と読み込みの検査を保ち、ソケットのケースだけ短いシステム一時ディレクトリを使う。一意の名前で作成し、既存のdeferで削除する。偽の.gitで実リポジトリの探索を止める既存の分離も保つ。

共通の置き場を/tmpに移した中間版は、/tmp自身がリンクであるため、親フォルダを参照する別の列挙テストでフォルダ判定と並び順の2件が失敗した。ソケット以外は従来の実ディレクトリ配下を使う形に直し、元の期待値は変更していない。

## 実装と検証結果（2026-10-09・初版）

- 選択中のスラッシュ候補の説明にだけAppKitの文字ビューを重ね、文字レイヤーの移動をCore Animationに登録した。説明のレイアウトを決めるSwiftUIのTextは静的で、名前と出どころの位置は変わらない。説明に改行がある場合は表示上の空白に変換し、後続行も読むことができる。ツールチップと読み上げは元の全文を保持する。
- 計測は説明変更時だけで、再描画時は登録済みのアニメーションを保持する。短文・幅0・未接続・非表示では動かない。選択変更と候補の却下後に、保持している古いビューにもアニメーションが残らないことを検査した。
- 先頭・途中・末尾・次周の先頭を、検証用に止めたCore Animationの時計で描画させた。実際の表示レイヤーの移動と、文字のレイアウト枠が固定されることを検査した。
- 幅320pt・460ptで開始・途中・末尾の計6枚を画面外で生成し、目視で見本の候補行と比較した。末尾の文字、固定列、行高、選択色、クリップを確認した。画像の途中と末尾は、cacheDisplayがアニメーションの表示状態を採らないため、登録された移動距離から制御した位置を描画している。この画像検査はPHLOX_DESIGN_SNAPSHOTS指定時にだけ実行するテストに登録している。

### 失敗・警告と検証の限界

- 初回の検証コードは読み取り専用のaccessibilityReduceMotion環境値への代入でコンパイルに失敗した。システム値をポップアップから表示部品へ渡し、部品の停止時表示を検査する形へ修正した。OS設定そのものを操作した確認は未実施。
- アニメーションの数値をCGFloat配列へ直接変換する検証が1件失敗した。APIで使用するNSNumberへ統一し、開始位置・移動距離・速度・待機時間の検査を維持した。
- 描画の検証用コードが登録済みアニメーションのbeginTimeを変更し、CAAnimationImmutable（attempting to modify read-only animation）でテストプロセスが終了した。検証用のコピーを変更する形へ修正した。アプリの実装は登録済みオブジェクトを変更しない。
- 全画面の描画が有効になる指定で開始した中間実行は、描画範囲を今回のポップアップだけに絞るため中断した。最終のパッケージ検査は設定済みrunnerで実行し、追加の描画検査だけを絞り込み実行した。
- 既存のファイルツリーテストと試験データ配置の修正で発生した失敗は上記の節に記録した。最終の本体・実Gitの実行は成功した。
- ビルドでは既存のPTYKitの非推奨init(cString:)、TerminalUIの非Sendableコールバック、DashboardViewのViewBuilder、AppIntentsメタデータ抽出スキップ（No AppIntents.framework dependency found）の警告が出た。検証コードでは、既存のSwiftUIアクセシビリティ木構築の方法に合わせたaccessibilitySetValueの非推奨警告が出た。
- CPU・GPU負荷や消費電力の実測は未実施。毎フレームの画面全体の更新を避けたことは設計とコードの確認であり、性能測定の結果ではない。稼働中のReleaseアプリへのインストール・起動・再起動は行っていない。
- 独立したmacOS lint・静的解析・型チェックは未設定。型検査はSwiftコンパイルに含まれる。iOSは今回の対象外。

ログと描画画像は元のリポジトリ（Phlox-oss）の`.build/command-description-scroll-validation/`に保存した。
