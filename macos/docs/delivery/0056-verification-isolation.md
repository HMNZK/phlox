# 全体検証の設定・通知・画像素材の分離

## 解決したい問題

別のテストの設定や保存通知を拾って失敗し、全体検証の失敗が製品の回帰なのか判断できない。画像素材をテスト途中で準備すると、先行した描画がロゴを見つけられず、後続の描画検査も失敗する。

## 現状

調査基準は `0856c7bb`。端末言語、Git区画、保存通知、テーマ、Usage設定の5系統で、最小の並列組合せが失敗し、同じ組合せの直列実行が合格した。DashboardFeature全体の直列2204件では使用量バー描画1本の8条件が失敗し、素材準備済みの新プロセスでは合格した。

標準入口 `macos/scripts/run-swift-tests.sh` はすでに画像素材の事前準備とMainActorの過剰な並行実行の防止を行う。一方、Git非追跡の古い `.claude/verify.sh` は直接swift testを呼び、この入口を迂回していた。新しい素材コンパイル機構を重複して作らず、標準入口を使う。

## 修正方針

- 設定を注入できる箇所はテスト専用のUserDefaultsへ分離し、通知の監視は対象文書・ルートに絞る。
- グローバルなアクティブテーマの切替自体を守るテストは、共通の排他的な実行範囲を使い、別スイートの切替と重ならないようにする。テスト全体を新たに直列化して済ませない。
- 画像素材は既存の標準スクリプトでテストプロセス起動前に準備する。検証ビルドを `.verification/` へ出力できるようにする。
- 成功状態を待つテストは処理完了を待つ。一定時間変わらないことを検査する否定テストの待機は維持する。

## 成功基準

- 再現した5系統の組合せが標準の並列指定で合格する。期待値の緩和、テスト削除・スキップ追加をしない。
- 専用の検証用ビルド領域で標準入口を実行し、画像素材の事前準備とDashboardFeature全数の成功を確認する。全数実行の前にはAssets.carが無い状態も用意する。
- 設定済みの標準パッケージ検査を実行し、適用できるビルドを確認する。実行不能や既存の警告・条件付きスキップは分けて報告する。
- 一まとまりの差分を独立レビューする。

## 仮定・未知・制約

ブラウザ等の過去の時間切れの直接原因は未特定。標準入口で再検証し、再発すれば追跡する。XCUITestは入力ソース追加を防ぐため実施しない。使用中のアプリは操作しない。Gitのブランチ名再利用時の表示順はADR 0209の既知制限として別件で残す。コミットとマージは今回の修正承認に含めず、実行前に別途承認を得る。

## ローカルの検証設定

Git非追跡の `.claude/verify.sh` を標準入口へ接続する変更は、保護フックが「PMのみ更新可能」として拒否した。ファイルが未変更であることを確認済み。迂回せず、Git追跡対象の本書・テスト方針と、元のworktreeのローカルAGENTS.mdで標準入口を案内する。ローカルAGENTS.mdの変更前コピーも検証ログとともに保持する。
