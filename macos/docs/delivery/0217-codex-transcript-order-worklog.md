# 問題定義: Codex の再起動後に出力順が変わる

## 解決したい問題

実行中の会話の順序と、保存ファイルから復元した会話の順序を一致させる。思考の複数の見出しを区切って表示する。

## 現状（調査の根拠つき）

2026-10-20 の対象セッションは、最後の回答より前の思考181件を回答の後ろに保存していた。Codex の元ログでは回答とコマンドの間にあった。ユーザーの保存データは変更していない。

`ChatSessionViewModel.handleCodexSettingsEvent` は完了項目を単体保存する。思考の `summary` は配列だが `chatItem(from:)` は文字列のみを読み取る。思考の差分は画面に反映される一方、単体保存されない。全体保存で `FileTranscriptStore.upsertTranscriptItems` を使うと、未保存の思考が末尾に追加される。復元は保存順を使う。

見出しの重複は元ログにもある。複数のsummaryを区切りなしで連結しているため、見出し間に空行がなくなる。

## 成功基準（検証可能な形で）

- Codexの思考差分、コマンド完了、回答完了を順に流し、保存ファイルと新しいVMの復元結果がライブの順序・本文と一致する。
- 複数summaryを空行で区切り、完了データの配列を読み取る。
- 途中保存、ターン境界、終了flush、履歴の切り詰めと復元の既存テストを維持する。
- `compact-test` 経由の `macos/scripts/run-swift-tests.sh` で対象パッケージを検査する。

## 仮定 / 未知

VMが全履歴を所有し、表示窓は別の描画処理であることを確認した。復元前・復元失敗時の空データで既存ファイルを上書きしないことを検証する。

## 設計判断

通常保存は引数なしの共通処理から、現在の全履歴を既存のFIFOキュー経由で置換する。配列の順序を保存の契約にする。復元中・復元失敗時の通常保存は禁止し、空の履歴も通常保存しない。意図的な履歴削除であるrevertは明示的な置換を維持する。

全体保存だけを置換し、単体保存を残す案も検討した。この案では完了イベント直後から次の全体保存まで順序が崩れ、途中の再起動を守れないため採用しない。既存のupsertを入力順へ並べ直す案は、部分更新と全体更新で順序の意味が変わるため採用しない。独立した2コンテキストは通常保存の全体置換で一致した。

思考の完了データはsummary配列を読み、空でない要素を空行で結ぶ。同じ見出しの重複は元ログ由来なので削除しない。保存形式やStoreの公開APIは変更しない。

独立レビューで、復元中・失敗時の本文保存を止めても表示情報の保存は続く問題を確認した。保存可否の判定を本文と表示情報で共有し、既存の最終応答時刻などを保護する。

## 検証記録

- 修正前の回帰3件で6箇所の失敗を確認した。保存順、複数summaryの区切り、復元中・失敗後の履歴保護が失敗した。
- 修正後の回帰6件が成功した。関連検査は29件成功。最終的な全パッケージ結果は完了後に追記する。
- 独立レビューで表示情報の保存漏れを1件検出し、修正前に最終応答時刻の保持検査が失敗することを確認した。本文と表示情報で保存許可を共有する修正後、独立実走の関連9件が成功した。
- 初回の全体検査はSessionFeature 1,232件、DashboardFeatureの実Git別パス41件、CodexAppServerKit 102件が成功した。DashboardFeature本体は4テスト・6箇所で失敗した。旧upsert処理を監視する検査が新しいsnapshot保存の契約と一致しないため、保存内容とFIFOの検証目的を保って更新する。別にGitHistoryWorkflowの登録済み既知問題1件が記録された。
- 画面外描画を手元で実行した。`before-restart.png` と `after-restart.png` は1560×1040で、RGB画素の差はなかった。描画補助コードは試験後に除去したため、この画像比較はリポジトリの回帰テストには未登録。
- 実アプリ全体の再起動は未実施。ユーザーの保存済み履歴は変更していない。
- 隔離したXcodeプロジェクトの生成で、生成先フォルダと相対参照の問題により失敗した。生成先を作成し、生成用コピーのplist・entitlements・bridging header・scripts参照を元ファイルの絶対パスへ補正した。署名設定は維持し、Debugビルドが成功した。ビルド中には既存TerminalUIのSendable警告と、AppIntents.framework依存がないためメタデータ抽出を省略する警告があった。

- SessionFeatureは最終状態で1,232件成功、終了コード0。ログは `.verification/codex-transcript-order/final-sessionfeature.log`。

- 最終ソースのDebugアプリのコンパイル・リンク・通常のDebug署名が成功、終了コード0。ログは `app-build-final-source.log`。

## 制約（技術・運用・期限）

既存の未コミット変更、利用中アプリ、`.env*` とmacOS入力ソースを変更しない。XCUITestは使わない。検証物はworktree内の `.verification/codex-transcript-order/` にまとめる。コミット・マージはユーザー承認後。

## スコープ外

既に順番が変わったユーザー履歴の自動移行。元ログで同じ見出しが繰り返される現象の修正。

## 既知リスク

全体保存を置換に変える場合、復元前や失敗時の空の配列で既存履歴を消す危険がある。表示窓は全体配列とは別だが、保存対象が全履歴であることを実コードで確認してから変更する。
