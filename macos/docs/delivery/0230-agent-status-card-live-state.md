# 状態カードの作業状態と実行中の時間

このチャットの実画面で、完了後も「タスク外の作業」が破線の丸のまま残り、未完了に見えることを確認した。コマンド行は完了後の所要時間だけを表示し、実行中の経過時間を表示しなかった。元の実装とデザイン見本にはこの振る舞いが明記されているため、今回の利用者の指示で変更する。

## 修正範囲

- 作業の実行中・完了・中断・記録不明を区別し、タスク外の行へ集約する。未完了の記録を完了に見せない。
- 作業の経過時間を実行中に更新し、完了後は所要時間を固定する。時刻の無いサブエージェントや古い会話の時間は推定しない。
- 短い所要時間を `<0.1s` と表示する。
- 手動開閉、タスクの所属、保存形式、全体の完了判定を維持する。

カード右上の時計は、同じ画面で 4 秒間隔の撮影により `0:40` から `0:44` への更新を確認した。停止の申告は未再現であり、根拠の無い時計の差し替えは行わない。可視性の切り替えを追加確認する。

## 設計と検証

調査と設計比較は読み取り専用の別コンテキストで行い、製品コードの実装者は 1 人にする。既存の型を維持する案と、作業の状態を型で表す案を比較する。時間ラベルだけ既存の `HangStatusTimelineSchedule` で更新し、完了済みの履歴やカード全体を毎秒組み立て直さない。

Swift の検査は `managed-build` と `compact-test` を通し、既存の `run-swift-tests.sh` と `verification-gate.py quality` を使用する。UI は本番と同じ SwiftUI 部品を使う隔離した実行環境で確認し、見本と画面外描画を比較する。証拠と所有記録は worktree の `.verification/card-live-state/` に置く。既存の Release は停止しない。

以下に設計比較と検証結果を記録する。

## 設計比較の結論

状態の正確さ、判定の重複、変更範囲、時計の更新範囲の4点で比較した。既存の `isRunning` と `duration` だけを保つ案Aは、完了・中断・旧記録を区別するために生の会話項目を再解釈する必要があった。状態を型で持つ案Bを採用し、Builderで一度だけ判定する。案Aからは、記録不明を進行中に似た破線にせず静止した疑問符にする案を取り込む。

比較は同じ親モデルの独立した2コンテキストで行った。別モデル系列の比較者は設定されておらず、親が両案を読み評価した。Model the Domain に従い状態を型へ集約し、Laziness Protocol に従い保存形式と全体の完了判定には触れない。Fix Root Causes に従い、右上時計は未再現のまま推測で変更しない。

## 検証経過

- 修正前の2件は、`outside.markKind → .outside` と `action(0.015) → "0.0s"` で失敗した。記録は `.verification/card-live-state/red.log`。
- 修正後のカード関連133件が成功した。実際の `NSHostingView` でも実行中の表示と読み上げが進み、画像は `3.0s`、`4.0s`、完了後 `2.4s` となった。記録と画像は同ディレクトリの `green.log` と `runtime/`。
- 初回の準備ビルド中に回帰テストが追加されたため入力変更を検出した。入力を固定して再実行した `red.log` を正式な修正前の証拠とする。
- 全体ゲートの初回起動は、終了済みの資源コンパイラ `ibtoold` が管理ビルドのロックを継承していたため停止した。同プロセスの自然終了を確認して、ロックを削除せず同じ入口を再実行した。

独立レビューで、見本のサブエージェントに `14s` がある一方、実装と設計は開始時刻を持たず時間を出さない既存の不整合を検出した。部品表と作業展開画面のHTML計4ファイルから推定時間と読み上げの秒数を除き、実装に合わせた。PDFは初回受領時の資料としてREADMEに明記する。

全体ゲートのMac検査では、今回追加した失敗印の13pt直書きを `FontTokenUsageTests` が検出した。既存の `DSFont.row` へ置換し、同検査1件の成功を確認した。テストの期待値は変えていない。残りのMac検査は終了し、既知のGit履歴の問題1件を除いて新しい失敗は無かった。失敗した全体ゲートは成功として扱わず、修正後に入口から再実行する。


最終差分の独立実行は、カード関連133件、フォント規約1件、カード全体の描画1件がすべて成功した。画像は11枚を生成した。親が「タスクなし」の実画像を改訂したHTML見本と見比べ、実行中の印と経過が出ることを確認した。「手で開いた」の画像では完了したタスク外の行がチェックと取り消し線になり、手動で開いた別のタスクは開いたまま残ることを確認した。記録は `.verification/card-live-state/independent-final.log` と `design-snapshots/`。

Mac専用のlint・独立した型チェック・静的解析コマンドは未設定。Swiftのビルドとリンク、既存のDesignSystem規約テストを実行する。iOSのlintとアプリのビルドは標準の全体ゲートに含まれる。利用中のReleaseは更新・再起動していない。
