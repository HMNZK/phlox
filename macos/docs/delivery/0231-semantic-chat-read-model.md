## 稼働サービスへの導入制約

現行Launcherはlease保持中のサービスへ接続し続ける。GUI更新・GUI再接続だけでは旧サービスに新能力を足せない。旧サービスでは明示案内と従来表示を維持し、新表示は対応サービスで保証する。使用中のアプリや実行サービスは本作業で停止・差替えしない。

導入時は全作業と各セッションの明示終了、既知の子PID消滅を確認したうえで、別途承認した計画的なサービス終了と新版GUI起動が必要になる。`idle` は入力待ちであり終了ではない。更新後は新generation・新PID・対応能力と会話の読取復元を確認する。lease/discoveryファイルを消して強制的に併存させない。

既存終了処理は本文flushに3秒、全終了に10秒の上限があり、保存完了の公開ACKとdescriptor保存列のdrainはない。正常終了要求だけで保存成功を保証しない。保存データの保全・読取再確認と移行試験が必要で、稼働版の移行は本作業の検証アプリ受入とは別の未実施項目である。これは[独立実行仕様](../specs/independent-session-runtime.md)の「常駐自身の更新をまたぐ無停止保証は対象外」と整合する。
