## 原因を絞った根拠

詳細を空にしてから再取得する一時状態で文書が720px縮み、AppKitのoffset補正によって位置が145pxずれることを確認した。取得済み詳細の一括適用と、成功した移動だけを最初の表示窓へ適用する形へ直した。

背景更新では制御世代・loading・本文・履歴をawaitを挟んで公開していた。一回の公開へまとめると追記中央値が約103msから約43msへ改善したが、3段で約52–56msが残った。個別の閉じた作業の描画境界を試しても速度改善を確認できなかったため、その境界と付随Binding変更は取り除き、開閉・詳細更新の強化回帰は維持した。

元の境界・全40検証を維持したphase診断では、中央値がイベント適用待ち0.767ms、概要生成・適用13.060ms、内容更新待ち24.795ms、最終描画確認0.441msだった。区間和と元計測値の差は最大0.000292ms。概要と待機判定の全件質問走査を既存変更通知の位置索引へ替え、返答がない場合の逆走査も除いた。正式計測にはこの診断harnessの数値を混ぜていない。
