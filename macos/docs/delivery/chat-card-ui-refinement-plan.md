# 問題定義: チャットカードの作業内容と担当を明確にする

本書は承認済みの修正計画。2026-11-11 に TDD で実装を開始。

## 解決したい問題

- サブエージェントに任せた作業がアイコンだけで示され、カード全体の担当なのか、個別の作業なのか区別できない。
- 思考が閉じたカードになるため、本文を読むのに開く操作が必要。
- 実行中のコマンドを、文字の明るさが左から右へ移る演出で識別したい。
- カード左上の点描を、ミラーボールのように虹色が左上から右下へ滑らかに移り変わる表示にしたい。
- カードの所要時間の左側で、そのカードに記録された追加・削除行数を確認したい。追加は緑の `+n`、削除は赤の `-n` で示す。
- 「ファイル名 を編集」の行が押せることをホバー時に示し、展開した「変更済み」の欄の上下に余白を設けたい。
- ファイル編集中も作業行に対象ファイル名を表示し、コマンドと同じ左から右への明るさの流れで実行中と分かるようにしたい。

### 修正の順序と到達範囲

1. **仕様と見本を先に更新する。** `macos/docs/specs/agent-status-card.md`・同設計書と該当する ClaudeDesign のカード見本へ、下記の表示規則を反映する。思考を閉じる既存規則と点描の単色規則は、今回の対象範囲だけ改訂する。ADR は既存決定を部分置換する内容に絞って記録する。
2. **サブエージェントを文字で明示する。** 見出しは「サブエージェント実行中 · 依頼内容」。該当行は「↳ サブエージェント · 依頼内容 · 実行中」とし、完了・失敗・停止も明記する。既存のエージェント種類の情報は詳細な種類名がある場合に保持する。「サブエージェント」と状態を固定して確保し、長い依頼内容だけを省略する。日本語・英語の文言と VoiceOver を揃える。表示は既存の `.subAgent` と状態に基づき、本文や作業名から推測しない。親のコマンドや思考を子の作業として扱わない。カード全体の完了・中断・エラー表示は維持する。
3. **思考本文を常に表示する。** macOS の思考表示から思考専用の折りたたみと要約行を外し、既存の本文描画で受信済みの全文を折り返して表示する。通常の会話ログと常駐実行からの取得経路の両方を対象にする。空の思考は非表示を維持し、ストリーミング中も追記を表示する。思考を含むタスク・作業グループ全体の開閉規則は維持する。状態欄の短いプレビューは本文とは別の用途なので変更しない。
4. **実行中コマンドとファイル編集・書き込みの文字に明るさの流れを付ける。** 対象はカード内のコマンド作業行（`.command` とコマンド説明の `.run`）、ファイル編集・作成行（`.edit`・`.editFiles`・`.write`）。検索・サブエージェント行は対象外。旧セッション名の明るさ計算を再利用し、初期速度は 1.4 秒の移動＋1 秒の休止とする。等幅のコマンドは等幅のまま、ファイル名と説明文は既存の書体のまま保持する。完了・中断・失敗後は静止する。画面外・閉じたグループ・非表示・動きを減らす設定では動かさない。SwiftUI の表示木を毎フレーム再評価する旧方式は戻さず、既存の Core Animation 駆動方式を利用する。
5. **カード左上の点描を虹色にする。** 既存の点群と動きを使い、画面上の左上→右下の位置と時刻に沿って色相を滑らかに変える。円全体が一斉に同じ色へ切り替わる表示にはしない。カードが使う点描だけに適用し、共有部品の他の利用箇所・iOS の外観は維持する。画面外と動きを減らす設定では色の移動も止める。既存の待機時の静止・薄い表示も維持する。
6. **カード見出しに変更行数を追加する。** 配置は「左側の状態・作業名 …… 緑の `+101` 赤の `-0`  所要時間 `2:47`」。そのカードの変更記録を、既存の差分分類・計算で集計する。作業フォルダ全体の Git 差分は使わず、別ターンやユーザーの編集を含めない。同じ item ID の追記・置換・再受信では二重加算せず、別の編集操作は各差分を合計する。確定した値がゼロなら `+0 -0` と表示し、未取得・算出不能をゼロとして表示しない。失敗・未実行の編集を確定した変更として加算しない。実行中は確定分を更新し、完了後は最終値を維持する。閉じたカードや未取得のページも含む全体の値を実行側で算出し、既存のカード要約に最小限の省略可能フィールドとして載せる。既存クライアントとの互換性を保ち、新しい API 経路は作らない。描画や時計の更新のたびに全差分を読み直さない。
7. **編集中の名前・ホバー・展開余白を揃える。** ファイル名を取得できた時点で、カード内に「`filename` を編集中／書き込み中」の作業行を表示して上記の文字演出を適用する。見出しだけが「書き込み中」のままにはしない。同じ作業 ID の行を完了状態へ更新し、先行表示と確定結果の行を重複させない。まとめられる複数ファイルでも編集中の対象名が失われないようにする。Claude と Codex の受信タイミングを確認し、必要なら名前の確定した入力フィールドを早期に表示へ渡す。未確定・未受信のパスは推測せず、途切れた JSON・エスケープを含む名前・キャンセルを扱う。編集行へホバーすると薄い背景と開閉マークの反応で押せることを示す（ユーザー回答済み。操作ボタンは追加しない）。キーボードフォーカスでも識別可能にする。展開した変更欄は初期案として上下 8pt 相当の余白を設け、通常経路と常駐実行経路で統一する。親の行と次の思考行の両方に接しないよう、既存の余白トークンと文字倍率に合わせて見本で調整する。
8. **ひとまとまりの変更としてレビュー・検証する。** 文言・本文・変更行数・常駐実行の取得経路・編集中の受信イベント・アニメーション・狭いグリッドでの収まりをまとめて確認する。レビュー後の修正は失敗した最小確認から再開し、最後に既存の統合品質入口を通す。

到達範囲は上記の表示部品、必要な表示文言・ローカライズ、差分集計・カード要約・実行側の読み取り用 index、必要なファイル編集の受信処理、対応する既存テストと描画用 fixture、仕様・見本。`ThinkingOrbView` と `ShimmerTextView` の利用箇所は変更時に再検索し、共通部品の変更がカード外へ伝わらないことを確認する。新しい設定画面・依存ライブラリ・汎用アニメーション基盤は追加しない。

| アクセシビリティ | 動きを減らす設定で両方静止し、VoiceOver が担当種別・内容・状態を読む | 既存の設定・読み上げ契約のテスト。色や動きだけで状態を伝えない |

### 実行する検証

- 実装前に `~/.agents/docs/verification-execution.md` と managed-build スキルを読み、最新ブランチの品質設定・標準入口を再確認する。
- 局所確認は `~/.agents/scripts/compact-test` 経由で `macos/scripts/run-swift-tests.sh` の DesignSystem・SessionFeature・DashboardFeature の関連テストを使う。新規 E2E は追加せず、表示と状態の組み合わせは既存の下層・hosted テストで確認する。
- 思考の「非空なら既定で閉じる」期待値は、今回の明示的な仕様変更に対応して全文表示の期待へ改訂する。空白非表示や本文保持の検出範囲は弱めない。
- 比較画像は `PHLOX_DESIGN_SNAPSHOTS=1` と `PHLOX_DESIGN_SNAPSHOT_OUTPUT_DIR=<worktree>/.verification/<作業名>/design-snapshots` を指定し、更新した ClaudeDesign の見本と見比べる。静止画像と動きの確認を区別する。
- 最後に設定済み入口 `python3 -B macos/scripts/verification-gate.py quality` を使う。macOS 全パッケージ、iOS の既存 lint・単体・build、必須 fake E2E はこの入口の定義に従い、独自のコマンド列で置き換えない。macOS 専用 lint・別建て静的解析は調査範囲では未設定。Swift コンパイル・型検査・リンクと区別して報告する。macOS アプリの組み立て確認も既存ビルド入口で別に行う。
- 検証物・ログ・所有メモは対象 worktree の `.verification/<作業名>/` にまとめ、ビルド先も指定する。使用中の Release 版や他作業の検証環境は停止しない。
- セッションの停止・完了状態機械は変更しない。ファイル名の早期表示で `ChatSessionViewModel.swift`・`ClaudeChatClient*`・`CodexAppServerClient.swift` の変更が必要なら、AGENTS.md の対象表に従って `verify-phlox` の段 1 を追加する。モデル検査は関数・状態変数の変更範囲が発動条件に当たる場合に両モードを実行する。読み取り要約に必要な接続変更が `SessionRuntime*` に及ぶ場合は、同表に従って段 1 と段 2 も含める。

## 仮定 / 未知

- 本計画は画像の macOS チャットを対象とする。iOS と Cursor のカード構造を作り替える依頼ではない。ただし既存の macOS 共通思考表示は呼び出し元を含めて全文表示に揃える。
- 「全文」は CLI が Phlox へ渡した思考テキストの全量。CLI から届かない内容の生成や復元は行わない。
- 思考専用の開閉は廃止するが、親のタスク・作業グループを閉じれば、その中の思考も隠れる。この既存のグループ操作は維持する。
- コマンド・編集・書き込み行の演出は実行中だけ。速度は旧値を初期値にし、点描の色の速度・彩度とともに描画結果を見て調整する。利用者向け設定は増やさない。
- 見出しの行数は、そのカードに記録された個々の編集差分の合計とする。同一ファイルを別操作で再編集した場合は各操作を数えるため、作業開始前と終了後のファイルを比較した純増減とは異なる。既存の個別差分欄と同じ計算を使う。
- サブエージェントの内部差分は、親側のログへ確実な変更記録が届く場合だけ対象にできる。依頼したという印だけから行数を推測しない。過去ログ・失敗操作・シェル経由の変更など、差分を取得できない場合の扱いは実装時に入力形式と照合する。
- 「編集中の名前」は、CLI がパスを通知する時点より前には表示できない。名前受信後から作業行を出すことを保証し、モデルが編集内容を生成している間にパスも届く経路では先行表示する。
- 最新 dev に他作業の改善が加わっていれば、その実装を優先して差分を最小化する。

## 制約（技術・運用・期限）

- 2026-11-11 の実装指示を受け、仕様→受け入れテスト→RED→実装→GREEN の順で進める。
- 実装時は資料を先に更新し、その後に製品コード・必要なテスト・fixture を直す。
- 保存形式の移行、親子セッションの関連付け、作業の所属判定、実行サービスの API 経路は変更しない。カード全体の変更行数を届けるため、既存の読み取り用要約への省略可能な値の追加と、その生成・受け渡しは対象に含める。旧データで値がないことをゼロとして扱わない。
- `.env*` と既存の未コミット変更には触らない。計画への承認は push・dev/main への統合・リリースの承認には含めない。
- 現チェックアウトの設計書は「未実装」、dev の同設計書は「Mac 実装済み」。これはブランチ差であり、現ブランチの製品実装との矛盾として扱わない。
- AGENTS.md にある比較画像の `.build/design-snapshots/` は既定出力先。dev の実装と手動検証ガイドには `.verification/` を指定できる環境変数があるため、検証物の配置ルールに従ってそちらを使う。

## スコープ外

- サブエージェント内部のログ表示・展開機能、新しい親子ツリー、子の操作ボタン。
- セッション名の旧演出の復活、カード外や iOS の点描の虹色化。
- 保存形式の移行、セッションの停止・完了状態機械の変更。ファイル名の先行表示に必要な受信処理と行更新は対象に含む。
- 編集行への新しい操作ボタン、変更行数のための全作業フォルダ Git 監視、サブエージェント内部の差分の推測。
- ビルド・品質ゲートの再設計、新しい検査ツールの導入。
- マージ、push、リリース。実装・ビルド・対象テストは承認済み。

## 既知リスク

- 全文表示は長い会話の高さと描画負荷を増やす。既存の表示範囲制御を維持し、全文の切り捨てで対処しない。
- 虹色の点描と文字演出を同時に動かすため、狭いグリッドで注意を奪いやすい。彩度・明暗差・速度を控えめに調整し、画面外停止を維持する。
- 明るさを下げすぎるとライトテーマで読みにくくなる。旧実装の弱い文字色をそのまま重ねず、明暗両テーマで確認する。
- 共通の点描とテキスト部品は他画面・他プラットフォームでも使われる。必要最小限の適用範囲指定でカード外への外観変更を防ぐ。
- 親と子が並行実行する場合、見出しは既存規則に基づく現在の作業 1 件だけを示す。カード内の各作業行の担当表示で区別し、全体が子の作業であると表現しない。
- 読み込み済みの表示行だけで集計すると、閉じたカード・ページ分割で行数が減る。実行側の全体要約から配信し、大きな差分を画面へ全取得して補わない。
- ツール入力の差分は、ファイルへ適用されたことの証明とは限らない。結果と照合し、失敗した操作や未確定の入力を確定行数として表示しない。過去ログで判別不能なものは正確な集計として断言しない。
- ファイル名の先行表示では、途切れた入力、同じ item の確定イベント、複数同時編集が重なる。作業 ID ごとに対応付け、重複・子の情報の親への漏出・完了後の再点灯を防ぐ。
