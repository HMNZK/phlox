# Markdownスクロールのフリーズ調査と修正

## 結論

OwlyzeのAGENTS.mdのフリーズ直前の履歴版を使い、元のOS記録と同型の長時間固着をDebugで再現した。可変高のブロックを行ごとに遅延配置すると、サイズ推定・配置・選択用文字部品の更新が収束しない。本文の再解析を止める修正だけでは固着した。

32ブロックずつの配置は固着を抑えたが、最終実画面で本文全空白を発見して不採用とした。最終案は標準Listへブロックを直接載せる構成。本文表示と大文書の初回負荷を改善し、Listに伴うクリック転送と古いフォーカス要求の競合も修正した。最終の性能・全体品質検査も通過した。画面外になった編集の確定とホバー解除は、行の破棄に依存せず明示的な可視判定で維持する。

## 因果関係の対照

| 条件 | 結果 |
| --- | --- |

## 実装と維持する動作

- `MarkdownBlockEditor`：Listへブロックを直接載せ、標準の遅延行生成を使う。行IDとアクセシビリティ識別子の全体indexを維持する。行間と文書端の余白は各行で指定する。
- 編集欄：同じ編集IDが一度可視になってから画面外へ移った場合だけ、次のメイン処理で同期・確定する。ID・最新の可視状態・通知世代を再確認し、確定成功時だけフォーカスを解除して既存の撤去処理へ渡す。失敗時は内容と欄を保持する。
- ホバー：画面外になった行のローカル状態を解除する。
- `RichMarkdownView`：未変更のファイル本文の再解析を抑止する等価な子Viewへ切り出す。本文・ホバー中URL・テーマIDを比較し、操作先は外側の環境値で更新する。チャット描画の処理は維持する。

再解析の対照では8ストリーム更新中の未操作10秒で親body372回に対して解析を含む子bodyは0回だった。計測専用コードは最終ソースから撤去済み。

## 全体ゲートのTerminalUI検査の実行条件

Markdownを含むDashboardFeatureは全件成功した後、TerminalUIの並列実行でOption矢印からPTYへ届く検査の2条件が空受信で失敗した。同じ8テストの単独スイートは0.36秒で成功し、全128テストを直列にした対照も114.49秒で成功した。openpty・端末設定・writeの失敗はなく、ADR0054のENXIO型とは異なる。

TerminalCoordinator.sendはMainActorへ配送を予約し、検査の受信ループはreadより前に1秒の期限を確認する。他のMainActor検査の同期生成・描画により再開が遅れると、配送済みでも次のreadを行わず空受信になり得る。既存のSessionFeature／DashboardFeatureと同じく、パッケージ内の独立ケースを直列に実行する。ケース内の並行処理、128件の集合、入力の期待値と期限は変えない。標準入口の既定とゲートの記録値を同時に更新する。

標準入口のコメントが参照していたADR0170のserial-execution文書は存在しないため、その参照を削除した（現0170はworktreeの中断方針）。TerminalUI直列対照の根拠はこの節とterminal-all-serial-control.log。

## 32件配置を不採用にした表示欠落とListへの変更

全体ゲート通過後の最終Debugで、17KB版の先頭から10ページdownすると本文が全空白になることを4往復で確認。AX応答だけを成功とした先行の実画面判定は不十分だった。空白は追加観測後も続き、up1で本文が戻る一方、スクロールバーは0.8487から0.965へ増加した。遅延配置の高さ推定とoffset補正の問題が残るため完了扱いにしない。Apple公式のlazy stack解説もoffscreen高さの推定とoffset補正を説明する（https://developer.apple.com/videos/play/wwdc2026/321/）。

最小の次の対照として、元のブロック単位の行をplain Listへ載せ、標準の遅延行生成を使う。編集・リンク・文字選択・Undoの既存処理と表示幅は維持し、native Listの入力干渉と見た目の差を確認する。独自の高さキャッシュ・仮想化は追加しない。

List入力のtraceでは、対象行のmousedownはinside=trueだがmouseupがlocal monitorへ届かなかった。hitTestのunderlying targetは文字部品でなくSwiftUIの行コンテナだった。文字部品型だけを中継する条件を取り除き、行内の有効なtargetを既存の同期mouseDown転送へ通す。転送中は再hitTestの自己再入を防ぐ。selectionDisabledだけの対照は失敗したので撤去。テストhelperの期待は変更しない。traceはlist-event-trace.logとlist-hit-trace.log。

隣接段落への移動では、新しい編集開始後に古い描画行の遅延focus要求とonFocusが届く競合をtraceで確認。編集開始時に描画行フォーカスを解除し、遅延focusBlockとSelectionView.requestFocusは実行時点の編集・選択状態を確認する。遅れて届くonFocusも編集中は反映しない。visibilityfalseによる確定は採取記録で否定された。

Listの初回生成中には非可視行の文字部品が増えるため、hover回帰は初回生成の安定を条件待ちしてから、既存の全子孫文字部品IDの完全一致を測る。比較する集合と本文構築ゼロの期待は維持する。画面外の行は再利用用にwindowから外されてもvisibleRectが非空となり得るため、所属windowと表示領域との交差で実際の非表示を判定する。初期高さのoverrideは推定高さを過小にしたため削除し、Listの既定を使う。

選択文字部品の探索では、行コンテナ内部のクリック座標にある選択可能なNSTextField／field editorを標準NSView階層から解決する。privateな行コンテナ型名には依存しない。この転送でダブルクリック単語選択も成功した。

AX検査は公開されたAXChildrenだけで編集欄へ到達できることを確認した。ListのAppKit行・セルが返す従来形式のAXRole／AXChildrenを、検査補助が読めていなかった。modern getterから公開legacy属性へfallbackを追加し、AppKit subviewsへの迂回や期待値の変更なしに既存の公開／確定後非公開検査が成功した。
