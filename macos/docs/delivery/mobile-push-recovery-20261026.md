# iPhoneの完了通知を復旧する

iPhoneのPhlox 1.0/build 5で、メッセージと返信は届くが完了通知が届かなかった。
Macの通信制限を緩めず、Appleへの通知登録を更新する経路を修正する。

現在はiPhone build 7とMac 1.14.0/build 36のローカル修正版を反映済み。
Macは画面側だけでなく通知を送る常駐側の実行ファイルも修正版と一致することを確認した。
通知登録を取り直した後、実機で前面・バックグラウンド各1件の送信、返信、完了通知を確認した。
各検査で返信が8秒間消えずに表示されることも確認した。正式配布は未実施。

## 原因を確認した記録

実機が受け取った古い通知トークンとMacの登録の一致を、値を公開せず指紋で確認した。
そのトークンへの直接送信は、開発用環境でHTTP 410 `Unregistered`だった。
初期調査では再登録後のHTTP 200を同一トークンの成功と記録していたが、別の配布用登録も存在していた。
後の指紋比較で実機の失効トークンと配布用登録が異なると確認できたため、初期の200を実機復旧の根拠から除外する。
実機build 5と6の配布物には`aps-environment=development`が含まれ、実機の通常起動でも環境判定がsandboxとなることをデバッガーで確認した。

復帰処理は`PushRegistrationService.retryIfNeeded()`だけを呼び、Macへの登録に一度成功すると何もしなかった。
この経路ではApple側の失効状態を更新できない。復帰時の登録更新を追加した。

この変更後も実機で前面通知の検査が失敗した。Macの2026-10-26 20:02:17のCFNetworkログでは、
HTTP 410応答に`cache_hit=true`が記録され、端末登録を削除していた。
MacのURLキャッシュにもAPNs宛てPOSTのHTTP 410応答が2件あった。
別登録への直接送信がHTTP 200の状態でも、この保存済みの失効応答が通知を止めていた。

## 修正の範囲

通知が有効なアプリ復帰時にもAppleへの登録を取り直す。
返されたトークンは既存のdelegateと`PushRegistrationService.updateDeviceToken`からMacへ送る。
通知OFFとUIテスト用の依存分離を維持する。Tailscaleの設定や既存チャットは変更しない。
Macの`APNsSender`が生成する送信リクエストには`.reloadIgnoringLocalCacheData`を指定し、
過去のHTTP応答を使わず、毎回Appleの現在の応答を確認する。

## 検証と途中結果

実機で前面とバックグラウンドの完了通知を確認する。
通知用トークンの受領後に同じ値でもMacへ再送する既存テストを確認し、iOSパッケージテスト、lint、アプリのビルドと静的解析を実行する。
APNs送信の回帰テストは開発用と配布用、通常通知とLive Activityの4組み合わせで修正前に失敗し、修正後に成功した。
APNsClientは10テスト、AppBootstrapは216テスト成功。iOS開発ブランチは694テスト、実機向け互換版は668テスト成功。
実機向け互換版は既存build 5の写真入力修正を保ち、同じ通知登録の修正を追加したbuild 6。
ビルド・静的解析・既存lintは成功。
起動中MacのURLキャッシュから、保存済みのAPNs向けHTTP 410応答2件だけをURLCache APIで除去した。
除去後、実機のバックグラウンド送信、新しい返信`TW_PUSH_BG_OK`、通知タイトルと「作業が完了しました」の本文をXCUITestで確認した。1件成功。
この実機検査は手元で実行し、検証用ランナーは`.verification/`に保持している。リポジトリの標準テストには未登録。
ロック解除待ちだった前面検査は、開始前に実機との接続を失って終了した。
ユーザーの解除後に`foreground-unlocked`を実行したが、返信は表示されても通知は検出できず、108秒で1件失敗した。
このときも稼働MacでHTTP 410と`cache_hit=true`を観測した。背景1回の成功を、安定した復旧とは扱わない。

## ローカル反映の確認

キャッシュ除去だけでは安定しなかったため、通知修正1行を加えた1.13.0を署名・公証してローカル更新した。
更新後の最初の検査は、以前の検証チャットが一覧にないという送信前の前提で失敗した。
新規チャットへ変えた再検査は中断され、xcresultのInfo.plistが未生成だったため結果未確定。

中断中に通常版1.14.0へ更新されたため、v1.14.0タグのMacソースに同じ修正1行だけを加え直した。
Intel／Apple Silicon両対応、Releaseビルドと静的解析に成功。
既存箇所の非推奨API・Sendable・AppIntents抽出の警告は残る。
Developer IDの署名識別条件・権限を通常版に揃え、公証Accepted、stapler validate、Gatekeeper acceptedを確認。
バックアップと実行ファイルのSHA256も検証し、ユーザーの更新承認に基づきローカル反映した。

画面側の更新後も前面通知の検査は失敗し、背景の検査は送信前の画面操作で失敗した。
このときAPNsの失効を記録したPIDは画面側68416ではなく常駐側46560だった。
常駐側は`session-runtime-bundles`内の更新前1.14.0と同一の実行ファイルを使い続けていた。
互換性のある画面更新では常駐側を維持する設計なので、画面の再起動だけでは送信コードを更新できない。

履歴の保存処理を通す正常終了で画面側と旧常駐側を終了し、更新済みアプリから常駐側を起動し直した。
新しい常駐側PID91210がreadyで、実行ファイルのSHA256がローカル修正版と一致することを確認した。
この切替後も前面検査は通知未検出、背景検査は返信未表示で失敗した。
このときの失効応答は`cache_hit=false`で、Appleからの実応答だった。
実機の通常起動でOSへの登録呼び出し、32バイトの登録コールバック、登録サービスの非nilを確認したが、同じ古いトークンが返っていた。

実機アプリ単位で`unregisterForRemoteNotifications()`を呼び、未登録状態を確認してから通常起動で登録を取り直した。
チャットデータの削除・アプリのアンインストール・通知許可設定の変更はしていない。
取り直し後は新しい開発用トークンがMacへ登録され、そのトークンへの直接送信がHTTP 200となった。
古い失効登録への410を含む診断は失敗として保持し、新しい登録のみとなった後の直接送信の成功と区別する。
取り直し後の前面検査では通知バナーが届いたが、画面の点滅により返信表示の検査が失敗した。背景検査も送信前の画面操作で失敗した。
更新と常駐切替の記録は`.verification/push-delivery-20261026/local-update-1.14/`に保存する。

## 点滅修正の反映と最終結果

Devには`596e4b99`の対応待ちバー切替時の画面再生成を防ぐ修正が含まれていたが、実機build 6の`DSPlatformTabView.swift`は修正前と一致していた。
既存の写真入力修正と通知修正を維持する互換ソースへ、Devの該当ファイルとその回帰テストを反映し、build 7を作成した。
Dev全体を実機へ入れ替えたものではない。既存データを保持してbuild 7へ更新し、署名検証、ビルド、静的解析、lintが成功した。

- シミュレーター: `TabAccessoryIdentityTests`の2条件が成功、失敗・スキップ0。
- 実機前面: 新規チャットの送信、正しい返信、システム通知のタイトル・本文、返信の8秒間表示が1件成功。
- 実機背景: ホーム画面へ移った後のシステム通知、アプリ復帰後の返信、返信の8秒間表示が1件成功。
- 実機検査は2件とも失敗・スキップ0。`build7-foreground.xcresult`と`build7-background.xcresult`に保存した。手元の検証用ランナーで実行し、標準テストには未登録。

通知と返信の添付画像も確認した。チャット内には既存のCodex未安定機能の警告が表示されており、その設定は変更していない。
この検査は各状態1回と短時間の表示維持を対象とし、長時間利用や別端末は未検証。
Macの更新後、Tailscaleの限定通信ルール、SSH無効、Serve無効、未認証APIの401を再確認した。

常駐側のコードを変更した更新を反映するときは、GUIの版だけでなく、通知を送る常駐側の実行ファイルも確認する。
常駐側の再起動は実行中のチャットを中断するため、通常のGUI検証や無関係な作業で実行しない。

入力ソース全体の比較は`EmojiFunctionRowItem`の増加で失敗した。由来は未特定で、設定は変更していない。Unicode Hex Inputの追加はなかった。
今回の再開直前の控えとの比較は一致した。過去の増加の由来を解明したものではない。

記録と結果バンドルは作業worktreeの`.verification/push-delivery-20261026/`へ保存する。
