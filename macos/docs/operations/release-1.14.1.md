# Phlox 1.14.1（build 43）配布準備

## 状態

準備中。非同期質問の表示修正と後続の実行状態改善を含むdevをverifyへ統合し、Mac42/iPhone12を生成した。その後の修正を含むMac43を新たに生成したが、2026-10-28の独立レビューでは、このMac43はQR再試行・入力欄・テストの追加修正より前の入力で生成されたため、リリース前に再生成が必要と記録された。その後、追加テスト後のverifyからMac43を再生成し、appcastを再生成したZIPの情報へ更新した。再生成したMac43の配布物は独立レビューでpassとなった（「検証の区別」）。実機検証、main用リリース検査、mainへの統合、公開、pushは未実施。
既に配布した1.14.0 / build 36を別バイナリへ再利用せず、新しい版とbuildで実機確認用の候補を作る。
iPhone 1.0/build13の書き出しは署名認証待ちで中断し、配布物・来歴は未完成。ユーザーの実機テスト不要という指示に従い、実機向けビルドを待たずMacの配布準備を進める。

ユーザーはbuild9とbuild10の更新後に既存の会話一覧が見えるとそれぞれ報告した。これは基本的な画面/接続の観測であり、最終候補の必須5シナリオの合格ではない。外出中は所有を照合したiPhone10のexportとcodesignだけを停止し、中断記録を保存した。帰宅後の再署名は確認待ちにならず成功した。本体/Widgetの実版と署名、有効な端末profileを照合し、アンインストールせず9から10へ更新した。最初の起動は端末ロックで拒否されたが、ユーザーの解除後に起動とプロセス照会が成功した。build10の一覧表示の人間による観測は同ビルドのインストール記録へ保存した。

最初のbuild 37はビルド・署名・公証・stapleまで完了したが、producerがコンパイル用コピーをビルド前後に照合していなかったため採用しない。実際の改変は観測していない。コピーの改変を受け入れる独立否定テストが失敗し、入力照合の不足を確認した。生成project・Info.plist・lockを含むコピー全体を固定し、独立否定テストの成功後にbuild 38を新規生成した。build 37の実機合格記録は作らない。

iPhone版の最初のexportは、署名確認待ちの後に`errSecInternalComponent`で失敗した。ユーザーの再試行依頼後、同じ入力から再archive/exportして成功した。鍵のアクセス設定や署名検査は変更していない。最初の失敗記録を成功へ書き換えず、成功した再試行の来歴を別ファイルへ保存している。

インストール直前の実IPA検査で、build8の実際の表示版は1.0、記録は0.1.0という不一致を検出した。XcodeGenの生成Infoに既定値1.0が入り、配布入口・capture・releaseが実ファイルの表示版を照合していなかった。署名/hashは有効でも本候補は不採用。ユーザーは設定と検査の修正・新番号での再生成・インストールを選択した。元来歴を書き換えず、選定記録から除く。関連ソースの入力manifestが変わるためMac38も新候補へ流用しない。

## 検証の区別

- iOS シミュレーター上のパッケージ全体テストは、UIKit の外観設定を呼ぶテストにメインスレッドの指定がなくコンパイルに失敗した。テストの実行コンテキストを修正して全体テストを再実行した。テストコードも配布候補の入力に含まれるため、修正前のMac42/iPhone12は最終候補に使わない。
- 修正後のmacOSホスト版パッケージテストは694件成功。iOS 26.2シミュレーターでは1097件中1095件成功・2件失敗し、描画テストは24件中23件成功・1件失敗した。QRの失敗ではVisionが解析環境を作れないエラーを返し、通知設定はmacOSホストを前提とした期待値がシミュレーターと異なった。描画テストでは作業場所のアクセシビリティ項目を取得できず、原因は未特定。
- 通知設定の環境判定は、macOSホストではproduction、iOSシミュレーターではsandboxをそれぞれ検査する。
- QR画像の解析でVisionが内部エラーを返した場合は、旧リビジョンで再試行する。通常の読み取り結果が空の場合や別のエラーでは再試行せず、既存のnilを返す契約を保つ。
- QRの再試行は、Visionの成功・内部エラー・その他のエラーを制御する自動テストでも確認する。
- 追加テスト後のverifyからMac43を再生成した。以前のMac43は入力が異なるため今回の配布には使わない。実機検証とiPhone版の新しい配布物は未完了。
- 描画テストの調査では、同じアプリ内で複数テストのウィンドウが重なった。互いの読み上げ項目の探索に影響しないよう、描画テスト群を直列実行する。
- 文字を最大にして狭い画面で空の入力欄を表示したとき、UIKitの入力領域がプレースホルダーの高さを無視していた。実際の入力領域にも必要な最小高さを渡す。
- ユーザーは今回、実機テストを行わずシミュレーターで検証するよう指示した。現行のmain用リリース検査は実機記録を必須としており、この指示のままでは通過していない。
- 今回のMac版に限り、実機未実施を明記した上で、シミュレーターの検証結果とMac配布物の署名・来歴・内容の照合を行う。実機シナリオを成功と記録せず、iPhone版は配布しない。通常の実機必須検査は維持する。
- シミュレーター連携の異常試験で、補助プロセスの再起動が自動復旧の5秒期限に間に合わず復旧しないことを確認した。自動復旧時の接続確認を20秒に変更し、対象23テストと専用ハーネスで自動復旧・タップを確認した。追加修正後のMac43を再生成し、appcastを更新した。
- 修正後のシミュレーター上のパッケージテストは1097件、外部アクセシビリティ検査を伴う描画テストは24件成功した。macOSホスト上のパッケージテスト694件とiOSのlintも成功した。

## 配布物と来歴

旧記録は統合元リポジトリの`.verification/release-1.14.1/`、`.verification/release-1.14.1-build39/`、`.verification/release-1.14.1-build40/`、`.verification/release-1.14.1-build41/`と、この作業場所の`.verification/release-1.14.1-build42/`へ保持する。最初に生成したMac43の配布物と来歴は`.verification/release-1.14.1-build43/`に保存した。このMac43はQR再試行・入力欄・テストの追加修正前の入力で生成されていたため今回の配布には使わない。appcastは再生成したMac43のZIPの情報へ更新した（「検証の区別」の2026-10-28の独立レビュー）。
