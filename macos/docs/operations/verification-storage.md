# 検証物と長期保存データの配置

`.verification/`には、作業終了後に削除しても必要な情報を失わない一時物だけを置く。配置はファイル形式ではなく、作業終了後の必要性で決める。

| 保存先 | 用途と終了時の扱い |
|---|---|
| `<worktree>/.verification/<作業名>/` | 再生成可能なビルド、合成データ、使い捨てログ・画像・計測。使用終了後に削除できる |
| `<統合元repo>/release-archives/evidence/<版>/<buildID>/` | 配布物、来歴、署名・公証、保持する品質・承認・統合記録、シンボル。継続保管する |
| `<統合元repo>/backups/<版>/<buildID>/<用途>/` | 実ユーザーデータ・設定・元アプリの復旧用退避。検証キャッシュとして削除しない |
| `macos/docs/`・`ios/docs/` | 設計・仕様・手順・作業記録の正本。Gitで管理し、秘密情報・私的データは置かない |

`.verification/`・`release-archives/`・`backups/`はGitに追加しない。`.env*`の作成・移動・変更・削除禁止、使用中データ・未保存成果の保護はどの保存先にも適用する。

## 作業の開始と終了

1. 一時物は固有の作業ディレクトリへまとめ、用途・所有・起動PIDと実行ファイルを記録する。普段のアプリ・データ・ポートから分離する。
2. 保存する記録は作業終了前に`.verification/`外へ移す。確認用アプリを継続使用する場合も、一時領域の外へ配置してから起動する。
3. 移管後の実体・ハッシュ・参照を確認する。`--evidence-root`と現行`gitflow.releaseCommand`は永続保存先を指す。`release`・`distribution`は`.verification/`内の証拠基準を拒否する。
4. 使用済みプロセスと不要物を`session-cleanup`の手順で片付ける。管理ビルドのキャッシュは再生成可能な一時物であり、長期データの保存手段にしない。

削除できる条件は、作業が終了し、プロセスが使っておらず、必要な成果を外へ保存済みであること。別の実行中作業を停止・一括削除しない。

## 既存の証拠の移管

証拠基準配下の相対構造を維持し、配布物・provenance・外部入力・過去ログの内容とSHA-256を変えない。sourceOIDや入力manifestを現在のソースへ書き換えない。

復旧データは`backups/`へ分離する。旧所在地との対応と移管結果を`release-archives/storage-migration-<日付>.json`へ残す。過去の版別文書・署名済みアプリ・凍結ビルド入力は一括置換せず、この対応表で新所在地を案内する。現行ローカルゲートと結果ファイルの所在だけを更新する。

使用中の検証プロジェクトはその場所に残す。周辺の保持対象は使用中プロジェクトを巻き込まずに移し、外へ保存済みの作業コピーだけを一時領域に残す。

2026-11-12の移管結果は統合元repoの`release-archives/storage-migration-20261112.json`を参照する。使用中だった旧`1.14.8/mac54-ios23/physical`だけは一時作業コピーとして元の場所に残し、必要な証拠とバックアップは外へ保存・照合済みである。
