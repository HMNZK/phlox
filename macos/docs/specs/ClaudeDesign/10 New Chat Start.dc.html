F. 入力欄の下段のチップとメニュー（ダーク）
どのメニューもチップの真下に開くポップオーバー（背景 #2F2F33・角丸 10）。左のチップは左端、右のチップは右端を揃える。開いている間、チップは押下中の面のまま。選択中の値はチェック、キーボードで指している行は選択の面（藍の淡い面）。@ と / の候補だけは今のセッション画面と同じく入力欄の上に出す。
論点: プロジェクトを選び直すと下書きが入れ替わることの手がかり
手がかりは要る。ただしメニューの中だけに置く。入れ替わった後に通知やアニメーションは出さない（毎日何度も切り替える操作で、毎回の通知は邪魔になるため）。
1. 下書きがあるプロジェクトの行に「下書きあり」の文字のタグを付ける（E8。図形の印は使わない）。選ぶ前に「選ぶと書きかけが出る」ことが分かる。
2. メニューの下端に 1 行「本文と添付はプロジェクトごとに保たれます」。選ぶ前に、今の本文が消えずに残ることが分かる。
3. 選び直した後は、入力欄の本文と添付がそのプロジェクトのものに替わるだけ（F2）。下書きが無ければ空になる。
F1プロジェクト · メニューを開いた
名前の下にパスを等幅・副文字色で出す。ios-companion に「下書きあり」。下端に「プロジェクトを追加… ⌘O」と下書きの説明。
F2ios-companion を選んだ後（FR-6・D9）
本文が ios-companion の下書きに替わり、入力欄にフォーカスが戻る。Phlox-oss の書きかけ（F1 の本文）は Phlox-oss に残っていて、戻すと出る。@ ファイル候補の取得先も ios-companion に替わる（E4）。
F3作業場所 · メニューを開いた
毎回「既存ディレクトリ」から始まる（D2）。各項目に説明を 1 行。
F4git リポジトリでないプロジェクト（例: site）
「新しい worktree」は補助色で押せない。理由は項目の下に説明文で出す（副文字色、ポップオーバーの背景に対して約 6.4:1）。ツールチップにはしない。矢印キーでも止まらずに飛ばすが、VoiceOver では「新しい worktree、使用不可。git リポジトリではないため worktree を作れません」と読む。site が git リポジトリでないのはサンプルの仮定。
F5「新しい worktree」を選んだ後のチップ
アイコンが分岐に、文言が「新しい worktree」に替わる。色は変えない（アクセントは選択・フォーカス・主要な操作にだけ使う）。
F6＋（添付）
「ファイルを添付…」「画像を添付…」。どちらもファイル選択のパネルを開く。画像は貼り付け・ドロップでも添付できる（今の入力欄と同じ）。
F7effort · Claude Code
低・中・高・非常に高・最大。初期値は「最後に使った設定」。
F8effort · Codex（ultra あり）
候補はモデル一覧の取得結果から出す（§5.4）。起動後に候補が変わっても、その差はこの画面では見せない（E7）。
F9mode · Cursor（effort の代わり、権限なし）
Cursor では effort の位置に mode（既定・ask・plan）が入り、権限のチップは無くなる。左のチップが 1 つ減っても右の 3 つは動かない（E6）。
F10権限 · Claude Code
acceptEdits・auto・bypassPermissions・manual・dontAsk・plan。表示名は今のアプリのまま。
F11権限 · Codex
Full Access・Default・Read Only（内蔵の 3 つ。§5.4）。
F12画像を添付したまま Cursor に切り替えた（§5.3・E7）
添付は消さずに残す。下段のすぐ上に原因と直し方を 1 行で出し、送信は無効。✕ で画像を外すか、ハーネスを Claude Code / Codex に戻すと、行が消えて送れるようになる。
F13「@」のファイル候補（E4）
今のセッション画面と同じ見た目で、入力欄の上に出す。見出しに取得先（プロジェクトと作業場所）を出す。どちらかを替えると候補を取り直し、入力済みの「@…」は書き換えない。
F14「/」のコマンド候補（Claude Code）

K. 新規チャット画面への入口（ダーク）
新規チャット画面を出す入口は ⌘N・サイドバー下端・プロジェクト行の ＋ と「新規チャット」・グリッドの空状態・単体表示でのプロジェクトの選択。どれもセッションを作らず、単体表示に切り替えてセッションの選択を外す（FR-1a）。画面からターミナルのセッションを始める手段は置かない（D1）。カスタムエージェントは機能ごと廃止し、どの画面にも出さない（D22）。
決定: 「プロジェクト名を変更…」の置き場所（E3・11 の P6）
ヘッダーからプロジェクト名と worktree のボタンを消し、「プロジェクト名を変更…」は上段のプロジェクトのタブの右クリックメニューに移す。ヘッダーに残るのはサイドバーの開閉（隠しているときだけ）・単体／グリッド・インスペクタの開閉の 3 つ（38pt）。
K1プロジェクト行のホバーと下端のボタン
＋ を押した時点で、そのプロジェクトの新規チャット画面に切り替える（確認・メニュー・ポップオーバーは挟まない）。ツールチップ「Phlox-oss で新規チャット」、VoiceOver も同じ。下端は「＋ 新規チャット ⌘N」（旧「新規セッション」）。
K2プロジェクト行のメニュー（⋯ / 右クリック）
「新規チャット」「プロジェクト名を変更…」「削除…」の 3 つ。「新規ターミナルセッション」（D1）と「git worktree で隔離する」（FR-15）は無い。
K3メニューバー「ファイル」
「新規チャット ⌘N」「プロジェクトを追加… ⌘O」「閉じる ⌘W」。「新規ターミナルセッション」は無い（D1）。新規チャットは対象のプロジェクトが決まらなくても押せて、プロジェクト未選択の新規チャット画面を出す（FR-2a）。
K4単体表示で、セッションが 1 つも無いプロジェクトを選んだ（D21）
サイドバーで site を選ぶと、そのまま site の新規チャット画面を出す。入力欄のプロジェクトは site、上段の選択中のタブも site。site の下は「セッションはありません」の 1 行だけで、下段は「新規チャット」タブだけ。グリッド表示では今どおり絞り込むだけ（K5）。
K5グリッド表示でセッションが 0 件
主ボタン「新規チャット」。押すと単体表示に切り替えて、このプロジェクトの新規チャット画面を出す。サイドバーを隠した状態なので、ヘッダーの信号の右に「サイドバーを表示」（11 の T12 と同じ）。
K8プロジェクトが 1 つも無い（FR-3）
今のフォルダ登録の案内（StartOnboardingView）のまま。⌘N もこのとき押せて、同じ案内を出す（今はプロジェクト 0 件で無効）。ここに描いたのは配置の目安で、文言とレイアウトは今の画面に合わせる。

J. 履歴から再開（ダーク）
提案チップの下の、副文字色の小さなボタン「履歴から再開…」。選択中のハーネスが Claude Code か Codex で、このプロジェクトに履歴があるときだけ出す。出さないときも 24pt の高さを空けたままにして、上の見出し・入力欄・チップの位置を動かさない。
論点: 一覧はポップオーバーにする（シートにしない）
ボタンの真下に開くポップオーバー（幅 480pt、一覧の高さ 300pt でスクロール）。選ぶか Esc で閉じるだけの軽い操作なので、ウィンドウを覆うシートは重い。入力欄のメニュー（F・G）と同じ部品・同じキー操作にそろえる。
作業場所の手がかりは 2 段。一覧の先頭に常に 1 行「選んだ会話を、今の作業場所（既存ディレクトリ）で再開します」を出す（入力欄の作業場所の選択に合わせて文言が替わる）。さらに worktree で進めた会話を指したときだけ、その行に「元の worktree には戻らず、既存ディレクトリで再開します」を足す。
どこで進めた会話かは文字で出す（「Phlox-oss」「worktree」「worktree（削除済み）」）。図形や色は使わない。
J1一覧を開いた · worktree の会話を指している
最大 20 件、更新日時の新しい順。各行は最初のメッセージの冒頭（1 行で省略）、相対時刻、どこで進めた会話か。worktree が消えていても「worktree（削除済み）」として出す。VoiceOver は「サイドバーのセッション行に状態の文字を出す、昨日、worktree で進めた会話」。
J2作業場所に「新しい worktree」を選んでいるとき
先頭の 1 行が「選んだ会話を、新しい worktree を作って再開します」に替わる。この場合はどの会話を選んでも新しい worktree で動くので、行ごとの注記は出さない。
J3読み込み中（FR-13b）
行の形の骨組みを 3 本と「読み込んでいます…」。2 回目以降に開くときは前の一覧を出したまま裏で読み直す。
J4一覧が空（FR-13b）
ボタンを出した後に読み込んだら 0 件だったとき。「履歴がありません」とだけ出す。次に新規チャット画面を出すときはボタン自体を出さない。
J5読み込みの失敗（FR-13b）
「履歴を読み込めませんでした」と「再試行」のボタン。開いたときのフォーカスは「再試行」に置き、↩ で読み直せる。
J6ボタンにホバー
灰色の面と主文字色。押下中・フォーカスは部品の状態の表（D）と同じ。
J7履歴が無いとき（出さない）
ボタンを出さず、24pt の高さだけ空ける（紫の破線は説明用で、画面には出ない）。
J8Cursor を選んでいるとき（出さない）
ハーネスを Cursor に替えた瞬間にボタンを消し、高さは保つ。Claude Code・Codex に戻すとまた出る（そのハーネスの履歴を読む）。

I1「既存ディレクトリ」で送った直後 · 起動中
サイドバーに新しい行（題名は最初のメッセージから）を出して選択し、右端は「起動中」。タブも同時にできる。預かった本文は会話にユーザーの発言として出し、下に「送信待ち · 起動が終わると送ります」。入力欄は空で、プレースホルダが「起動しています…」に替わる。下段のチップは補助色にして押せない（起動時の値で動いているため）。送信は無効。
I2起動が終わり、最初のメッセージを送った後
「送信待ち」が外れて通常の発言になり、行の右端は「実行中」。入力欄は通常に戻り、送信ボタンは ■（中断）。ここから先は今のセッション画面と同じ。
I3「新しい worktree」で送った直後 · 行はまだ無い（D11・FR-11）
新規チャット画面のまま、下書きは空になる。画面下部にトースト「worktree を作成しています…」と作成先のパス。数秒後に作成が終わると、サイドバーに行が出て選択され、I1 と同じ起動中の画面に移る。
I4起動に失敗した
行は消さず、右端に注意の色で「エラー」。会話には「起動できませんでした」と理由、最初のメッセージを送っていないこと、本文を戻したことを書き、「再起動」「閉じる」を並べる。預かっていた発言は会話から消し、入力欄に戻す。入力欄の 1 行は「本文を戻しました。再起動すると送れます」。閉じると今の後始末で worktree も片付く。
I5「再起動」を押した後（D20）
失敗した行を閉じ、同じハーネス・モデル・effort・権限・作業場所で新しいセッションを起動して選択する。本文は入力欄に残ったままで、自動では送らない。起動中は「起動しています。終わったら送れます（自動では送りません）」と出し、送信は無効。起動が終わると送れるようになる。
I6起動後、最初の送信が失敗した
今のセッション画面の送信失敗の表示（入力欄の上の通知と「再送」）に合わせる。本文と添付は入力欄に戻り、そのまま送れる。セッションは残り、行の右端は待機中の経過時間。
I7worktree の作成に失敗した（行が出る前）
今のダイアログ（シート）をそのまま使う。git の出力を等幅で見せ、「閉じる」「既存の worktree を使う」「隔離なしで起動」。隔離なしで起動を選ぶと、既存ディレクトリで I1 に進む。Codex の app-server の失敗も同じく今のエラー表示を出し、閉じると下書きに戻す。
I8ダイアログを閉じた後 · 本文が下書きに戻る（AC-5d）
新規チャット画面に戻り、本文と選択（作業場所は「新しい worktree」のまま）が下書きに戻る。トーストで「worktree を作れなかったため、本文を下書きに戻しました」と知らせ、数秒で消す。入力欄にフォーカスを置くので、すぐ送り直せる。

G. ハーネス・モデル選択（ダーク）

論点: 長いメニューは「絞り込み欄＋スクロール」の両方にする
絞り込み欄はメニューの先頭に常に置き、開いたときから入力を受け付ける。文字を打つとすぐ絞り込まれ、↑↓ は欄にいたまま候補を移る（G3）。Cursor だけで 28 モデルあり、名前を覚えている上級者には打つのが最も速い。
一覧の高さは 340pt で止め、中をスクロールする。新規チャット画面では入力欄の下に 380pt ほどしか余白がないため（ウィンドウ 900pt）。開いたときは選択中のモデルが見える位置にする。
Cursor は先頭 4 件と「ほか 24 件を表示…」。ハーネスの並びを一目で見渡せる長さに保つ。残りは押すとその場で広がり、絞り込みでは全件を探す（G6）。
