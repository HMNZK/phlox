## 統括役の決定（2026-10-15。モックより優先）

`判断が必要な項目.md` への答え。詳細は要件書 `git-tab-workflow-and-worktree-start.md` §7。

1. 入力欄の縁は今のアプリの値（主文字色の 14%）のまま。Git タブだけ変えるとアプリ内で不揃いになるため。コントラスト不足はアプリ全体の課題として別に扱う。
2. ボタンの入力先の示し方は、アプリの既存のボタンと同じ（新しい輪を作らない）。FX-1・FX-2 は一覧と差分欄の外枠の話で、ボタンは対象外。
3. 実行中のセッションがあるときの確認は、キャンセルを既定にする（モックどおり）。「このプロジェクトでは聞かない」は付けない。
4. キー: ⇧⌘C（コミット欄へ）・⌥⌘P（プッシュ）・⇧⌘R（取得）・⌥⌘S（スタッシュ）・⌃↩（メニュー）は採用。⌥⌘N はファイルツリーの「新規ファイル」と重なるので、新しいブランチにはキーを割り当てない（見出しの「＋」と右クリック）。キーは Git タブを表示しているときだけ有効。
5. 理由の 1 行を押せるときも出す・↩ は「作成して切り替え」・「変更」タブの「エディタ」の行を無くす・一部ステージのファイルに印を付けない、はモックどおり採用。
6. グラフの線と札の提案は採用。「origin だけ取得」は足さない。
7. 「変更」タブの構文の色は、モックの仮の値ではなく実装の構文色を使う。
