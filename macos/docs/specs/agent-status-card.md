# エージェント状態カード（要件・受け入れ基準）

> **このファイルの役割**: チャットの会話ログで、入力 1 回ごとのエージェントの動きを「タスクと作業」に整理して見せるカードの要件、受け入れ基準、範囲。
> **書かないもの**: 実装の設計（→ [agent-status-card-design.md](agent-status-card-design.md)）、なぜこの方式か（→ [ADR 0226](../adr/0226-agent-status-card-derived-from-transcript.md)・[ADR 0227](../adr/0227-status-card-icons-inside-card-only.md)）。用語の定義は [glossary.md](glossary.md)。
> **デザインの見本**: [Claude Design の10画面と部品・全状態の対応表](ClaudeDesign/agent-status-card/index.html)（[全状態・寸法・色・VoiceOver](ClaudeDesign/agent-status-card/boards/10-Anatomy.html)、[PDF](ClaudeDesign/agent-status-card/pdf/phlox-agent-status-card.pdf)、編集用データは `ClaudeDesign/agent-status-card/source/`）。ユーザー作成の見本を2026-11-07に取り込んだ（依頼文は `macos/Design/claude-design-prompts.md` の「14」）。参考はユーザーの手描きスケッチ [ClaudeDesign/agent-status-card-sketch.png](ClaudeDesign/agent-status-card-sketch.png) と、Elia (@eliakuratli) の「Agent status component」動画（2026-10-23、https://x.com/eliakuratli/status/2113618712066711970 。第三者の動画なのでリポジトリには入れない）。実装は見本と見比べてから完了とする。
> **状態**: 要件確定（2026-11-06 のインタビュー、2026-11-07 に D19〜D21 を追加）。1 段目（Mac）を実装済み（2026-11-07）。2 段目（iOS）は未実装。

## 1. 解決したい問題

今のチャット画面では、エージェントの動きが次のように散らばっている。

- 作業（ファイルの読み込み・編集・コマンド）が会話ログに 1 件ずつ並び、1 回の入力で数十件になる。
- タスクリストはセッション全体で 1 枚だけで、最初に登録された位置で書き換わり続ける。いつ・どの入力で何が進んだかが読めない。
- 処理中の表示（点描アニメーション・状態語・経過）は会話ログの末尾に別の行として出て、タスクとも作業ともつながっていない。

ユーザーが知りたいのは「今何をしているか」「全体のどこまで進んだか」「各タスクで何をしたか」である。

## 2. 方針

**エージェントは自由に動かし、Phlox は観察した動きを整理して見せる。** タスクの登録を指示したり、ツールの使用を拒否して強制したりはしない（指示の自動注入を撤去した ADR 0035 を維持する）。タスクを登録しない入力でも、カードは作業の一覧として成り立つ。

## 4. 機能要件

### 4.1 カードの単位

- **FR-1** ユーザーの入力（`userMessage`）1 件につきカードを 1 枚作る。範囲は、その入力から次の入力の直前まで。
- **FR-2** 作業もタスクも無く、文章だけで答えた入力（例: 「OK と返して」）ではカードを出さない。実行中は、返答が届き始めるまで見出しだけのカードを出す。
- **FR-3** 実行中に次の入力を送った場合（Phlox は送信を待たせない）、次の入力から新しいカードを始める。前のカードは「次の入力へ続く」状態で閉じる。経過時間はカードごとに、その入力を送った時刻から数える。

### 4.2 見出し（1 行目）

| 状態 | 左 | 中央 | 右 |
|---|---|---|---|
| 実行中・タスク登録前 | 点描アニメーション | 状態語（「考え中…」など今の `AgentActivityState`） | 経過 `0:09` |
| 実行中・作業あり | 点描アニメーション | 今の作業（種類のアイコン＋「api.swift を編集中」） | 経過 |
| 応答なし（ハング判定） | 点描アニメーション | 今の作業 | 「無応答 1:30」と中断（Esc）ボタン |
| 承認・質問待ち | 待機の表示 | 「待機中…」 | 経過 |
| 完了 | ✓ | 「完了」 | 所要 `0:13` |
| 中断 | 中断の印 | 「中断」 | 所要 |
| エラー | エラーの印 | 「エラー」 | 所要 |
| 次の入力へ続く | 中断の印 | 「次の入力へ続く」 | 所要 |
| 終了（終わり方の記録が無い。この機能より前の会話・プロセスの異常終了・アプリの終了） | 印なし | 「終了」 | なし |

- **FR-4** 経過時間は `m:ss`、1 時間以上は `h:mm:ss`。60 秒未満も `0:09` と書く（今の「9 秒」表記はカードでは使わない）。
- **FR-5** 実行中かどうかの判定は、今の処理中表示と同じ条件にする（`showsProcessingIndicator`。バックグラウンドタスクやサブエージェントが動いている間も実行中）。 最新のカードでは、この判定をターンの終わり方の記録より優先する。

### 4.3 タスクの行

| 状態 | 印 | 文字 | 開閉 |
|---|---|---|---|
| 完了 | ✓ | 取り消し線、薄く（非活性の見た目） | 閉じる |
| 進行中 | 小さい点描アニメーション | 通常 | 自動で開く |
| 未着手 | ○ | 薄く | 作業が無いので開けない |
| 中断 | 中断の印 | 通常 | 閉じる |

- **FR-6** 印を縦の線でつなぐ（スケッチの ○―○―○）。各行の右端に、そのタスクの所要時間（進行中になってから完了するまで）を出す。
- **FR-7** 進行中のタスクが完了したら自動で閉じ、次に進行中になったタスクを開く。ユーザーが手で開いたタスクは自動では閉じない。
- **FR-8** 作業が終わったカードは、すべてのタスクを閉じた状態で残す。
- **FR-9** 「タスク外の作業」があれば、タスクの行と同じ形の行として出す。位置は時系列順で、登録前の作業はタスクの上、それ以外は該当の位置に出す。

### 4.4 作業の行

2026-11-09 の表示確認で、次の変更を決めた。タスク外の行も、含まれる作業が実行中なら進行中の印、全件の完了記録があれば完了の印にする。中断した作業や記録が無い作業を完了として扱わない。記録から状態を決められない場合は、点描と区別できる静止した疑問符の印にする。手動の開閉は保持する。

作業の時間は、実行中は開始からの経過、完了後は記録された所要時間を表示する。時刻が無い作業には時間を出さない。0.1 秒未満の所要時間は `<0.1s` とし、`0.0s` と表示しない。画面外やバックグラウンドでは既存の可視性制御で時計の更新を止める。

- **FR-10** 1 行は「種類のアイコン・何をしたか・所要時間」。進行中は薄い文字で「〜中」、終わったら体言止め（「go.mod を編集」。D20）にする。
- **FR-11** 同じ種類の作業（読み込み・検索・編集）が続いたら 1 行にまとめる（「5 ファイルを編集」）。コマンドの実行はまとめない。
- **FR-12** 文言の元は次のとおり。結果の意味（「12 件中 12 件合格」など）は出さない。
  - ファイル操作は対象のファイル名を使う。
  - 検索は「N 件」まで出す。
  - Claude の Bash はエージェントが付ける短い説明（`description`）を使い、無ければコマンドを出す。
  - Codex のコマンドはコマンドを出す。
- **FR-13** 作業の行を開くと、今のツールカードと同じ中身（差分・コマンド出力）が見える。
- **FR-14** サブエージェントは 1 行の作業として出す（サブエージェントの説明・種類・状態。今の `SubAgentMarkerCell` と同じ情報）。今のチャット画面はサブエージェントの中身を表示しない（右パネルは 2026-09 に廃止）ので、1 段目ではこの行は開けない。属するタスクは、起動した時点で進行中のタスクがちょうど 1 件ならそのタスク、そうでなければタスク外。
- **FR-15** 1 つのタスクに作業が非常に多いときは、新しい順に一定件数だけ出し、残りは「さらに表示」にする。

### 4.5 会話ログとの関係

- **FR-16** カードの上に出すのは、その入力の最初の作業・タスク登録より前に書かれた文章と思考。
- **FR-17** カードの中に出すのは、作業、タスクの進行中に書かれた文章と思考、回答済みの質問の記録、エラー。
- **FR-18** カードの下に出すのは、作業が終わった後の、その入力の最後の返答とターンの使用量。実行中はその返答もカードの中に出ており、終わった時点で一度だけ下へ移る。
- **FR-19** 承認待ちと未回答の質問は、今の入力欄の上（`ChatReplyArea`）のまま。

### 4.6 保存・復元・巻き戻し

- **FR-20** アプリを再起動してもカードは同じに見える（同じタスク、作業の振り分け、所要時間）。
- **FR-21** 巻き戻した入力のカードとタスクは、表示からもエージェント側の記憶からも消える。巻き戻した後の最初のカードに、消えた入力のタスクが出ない。
- **FR-22** この機能より前に保存された会話も表示できる。経過の記録が無いので、作業はタスク外にまとめ、タスクリストは最後の状態だけを出し、所要時間は出さない。古い会話を書き換える移行処理はしない。

### 4.7 他の画面

- **FR-23** グリッドの各列は会話ログの部品を共有するので、同じカードが出る。グリッドのタイルの状態の行（会話を出さない小さいタイル）は、カードの見出しと同じ内容にする。
- **FR-24** iOS は 2 段目。Mac → iPhone の通信に作業の終了時刻と説明を載せ、iOS 側に同じカードを作る。1 段目では iOS の表示を壊さないこと（未知の種類は今も無視される）。

## 5. 非機能要件

- **NFR-1 性能**: 経過時間とアニメーションは、今の可視性の仕組み（`HangStatusTimelineSchedule`・`isTimelineVisible`。ADR 0010・0067・0159）に乗せる。画面外・非表示のときは更新を止める。新しいタイマーや `GeometryReader` は足さない。グリッドで 9 列並べてもメインスレッドの負荷が今の処理中表示より増えないこと。
- **NFR-2 動きを減らす設定**: 点描アニメーションは静止表示にする（今の処理中表示と同じ）。
- **NFR-3 VoiceOver**: 見出しは「状態・今の作業・経過」を 1 つのラベルで読む。タスクの行は「状態・タスク名・所要時間」、開閉できることを読み上げる。
- **NFR-4 言語**: 日本語と英語（xcstrings）。英語で長くなっても見出しは 1 行で省略する。
- **NFR-5 互換**: 保存形式の変更は、古い版のアプリで開いても会話が読めること（ADR 0226）。
- **NFR-6 配色**: アイコンと ✓ は文字と同じ半透明グレー。緑やアクセント色は使わない（ADR 0042・0189・0227）。

## 6. 範囲外

- タスク登録の強制（指示・関所）。D3 で撤回。
- 進捗バー・「Step N of M」・モデル名・一時停止・Open run（参考動画にあるもの）。
- 作業の結果の意味の要約（AI 要約を含む）。
- Cursor のチャット・ターミナル画面。
- ユーザーによるタスクの直接編集（D2）。

## 7. 受け入れ基準

| # | 条件 | 期待 |
|---|---|---|
| AC-1 | Claude に「X を直して」と送り、エージェントがタスクを 3 件登録して順に進める | カードが 1 枚出て、進行中のタスクだけが開き、作業がその下に増える。完了したタスクは ✓・取り消し線・薄字で閉じる |
| AC-2 | 同じ入力で、タスク登録の前にファイルを 2 件読む | 2 件は「タスク外の作業」としてタスクの上に出る |
| AC-3 | タスクを登録しない短い依頼で、作業が 3 件ある | カードは見出しとタスク外の作業 3 件だけで出る |
| AC-4 | 「OK と返して」 | カードは出ない（実行中に一瞬見出しが出るのは可） |
| AC-5 | 進行中のタスクが 2 件ある間の作業 | タスク外の作業に入る |
| AC-6 | 作業が終わる | 見出しが「完了 · 0:13」になり、最後の返答がカードの下に出る |
| AC-7 | 実行中に Esc で中断 | 見出しが「中断」、進行中だったタスクに中断の印 |
| AC-8 | 次の入力でエージェントがタスクを登録し直す | 新しいカードには、その入力で登録・更新されたタスクだけが出る |
| AC-9 | 2 つ前の入力まで巻き戻して新しく送る | 消えた入力のカードとタスクは出ず、新しいカードにも混ざらない |
| AC-10 | アプリを再起動して同じ会話を開く | カードの内容（タスク、振り分け、所要時間）が再起動前と同じ |
| AC-11 | この機能より前の会話を開く | 落ちずに表示され、作業はタスク外、所要時間なし |
| AC-12 | 古い版のアプリで、新しい版が保存した会話を開く | 会話が読める（タスクのカードが複数枚に見えるのは可） |
| AC-13 | Codex で計画（update_plan）を使う | 同じカードに出る。今の末尾の「プラン」表示と二重にならない |
| AC-14 | Cursor のチャット | 今の表示のまま変わらない |
| AC-15 | グリッドで実行中のタイル | 列にカードが出る。小さいタイルの状態の行は、カードの見出しと同じ内容 |
| AC-16 | 動きを減らす設定がオン | アニメーションが止まり、静止表示 |

## 長い会話の取得契約

取得範囲でカードの所属・順序・状態・時刻・最終返答位置を変えない。本文をまだ取得していなくても、入力欄右上の履歴入口と最新 12 本の目盛りを使える。古い入力への移動は直接取得し、間の本文を全件読み込まない。巨大なカード・行・作業・本文も段階取得し、プレビューを元の入力として呼び戻さない。構造と版、性能・受入条件は [ADR 0231](../adr/0231-semantic-chat-read-model.md) を参照する。

2026-11-10 に Mac で実装し、関連回帰・正式性能計測・隔離した実アプリの受入・全体品質ゲートの合格を記録した（[delivery 0231](../delivery/0231-semantic-chat-read-model.md)）。この保証は新しい取得機能に対応した実行サービスに限る。未対応の実行サービスでは、サービスの更新が必要なことを示したうえで従来の表示を続ける。
