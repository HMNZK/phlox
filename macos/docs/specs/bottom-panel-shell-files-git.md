## 0. 要点（平易な言葉で）

- **下部パネル**: 中央の下から引き上げて開く欄。中身は既定でそのプロジェクトのターミナル。閉じてもシェルは生きていて、開き直すと続きが見える。
- **既定のシェル**: 設定に「ターミナル」の欄を足し、新しく開くターミナルのシェルを選べるようにする。今は macOS のユーザー設定（ログインシェル）に固定されている。
- **ファイルの作成・名前変更・削除**: 右サイドバーのツリーの右クリックメニューとキー操作で行う。削除はゴミ箱へ移す（元に戻せる）。
- **Git タブ**: 右サイドバーの上に「ファイル / Git」の切り替えを戻し、Git では作業中の変更ファイルの一覧と小さな差分を出す。大きく見る・コミットするのは今の「変更」タブで行う。

## 2. 下部パネル（ターミナル）

### 機能要件

| ID | 要件 |
|---|---|
| BP-1 | 中央（子タブの区画）の下端に、開閉できる下部パネルを置く。左右のサイドバーの高さは変えない（パネルは中央の列の中だけに出る）。使用量のバーはパネルの下に残る |
| BP-2 | 開閉の手段は 3 つ: キー操作（⌘J）・メニュー「表示 › 下部パネルを表示／隠す」・ヘッダー右端の開閉ボタン（「単体／グリッド」と「インスペクタの開閉」の間。Xcode のように左・下・右の区画の開閉が並ぶ。ユーザー決定 2026-10-14） |
| BP-3 | パネルの中身は既定でターミナル。プロジェクトごとに 1 つのシェルを持ち、作業フォルダはそのプロジェクトのフォルダ。シェルは BS-1 の既定のシェル |
| BP-4 | シェルは初めてパネルを開いたときに起動する（開いていないプロジェクトではシェルを起動しない） |
| BP-5 | パネルを閉じてもシェルは終了しない。開き直すと scrollback ごと元の表示に戻る。プロジェクトを閉じたとき・アプリ終了時にシェルを終了する |
| BP-6 | プロジェクトのタブを切り替えると、パネルの中身はそのプロジェクトのターミナルに替わる。開いているか閉じているかはウィンドウ単位で保つ（プロジェクトごとには変えない） |
| BP-7 | 上端の境目をドラッグして高さを変えられる。最小 120pt、最大は中央の高さの 70%。ただし上の区画（会話など）の中身には最小 200pt を残す（どちらか小さい方が最大）。左右分割のときも同じ。高さはアプリを終了しても保つ。境界の見た目・操作は後続要件 BD-2/3 と ADR 0202 で共通の ResizeGripView に統一（ホバー、カーソル、ダブルクリックで既定高） |
| BP-8 | 開いたときはターミナルにキー入力のフォーカスを移す。開閉キーをもう一度押すとパネルを閉じ、フォーカスを開く前の場所（入力欄など）へ戻す。Esc ではパネルを閉じない（ターミナルが Esc を使うため） |
| BP-9 | パネルの見出しは「下部パネル」と名乗り（VoiceOver も同じ）、シェルの名前（例 `zsh`）と作業フォルダ、「シェルを再起動」「パネルを閉じる」を置く。入力先の外枠は後続要件 BD-1 と ADR 0202 で廃止し、見出しの文字の強調は残す。シェルが終了したら、その旨と「再起動」を出す。BS-4 の注意は見出しにも、次に再起動するまで残す |
| BP-10 | 文字の大きさは子タブのターミナルと同じ設定の値を使う（既定はシステムの文字の大きさ 13pt）。⌘+ / ⌘− / ⌘0 は、パネルのターミナルにフォーカスがあるときはターミナルの文字に効く |
| BP-11 | プロジェクトが選ばれていない（タブが無い）ときは、開閉の操作を無効にする |
| BP-12 | グリッド表示でも開ける。対象は選択中のタイルのプロジェクト。選択中のタイルの見た目は今のまま（新しい印は足さない） |
| BP-13 | メニュー「表示 › 下部パネルのシェルを再起動」を置く（キーボードだけで再起動できるように）。そのプロジェクトのシェルを一度でも起動していれば、パネルが閉じていても使え、押すとパネルを開く。一度も起動していなければ無効 |

### 受け入れ基準

- プロジェクト A でパネルを開き `echo a` → 閉じる → 開くと `a` の出力が残っている。
- プロジェクト B のタブに切り替えると、B のフォルダ（`pwd`）のシェルが出る。A に戻ると A の表示に戻る。
- パネルを開いたまま会話の入力欄に戻ると（クリック）、入力欄に文字が入る。開閉キーで閉じるとフォーカスが入力欄へ戻る。
- 高さを 300pt にしてアプリを再起動すると、開いたときの高さが 300pt。
- 使用量のバーは、パネルの開閉・高さに関係なく常に下端に見える。

## 3. 既定のシェル（設定）

デザインの依頼は不要（既存の設定の行の部品で組める）。

| ID | 要件 |
|---|---|
| BS-1 | 設定に「ターミナル」の欄を新設し、「シェル」を選べるようにする。選択肢は「システムの既定（今のログインシェル。例 `/bin/zsh`）」＋ `/etc/shells` に載っていて実行できるもの＋「その他…」（パスを入力） |
| BS-2 | 既定値は「システムの既定」。今の挙動（`pw_shell`、空なら `/bin/zsh`）と同じにする |
| BS-3 | 「その他…」で入れたパスは、実行できるファイルであることを確かめてから保存する。だめなら理由を行の下に出して保存しない |
| BS-4 | 起動時に選んだシェルが無くなっていた（アンインストール等）ときは、システムの既定で起動し、ターミナルの最初の行に「設定のシェル（パス）が見つからないため、システムの既定で起動しました」と出す |
| BS-5 | 反映先は、これから起動するシェルすべて（ターミナルの子タブ・下部パネル・「シェルを再起動」）。今動いているシェルは変えない |
| BS-6 | シェルに渡す環境変数 `SHELL` を、実際に起動したシェルのパスにする（今は渡していない。zsh 以外を選んだときに子プロセスが食い違わないため） |
| BS-7 | （提案。依頼外）「ターミナル」の欄に、今「外観 › 文字の大きさ」にあるターミナルの文字の大きさの行も移す |
| BS-8 | エージェント（Claude Code・Codex・Cursor）の起動には使わない（エージェントの起動経路は別。ターミナルとして開くシェルだけが対象） |

受け入れ基準: `/bin/bash` を選んで新しいターミナルを開くと `echo $0` が bash、`echo $SHELL` が `/bin/bash`。既に開いていた zsh のターミナルは zsh のまま。「その他…」に存在しないパスを入れると保存されず理由が出る。

## 4. ファイルの作成・名前変更・削除（右サイドバーのツリー）

| ID | 要件 |
|---|---|
| FO-1 | 右クリックメニューに「新規ファイル」（⌥⌘N）「新規フォルダ」（⇧⌥⌘N）「名前を変更」「ゴミ箱に入れる」を足す（既存の 3 項目は残す）。空白部分の右クリックとツリー見出しの「＋」からも、ルート直下に作れる。⌥⌘N・⇧⌥⌘N は選択中の行の場所に作る。右クリックメニューには ↩ を出さない（Return は項目のキーとして登録せずツリーが受ける。Finder と同じ）。使えない項目は淡色にするだけで、理由のツールチップは付けない（メニュー先頭の見出しで対象を示す） |
| FO-2 | 新規作成は、対象のフォルダ（ファイル行ならその親フォルダ）を展開し、その中に名前の入力行をその場に出す。Return で作成、Esc で取り消す。作成したファイルはファイルタブで開く（フォルダは開かない） |
| FO-3 | 名前の変更は行の名前をその場で入力欄にする（Return で確定・Esc で取り消し）。拡張子より前を選択した状態で始める。キー操作は行を選んで Return（Finder と同じ。ユーザー決定 2026-10-14）。これに伴い、ツリーの Return は「開く」から「名前の変更」に変わる。ファイルを開くのは ⌘↓ とクリック、フォルダの開閉は → / ← とクリック |
| FO-4 | 名前の検査: 空・`/` を含む・`.` や `..`・同じフォルダに同名がある（相手がファイルなら「同じ名前のファイルがあります」、フォルダなら「同じ名前のフォルダがあります」）、は確定させずに理由を出す（下の行を押し下げない出し方）。大文字小文字だけの変更（`readme.md` → `README.md`）はできる |
| FO-5 | 削除はゴミ箱へ移す（`FileManager.trashItem`。完全削除はしない）。確認を出す（形は見本 6 と同じ、ウィンドウに付くシートの NSAlert。「〈名前〉をゴミ箱に入れますか？」。フォルダなら中の件数も。数えるのは 1,000 項目までで、超えたら「1,000 項目以上」）。ゴミ箱は戻せるので、確認は軽い形（取り返しがつかない操作用の見た目にしない）。キー操作は ⌘⌫。確認の中では ⌘⌫ を効かせない（⌘⌫ の 2 回押しで消えないように。Return で実行・Esc で取り消し） |
| FO-6 | 複数選択はしない（1 件ずつ操作する） |
| FO-7 | 開いているファイルの名前を変えたら、そのファイルタブは新しいパスに付け替わる（未保存の編集もそのまま残る）。フォルダの名前を変えたら、その中の開いているファイルタブもすべて付け替わる |
| FO-8 | 開いているファイル（フォルダならその中のファイル）を削除するときは、確認に「開いているタブを閉じます」と出す。未保存の変更があれば「未保存の変更は失われます」も出し、この場合だけ取り返しがつかない操作の見た目にして、既定のボタンを「キャンセル」にする（Return で消えない）。削除したらそのタブを閉じる |
| FO-9 | 操作はプロジェクトのフォルダの中だけ。ルートそのもの・ルートの外を指す symlink は、名前変更・削除を出さない（無効表示）。`.git` と `.DS_Store` は今もツリーに出していない（`FileTreeLoader` の除外）ので対象外 |
| FO-10 | 操作の後、そのフォルダを読み直してツリーに反映し、新しい／名前を変えた行を選択して見える位置まで動かす |
| FO-11 | 失敗（権限なし・ディスクが読み取り専用・作成直前に同名ができた など）は、理由をツリーの上に一時表示する。ツリーと実際のファイルが食い違わないよう、失敗時もフォルダを読み直す |

受け入れ基準: `docs/` で「新規ファイル」→ `notes.md` → Return で `docs/notes.md` ができ、ファイルタブで開く。開いている `notes.md` を `memo.md` に変えると、タブの名前とパスが替わり未保存の編集が残る。`memo.md` を ⌘⌫ → 確認で、ゴミ箱に移りタブが閉じる。Finder のゴミ箱から戻せる。

## 5. Git タブ（右サイドバー）

> 2026-10-15: GT-3 のステージ区別なし・GT-4 の Git 内差分と境目・GT-5 の開く操作・GT-6 の変更タブ内コミット欄は、[GW-1〜6 と §7](git-tab-workflow-and-worktree-start.md#3-git-タブgw-見本ができてから実装する)・[ADR 0204](../adr/0204-git-staging-and-changes-navigation.md) で置き換える。変更をステージ済み／作業ツリーに分け、クリックで常に変更子タブへ渡す。コミット欄は Git 最上部へ移し、index だけをコミットする。以下の表は元の決定を記録する。

| ID | 要件 |
|---|---|
| GT-1 | 右サイドバーの上に「ファイル / Git」の切り替えを置く（ADR 0192 の「タブ無し」を置き換える）。最後に選んだ方をアプリを終了しても保つ。キー操作: ⌃⌘B で「ファイル」、⇧⌃⌘G で「Git」（右サイドバーが閉じていれば開く。⌃⌘G は「次の表示モード」で使用中） |
| GT-2 | 対象はプロジェクトのフォルダの作業ツリー。見出しにブランチ名（detached HEAD は短縮コミット）と変更の件数、更新ボタン |
| GT-3 | 変更ファイルの一覧: 種類（追加・変更・削除・名前変更・未追跡。Git の標準の 1 文字 A・M・D・R・U で示し、ツールチップと VoiceOver では「追加」などの言葉で読む。色は補助）・ファイル名・フォルダ（薄く）・追加行数／削除行数。並びはパス順。「変更」の子タブと同じく、ステージ済み／未ステージは区別しない（HEAD からの変更） |
| GT-4 | タブを上下に分け、上に一覧・下に選んだ行の差分を出す（境目をドラッグして比率を変えられる。行のすぐ下に開く形ではない。右サイドバーの幅で読める行の折り返し・長い差分は先頭の一部と「続きを『変更』タブで見る」）。バイナリは「バイナリファイル」、未追跡のテキストは全文を追加行として出す |
| GT-5 | 行のダブルクリック・Return・右クリック「『変更』タブで開く」で、「変更」の子タブを開いてそのファイルを選んだ状態にする。右クリックには「ファイルを開く」（ファイルタブ）「Finder で表示」「パスをコピー」も置く |
| GT-6 | コミット・push・PR 作成は Git タブには置かない。見出しに「コミット…」ボタンを置き、「変更」タブのコミット欄を開く |
| GT-7 | 自動で更新する時機: Git タブを表示したとき・エージェントのターンが終わったとき（そのプロジェクトのセッション）・ファイルタブで保存したとき・ツリーでファイルを作成／名前変更／削除したとき・アプリが前面に戻ったとき。手動の更新ボタンも残す |
| GT-8 | Git 管理外のフォルダでは「Git 管理外のフォルダです」、変更が無いときは「変更はありません」、git の実行に失敗したときは理由と「再試行」を出す |
| GT-9 | 「変更」タブと同じデータ（`WorkingTreeService` の結果）を使い、同じ時点で両者の一覧が食い違わない |

受け入れ基準: エージェントがファイルを書き換えてターンが終わると、Git タブに操作なしでそのファイルが出る。行を選ぶと差分が出て、ダブルクリックで「変更」タブがそのファイルを選んで開く。Git 管理外のプロジェクトでは空状態の文言が出る。

## 6. 共通の非機能要件

| ID | 要件 |
|---|---|
| NF-1 | 下部パネルの開閉・高さのドラッグで、会話・グリッドの全体を毎フレーム組み直さない（ADR 0116/0136 の方式に合わせる） |
| NF-2 | git の読み取りは git の状態を変えない（ADR 0150。`--no-optional-locks`）。大きなリポジトリでも全ファイルの内容を読まない |
| NF-3 | ファイル操作はプロジェクトのフォルダの外へ出ない（パスの包含確認を、既存の読み書きと同じ共通の経路で行う。symlink の差し替えに耐える） |
| NF-4 | キーボードだけで全操作でき、VoiceOver で各要素の役割と状態が読める。状態は色だけに頼らない |
| NF-5 | 日本語・英語のどちらでも文言が切れない（`Localizable.xcstrings` に両方を入れる） |

## 7. スコープ外（今回やらないこと）

> 2026-10-15: Git タブでのブランチ作成・切り替え・名前変更・削除、取得、スタッシュ操作は [GW-7〜15](git-tab-workflow-and-worktree-start.md) と [ADR 0206](../adr/0206-git-history-branches-stashes-and-graph.md) で取り込む。以前のスコープ外の記述よりこの決定を優先する。

| 項目 | 理由 |
|---|---|
| 下部パネルにターミナル以外（変更・問題・出力など）を出す、パネル内で複数のターミナルをタブで持つ | 依頼は「既定でターミナル」まで。複数のターミナルは今の子タブで開ける |
| 下部パネルのターミナルと子タブのターミナルの相互移動 | 依頼外 |
| ファイルのドラッグ＆ドロップでの移動・複製・複数選択の一括操作 | 依頼外 |
| ゴミ箱からの「取り消し（⌘Z）」 | Finder のゴミ箱から戻せる |

| ファイル監視（FSEvents）による自動更新 | GT-7 の時機で足りるかを先に確かめる |
| エージェントの起動シェルの変更 | BS-8 |
