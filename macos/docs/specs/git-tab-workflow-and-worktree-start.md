# 要件: フォーカスの外枠の整理・下部パネルの境界線・Git タブの作業の集約・ワークツリーの起点の選択

ユーザー依頼（2026-10-15）。下部パネル・ファイル操作・Git タブ（`bottom-panel-shell-files-git.md`）の続き。番号は FX = 外枠、BD = 下部パネルの境界、GW = Git タブ、WS = ワークツリーの起点、NF = 共通。

## 0. 依頼と決定

| 依頼 | 決定（ユーザー確認 2026-10-15） |
|---|---|
| ファイルツリーと Git タブの外枠を白くハイライトするのをやめる | FX |
| 下部ターミナルの白い外枠を他と統一し、境界線のホバーをサイドバーと統一する | BD |
| 「変更」タブ左の差分一覧を廃止し、Git タブの差分を押すと常に「変更」タブで開く。Git タブ内の差分表示を廃止。差分一覧の下に、折りたためるコミット・ブランチ・スタッシュ・リモートブランチ・Git グラフを置く。差分一覧も折りたためる。コミットメッセージ・コミット・プッシュ・PR 作成を Git タブの最上部へ移す | GW。一覧の操作は「見るだけ」ではなく操作もできる。コミットするファイルの選択はチェックボックスをやめ、ホバーの「＋」でステージし、ステージしたものだけをコミットする。見た目は Claude Design の見本を作ってから実装する |
| 新規チャットでワークツリーを選ぶとき、起点のブランチ・コミット・タグを選べる | WS。1 つの検索できる欄で、ローカル・リモートのブランチ、タグ、最近のコミットから選ぶ。コミット ID の直接入力も可 |

## 1. フォーカスの外枠（FX）

| ID | 要件 |
|---|---|
| FX-1 | ファイルツリーの一覧と Git タブの一覧に入力先があっても、一覧の外側に枠を描かない（サイドバーのセッション一覧と同じ）。入力先の位置は選択行の塗りで分かる |
| FX-2 | Git タブの中で入力先になれる部分にも、OS 標準のフォーカスリングを出さない |
| FX-3 | 名前変更・新規作成の入力欄の枠（入力中であることを示す）は残す |

## 2. 下部パネルの外枠と境界線（BD）

| ID | 要件 |
|---|---|
| BD-1 | 端末に入力先があっても下部パネルの外側に枠を描かない（子タブのターミナルと同じ）。BP-9 の「パネルの外側に枠」を置き換える。見出しの文字の強調（入力先の表示）は残す |
| BD-2 | 下部パネルの高さを変える境界線は、左右のサイドバーの境界線と同じ見た目と動きにする: ホバーで区切り線の色の 3pt の帯がふわっと出る（0.12 秒）、カーソルは上下の矢印、ドラッグ中もカーソルを保つ、ダブルクリックで既定の高さへ戻す、ウィンドウの移動にならない |
| BD-3 | BD-2 は同じ部品（`ResizeGripView`）を上下向きに使えるようにして実現し、見た目を別に作らない |

## 3. Git タブ（GW）— 見本ができてから実装する

| ID | 要件 |
|---|---|
| GW-1 | Git タブの最上部に、ブランチ名・コミットメッセージの欄・「コミット」「プッシュ」「PR を作成」を置く（「変更」タブ下部のコミット欄を移す。押せない理由の 1 行表示・実行中の表示も移す）。更新ボタンも上部に置く |
| GW-2 | その下に折りたためる区画を順に置く: 変更 → コミット → ブランチ → リモートブランチ → スタッシュ → グラフ。各区画の見出しに件数と、その区画の操作ボタン（あれば）を置く。開閉の状態はアプリを終了しても保つ。既定は「変更」だけ開く |
| GW-3 | 「変更」区画は「ステージ済み」と「変更」の 2 つに分ける。行の右にホバーで、未ステージなら「＋」（ステージ）、ステージ済みなら「−」（ステージを外す）を出す。見出しに「すべてステージ」「すべて外す」。行の内容（種類の 1 文字・ファイル名・フォルダ・追加／削除行数）は GT-3 のまま |
| GW-4 | 「コミット」はステージ済みのものだけをコミットする。ステージ済みが無いときは押せない（理由を表示）。ADR 0169 の「選んだファイルだけをコミット」を置き換える |
| GW-5 | 変更の行を押すと、常に「変更」の子タブを開いて（無ければ作って）そのファイルの差分を出す。Git タブの中には差分を出さない（GT-4 の差分表示と境目を廃止） |
| GW-6 | 「変更」の子タブは左の一覧を廃止し、Git タブで選んだ 1 ファイルの差分（または内容）だけを出す。差分／内容の切り替え・「ファイルタブで編集」は残す。何も選ばれていないときは「Git タブで変更を選んでください」を出す。コミット欄は廃止（GW-1 へ移す） |
| GW-7 | コミット: 今のブランチの履歴（新しい順、最初は 50 件、末尾で続きを読む）。行は要約・作者・相対時刻・短縮 ID。行を開くとそのコミットで変わったファイルが並び、ファイルを押すと「変更」タブにそのコミットでの差分を出す。右クリック: ID をコピー・ここからブランチを作成 |
| GW-8 | ブランチ: ローカルのブランチ（今のブランチに印、最近使った順）。見出しの「＋」で今の位置から新しいブランチを作る。行のダブルクリックまたは右クリックで「切り替え」、右クリックで「ここからブランチを作成」「名前の変更」「削除」 |
| GW-9 | リモートブランチ: リモートごとのブランチ。見出しに「取得」（fetch）。右クリックで「チェックアウト」（同名のローカルブランチを追跡付きで作って切り替える。既にあれば切り替えるだけ）・「ここからブランチを作成」 |
| GW-10 | スタッシュ: 一覧（新しい順。メッセージ・相対時刻）。見出しの「＋」で今の変更（未追跡を含む）をスタッシュする（メッセージは任意）。行を開くと変わったファイルが並び、押すと「変更」タブに差分を出す。右クリック: 適用・取り出す（適用して削除）・削除 |
| GW-11 | グラフ: 全ブランチのコミットの線のグラフ（新しい順、最初は 200 件）。行の見た目と操作はコミット（GW-7）と同じで、左に線、ブランチ名・タグの札を出す |
| GW-12 | 消すと戻せない操作（ブランチの削除・スタッシュの削除）は確認を出す。マージされていないブランチの削除は、その旨を確認に書き、承認したら強制削除する |
| GW-13 | 作業ツリーを書き換える操作（ブランチの切り替え・チェックアウト・スタッシュの作成／適用／取り出し）は、そのプロジェクトのフォルダで実行中のエージェントのセッションがあるとき確認を出す（同じ作業ツリーを書き換えるため）。ワークツリーで動くセッションは対象外 |
| GW-14 | git の失敗（未コミットの変更と衝突して切り替えられない・スタッシュの適用で衝突 など）は、git の理由をそのまま Git タブの上部に出す。勝手に退避・強制しない |
| GW-15 | 操作の後と、GT-7 の時機に、全区画を読み直す。読み取りは今までどおり git の状態を変えない（NF-2） |

受け入れ基準: Git タブで変更の行の「＋」を押すと「ステージ済み」へ移り、メッセージを書いて「コミット」でそのファイルだけがコミットされ、「コミット」区画の先頭に出る。変更の行を押すと「変更」タブにその差分が出る（「変更」タブに一覧は無い）。ブランチを右クリック →「切り替え」で見出しのブランチ名が変わる。

## 4. ワークツリーの起点（WS）

| ID | 要件 |
|---|---|
| WS-1 | 新規チャット画面の作業場所で「新しい worktree」を選んだときだけ、起点の欄を出す |
| WS-2 | 起点の欄は 1 つのポップオーバーで、上の検索欄で絞り込める。区分: ローカルのブランチ・リモートのブランチ・タグ・最近のコミット（今の位置から 30 件）。検索欄にコミット ID（短縮可）を入れて、実在すればそれも選べる |
| WS-3 | 既定は「今の位置（HEAD）」で、今までと同じ動き。選んだ起点は下書きと同じくプロジェクトごとに覚える |
| WS-4 | 起点を選ぶと、ワークツリーはその位置から新しいブランチ（今までどおり `phlox/session/<id>`）で作る。リモートのブランチは取得（fetch）しない（手元にある情報を使う） |
| WS-5 | 開始時に起点が無くなっていたら（ブランチの削除など）、セッションを始めず理由を出す（ADR 0170 と同じ扱い） |

## 5. 共通（NF）

NF-2〜NF-5（`bottom-panel-shell-files-git.md` §6）をそのまま適用する。加えて:

| ID | 要件 |
|---|---|
| NF-6 | git の書き込みは既存の `GitWorkflowService` の経路（`/usr/bin/git`、パスは `:(literal)` で渡す）に集め、画面から git を直接呼ばない |

## 6. スコープ外

| 項目 | 理由 |
|---|---|
| マージ・リベース・チェリーピック・リセット・プル・強制プッシュ・衝突の解消画面 | 依頼外。衝突は git の理由を出すだけ（GW-14） |
| リモートブランチの削除・タグの作成と削除 | 依頼外 |
| 行の一部（ハンク）単位のステージ | 依頼はファイル単位の「＋」 |
| 起点の選択のための自動の取得（fetch） | WS-4 |

## 7. 見本の依頼で決めたこと（2026-10-15）

| 論点 | 決定 |
|---|---|
| 縦の高さ | 上部（ブランチ・メッセージ・ボタン・失敗の表示）は固定。その下の区画は Git タブ全体で 1 本のスクロールにし、区画の見出しはスクロール中も上に貼り付ける。メッセージ欄は 1 行から伸び、5 行で止めて中をスクロール |
| 主ボタン | 「コミット」を常に主ボタンにする（状態で主を入れ替えない）。「プッシュ」は先行するコミット数（↑2）を添える。PR はプッシュ前など押せないとき無効にし、理由はツールチップで出す。下の 1 行の理由は「コミット」が押せない理由だけ |
| 「＋／−」と行数の重なり | ホバー中（と選択中）はその行の行数を隠し、同じ場所にボタンの形をした「＋」「−」を出す（ツールチップ「ステージ」「ステージを外す」）。キーボードは選んだ行で Space がステージ／外す。VoiceOver はカスタムアクション「ステージ」「ステージを外す」 |
| ステージ後の入力先 | 入力先は同じグループの次の行へ進む（Space を続けて押すと順にステージできる）。自動の更新では選択をパスで保つ |
| 選択 | 全区画で選択は 1 つ。今のブランチの印は選択の塗りではなく、チェックの記号と太字。部分的にステージしたファイルは両方のグループに出る。「変更」タブの見出しに差分の出どころ（作業ツリー／ステージ済み／コミット 9f3c2e1／stash@{0}）を出す |
| 重ね表示 | 行を押して「変更」タブを開いたら、重ね表示の右サイドバーは閉じる（今のファイルツリー・Git タブと同じ。`InspectorView`） |
| 確認が重なるとき | 1 枚のダイアログにまとめる。主の確認文（例 ブランチの削除）に、実行中のセッションの注意を 1 行添える |
| git の失敗の表示 | 上部のボタンの下（メッセージ欄より下なので、入力中の欄を押し下げない）。最初の 3 行と「詳細」で全文、× で閉じる。次の操作を始めたら消す |
| デザインの値 | Claude Design のアカウントにある「Design System」ではなく、依頼文の値（`Packages/DesignSystem`）を正とする |
| 入力欄の縁 | 今のアプリの値（主文字色の 14%）のまま。コントラスト不足（約 1.3:1）はアプリ全体の課題として別に扱う |
| ボタンの入力先 | アプリの既存のボタンと同じ。FX は一覧・差分欄の外枠だけが対象 |
| 実行中の確認 | キャンセルが既定。「このプロジェクトでは聞かない」は付けない |
| キー | Git タブを表示しているときだけ有効: ⇧⌘C コミット欄へ・⌥⌘P プッシュ・⇧⌘R 取得・⌥⌘S スタッシュ・⌃↩ 行のメニュー。新しいブランチはキーなし（⌥⌘N はファイルツリーの新規ファイルで使用中） |
| モックで広げた点 | 理由の 1 行は押せるときも出す（例「2 ファイルをコミット」）、ブランチ名の入力の ↩ は作成して切り替え、「変更」タブの「エディタ」の見出し行は無くす、一部ステージのファイルに印は付けない |
| グラフ | モックの線と札の提案を採用。「origin だけ取得」は足さない |

見本: `ClaudeDesign/14 Git Tab Workflow/`（README の「統括役の決定」がモックより優先）。
