# グリッドビューのレイアウト要件（分割ツリー）

> **このファイルの役割**: グリッドビューが満たすべき要件（FR/NFR）と用語。
> **書かないもの**: なぜこのモデルか（→ adr/0136）、実装構造（→ architecture/session-pane-layout.md）。

## 用語

- **ペイン（pane）**: 1 セッションを表示する矩形。分割ツリーの leaf。
- **分割（split）**: 領域を軸（水平/垂直）に沿って n 個の子へ分けるノード。子ごとの取り分を weight で持つ。
- **分割線（divider）**: 隣接する2つの子の境界。両隣のノード ID で識別する。
- **永続ツリー**: 保存されるレイアウト。隠れているセッションの leaf も含む。
- **実効ツリー**: 描画に使うツリー。永続ツリーを可視集合で刈り込んだもの。
- **プリセット**: 1クリックで到達できるレイアウトの雛形。
- **自動整列**: 表示対象と利用できる領域から配置を算出し、変化に追従する状態。新規利用時の既定。
- **カスタム**: ユーザーが決めた分割と比率を保持する状態。既存の保存配置はこの状態で復元する。

## 自動整列

### 対象と順序

プロジェクト絞り込みと表示セッション選択を適用した後の対象だけを配置する。
順序はサイドバーのプロジェクト順、各プロジェクトの親から子へたどる順、未割当の順とする。
左から右、上から下へ並べる。折りたたみ状態は順序と表示対象に影響しない。
プロジェクト見出しと対応待ち欄の重複行はセッションとして数えない。
実行状態の変化やタイルの選択だけでは並べ替えない。

### 列数と段数

各タイルの最小外寸は幅540pt、高さ440pt。タイルには見出し、会話、入力欄を含む。
外側の余白とタイル間の8ptは、この外寸に含めない。

1. タイル領域の幅と最小幅から最大列数を求める。
2. 最大列数で必要な段数を求める。
3. 段数を増やさずに配置できる最小の列数を採用する。
4. 列幅と基本の段高を等分する。最終段の空きは、直上のタイルを下へ伸ばして埋める。

最大3列の場合は次の配置になる。

| セッション数 | 配置 |
|---:|---|
| 3 | 横に3個 |
| 4 | 2列×2段 |
| 5 | 上に①②③、下に④⑤。③は上下2段分 |
| 6 | 上に①②③、下に④⑤⑥ |
| 7 | 上に①②③、中に④⑤⑥、下に⑦。⑤と⑥は最終段まで延長 |

高さが足りないときは440pt以上を保ち、グリッド全体を縦スクロールする。
表示対象を勝手に外したり、文字の倍率を変えたりしない。
1列分の幅も確保できない場合も540ptを下回らない。
グリッドでは中央の必要幅を左右余白込みで556ptとし、既存のサイドバー自動非表示とインスペクターの重ね表示を先に適用する。
それでも不足するときは横スクロールでタイル全体へ到達できる。アプリの最小ウィンドウ幅は720ptのままとする。
ライブリサイズ中は組み替えを抑え、終了時に確定する。
利用可能領域とリサイズ中の状態はウィンドウごとに持つ。別のウィンドウのサイズ変更で配置を変えない。

### フルHDの基準

基準は表示領域1920×1080pt、通常の最大化、メニューバーの予約30pt、Dockの予約0pt。
左サイドバーは標準260pt、右インスペクターと下部パネルは閉じる。
現行のバーと余白から算出するとタイル領域は1643×903ptで、3列×2段の各タイルは約542.33×447.5ptになる。
この算出をもとに下限を540×440ptとする。物理画素数だけが1920×1080の画面とは区別する。
Dockが領域を使う場合やサイドバーを広げた場合は、3列×2段の同時表示を保証しない。

### 手動調整からの復帰

レイアウトメニューには常に「自動整列」を置く。
選ぶと表示対象を並べ直し、以後は表示対象、サイドバー順、利用可能領域の変化に追従する。
直前のカスタム配置への切り替え取り消しを用意する。確認ダイアログは出さない。
取り消しは同じメニューの「直前のカスタムに戻す」で行い、会話入力の取り消し操作とは分離する。
境界調整、タイルの移動、プリセット適用、キーボードによる配置変更でカスタムへ切り替える。
自動整列とカスタムの選択は再起動後も復元する。

## 機能要件

- **FR1 自由な比率**: 分割比は連続値で、1/k の整数倍に制約されない。「左半分に1枚・右半分を上下に2枚」を作れる。
- **FR2 プリセット**: トップバーのメニューから 1 クリックでレイアウトを適用できる。
  バランス / 1 枚 / 2 列 / 3 列 / 2 段 / 3 段 / 2 × 2 / 左にメイン・右に積む / 上にメイン・下に並べる（06 Grid の名前。手で崩したあとは「（調整済み）」を付ける）。
  セッション数がプリセットの想定を超えた分は、最大ペインを分割して足す（レイアウトから溢れさせない）。
- **FR3 分割線ドラッグ**: 分割線をドラッグして隣接する2枚の比率を変えられる。
  **ドラッグ中はゴースト（半透明の線）だけが動き、離した時に1回だけ確定する**。
  ダブルクリックでその split を等分に戻せる。
- **FR4 ドラッグで移動・分割**: セッションのヘッダーを掴んで別タイルへ落とせる。
  タイル中央へのドロップは**入れ替え**、端（各辺から 25% の帯）へのドロップは**その方向へ分割して差し込む**。
  ドロップ位置に応じたインジケータ（結果と同じ矩形）を表示する。
- **FR5 分割線は端末タイルの境界でも掴める**: `.pty` セッション（AppKit の `NSView`）が隣接する境界でも、
  分割線ハンドルがホバー・ドラッグを受け取る。
- **FR6 永続化**: 選択した自動整列またはカスタムと、カスタムの配置を保持する。旧版の保存配置はカスタムとして復元する。
- **FR7 カスタムは絞り込みで位置を失わない**: 表示セッションの選択やワークスペース絞り込みでセッションを隠しても、
  戻したときに**元の取り分のまま元の位置へ**戻る。
- **FR8 セッション増減の追従**: 自動整列は表示数に合わせて再配置する。カスタムでは新規セッションを最大ペインの分割で追加し、減ったセッションのペインを畳む。既存のセッションを全体で並べ直さない。
- **FR9 番号と「グリッドから外す」**: タイルは左上から数えて番号を振る。行の上から、同じ行は左から数える。
  描画と同じ領域・隙間で計算し、同じ段の座標の丸め誤差を吸収する。見出しの「⌘n」と ⌘1–9 はこの並びを使う。
  ⌘W と見出しの ✕ はタイルをグリッドから外す（セッションは消さない。表示セッションの選択から外すだけ）。最後の 1 枚は外せない。
- **FR10 レイアウト名の保持**: 選んだプリセットと「調整済み」かどうかを保存し、再起動後も同じ名前を出す。
  記録が無い旧データは、保存済みの配置がバランスと同じかどうかで「調整済み」を決める。

## 非機能要件

- **NFR1 ドラッグ中にハングしない**: 分割線ドラッグ中にタイルの矩形を変えない。
  ADR 0116 が実測した 470〜643ms のメインスレッドハングの**発生条件が成立しない**こと。
  この保証は「ドラッグ状態機械の `changed` が決してレイアウト操作を返さない」というテストで固定する。
- **NFR2 タイルが空白にならない**: レイアウトを変えてもタイルのビュー identity と階層位置が変わらない
  （`NSViewRepresentable` の attach 競合を起こさない）。
- **NFR3 最小ペイン**: 自動整列は幅540pt、高さ440pt以上。カスタムの分割線操作は従来の幅240pt、高さ160ptをクランプの目安とし、領域が最小値の2倍未満なら50:50にする。
- **NFR4 レイアウトデータの健全性**: 保存データが壊れていても起動でき、既定レイアウトへフォールバックする。
- **NFR5 描画時の副作用ゼロ**: 実効ツリーの導出は view body から呼ばれるため、状態更新も永続化も行わない（ADR 0010）。

## スコープ外

- 旧 k×k 配置データ（`phlox.grid.arrangement.<k>`）からの移行（ADR 0136 §6）。
- 任意矩形の自由配置（キャンバス方式）。入れ子の分割で足りるとゲート①で決定した。
- タブ化（1ペインに複数セッションを重ねる）。
